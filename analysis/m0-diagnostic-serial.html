M0 초기 설정에서 직렬 출력까지

reset helper 뒤의 설정과 문자 출력 함수가 같은 MMIO 영역을 사용한다. 레지스터 배치와 분주식은 Ricoh 공개 소스의 USIO 직렬 드라이버와 맞는다. 이 비교로 초기 설정의 일부를 직렬 통신 경로로 좁혔지만 실제 출력 핀이나 SRAM remap을 확정한 것은 아니다.

0x3ffe0838은 0x4dffb208에 OR 0x20을 적용한 뒤 0x3ffe7698을 호출한다. 이 하위 함수는 설정을 준비해 0x3fff42e0으로 넘기고 0x3fff4550을 호출한다. 호출 순서는 확인했지만 pin 제어 후보와 실제 전기적 출력의 연결은 확인하지 않았다. 원본 명령과 주소 근거 · 조건부 pinctrl 해석.

상위 함수와 설정 적용 함수는 각각 0x4dffe000의 bit 24를 읽는다. 상위는 bit가 0이면 설정 첫 word에 115200을, 1이면 1200을 넣는다. 하위는 이 bit에 따라 100000000 또는 32768을 선택하고 0x4dffe100의 하위 byte에 1을 더한 값으로 먼저 나눈다. 이어 설정 첫 word로 나누고 1을 뺀 값을 0x4de00006에 halfword로 기록한 뒤 bit 15를 지운다. 두 상태 읽기 사이에 하드웨어 값이 유지되는지는 이번 분석으로 보장하지 않는다.

Q = ((N / (low8(clock_divider) + 1)) / config[0]) - 1
write16(0x4de00006, low16(Q))
write16(0x4de00006, read16(0x4de00006) & 0x7fff)

위 식은 유효한 양의 입력에서 정수 나눗셈을 순서대로 수행하는 경로를 나타낸다. 115200·1200을 설정 목표값 후보로 해석할 수 있지만 실제 baud rate를 측정한 것은 아니다. 100000000·32768도 코드에 쓰인 분자이며 해당 보드의 실제 입력 클록을 확인한 값은 아니다. 분기·나눗셈·기록 위치.

0x3fff4550은 상태 영역에 인자를 저장하고 0x4de00001의 bit 0을 설정한다. 두 번째 인자가 비제로일 때는 bit 4도 설정한다. 공개 USIO 드라이버에서는 같은 offset과 bit를 각각 송신 활성화와 수신 인터럽트 허용으로 부른다. 하위 함수의 실제 효과는 레지스터 대응이 성립한다는 조건에서 해석한다.

0x3ffe7710은 LF 앞에 CR을 출력한다. 0x3ffe0860은 하위 반환값과 무관하게 요청 길이를 반환한다. 따라서 이 반환값만으로 실제 카메라의 직렬 전송 성공을 판단할 수 없다. callback과 출력 함수의 명령 근거.

마지막 함수 0x3fff4800은 0x4de00003의 bit 1을 기다리고 0x4de00004에 halfword를 기록한 뒤 다시 같은 상태 bit를 기다린다. 기록값은 (읽은 halfword & 0xfe00) | r0의 하위 16bit다. 직접 인자의 높은 bit가 켜져 있으면 기존 상위 7bit에도 OR 결과가 반영된다. 상위 line writer는 문자 인자를 byte로 읽는다. 공개 소스의 SSR·DR 배치와 일치하지만 읽기·기록 레지스터의 실제 하드웨어 동작은 별도로 확인해야 한다. 이 함수에는 timeout이 없다. 상태 bit를 합성 RAM에서 바꾸는 CPU 검사는 분기와 접근 순서를 확인할 뿐 실제 송신 완료나 전압 파형을 재현하지 않는다.

공식 USIO 소스와 일치하는 부분

Ricoh의 K3mkIII_220.tar.gz 안에 있는 Linux 소스의 drivers/tty/serial/usio.c를 대조했다. 해당 소스는 SCR offset 1, SSR offset 3, DR offset 4, BGR offset 6을 정의한다. SCR bit 0은 TXE, bit 4는 RIE이고 SSR bit 1은 TDRE다. Ricoh 배포본 · archive·member 해시와 행 번호.

같은 소스의 390–394행은 baud가 1보다 클 때 uartclk / baud - 1을 계산하고 417행은 그 값을 BGR에 쓴다. 이 구조와 여러 레지스터 offset의 일치가 직렬 설정 해석을 뒷받침한다. 다만 이 소스에서 M0의 정확한 base 주소와 입력 클록을 확인한 것은 아니므로 레지스터 호환성 비교와 물리 주소 매핑을 구분한다.

이 경로는 0x4dffb208을 SRAM remap 레지스터로 볼 근거를 추가하지 않는다. 앞선 pinctrl 비교와 이번 직렬 초기화의 연속 호출은 pin 기능 설정이라는 해석을 뒷받침하는 단서다. 실제 pin multiplexing 표, CLK_CRRRS bit 정의, 0x2000fffc와 0x0100fffc의 물리적 관계는 여전히 필요하다. 보드별 기록 순서와 한계.

검증과 후속 경계

설정 적용·활성화·문자 출력의 genuine C 3개를 추가해 로컬에 저장했다. 원본 Thumb, literal, 분기와 호출 대상이 판단의 기준이며 원시 C를 빌드 가능한 복원 소스로 취급하지 않았다. 활성화 함수의 C에서 unsupported로 남은 명령은 원본의 DSB이고 문자 출력 C의 상수 반환은 남은 r0 값이므로 전송 결과 API로 해석하지 않았다. 공개 자료에는 분석 설명과 재현 도구, 코드 범위와 해시를 남겼다.

8사례의 합성 CPU 검사에서 원본 함수의 상태 분기와 기록 순서를 검증했다. 원본 MMIO 주소에는 독립 RAM을 배치했으며 카메라나 OS 장치에는 접근하지 않았다. 입력의 해시를 고정하고 직접 M0 파일과 decoded 컨테이너에서 같은 결과를 확인했다. 검사 결과 · 재현 도구.

python verify_m0_diagnostic_serial.py m0.bin --output m0-serial-direct.json

이 결과는 직렬 초기화의 일부를 구분한 것이며 수정 펌웨어의 수락을 입증하지 않는다. 비제로 bank의 실제 생산자, resource record+4의 값 결정 정책, 선행 Boot ROM의 인증과 SRAM remap은 미확정이다. 현재까지 검증한 bank 선택 조건.
