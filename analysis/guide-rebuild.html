펌웨어 재구축 안내

제조사의 소스 코드는 공개되어 있지 않습니다. 이 주제는 펌웨어의 일부를 직접 다시 만들어, 원본과 똑같이 동작하는 코드로 바꿔 넣을 수 있는지를 가장 작은 단위부터 시험합니다.

핵심 요약

  • 이 주제는 “원본과 같은 코드를 직접 만들 수 있는가 → 원래 자리에 넣어도 같은가 → 파일 크기를 원본에 가깝게 되돌릴 수 있는가”의 세 단계로 이어집니다.
  • 모든 확인은 PC에서 원본 기계어를 에뮬레이터로 실행하거나 파일 바이트를 직접 대조하는 방식입니다. 카메라에서 실행한 것은 하나도 없습니다.
  • 지금까지 함수 하나를 원래 자리에 넣고 패키지를 다시 만들어 원본과 같다는 것까지 확인했습니다. 카메라 수용·부팅은 아직 남은 과제입니다.

한눈에 보기

작은 계산 함수 하나를 골라, 다시 만들고 → 원래 자리에 넣고 → 파일을 원본 크기에 가깝게 되돌리는 순서로 진행합니다. 마지막 카메라 단계는 아직 하지 않았습니다.

배경 지식

세 문서를 읽는 데 필요한 개념만 짧게 정리합니다.

leaf 함수
다른 함수를 부르지 않고 계산만 하는 말단 함수입니다. 입력과 출력이 분명해 원본과 새 코드를 나란히 실행해 비교하기 쉽습니다.
Q13 고정소수점
실수 1.0을 정수 8,192(2의 13제곱)로 나타내는 표기입니다. 색 변환 행렬 값이 이 형식이라, 곱한 뒤 반올림하고 13비트만큼 내립니다.
SAD·SSD
두 신호의 차이를 재는 기본 연산입니다. 차이의 절댓값 합(SAD)과 제곱 합(SSD)으로, 위상차 AF의 상관 연산에 쓰입니다. 자세한 설명은 명령·셸 안내에 있습니다.
NEON
ARM의 SIMD 확장입니다. 여러 데이터를 한 명령으로 한 번에 처리해 속도를 높입니다. 원본 SAD·SSD 함수가 이 명령을 씁니다. Arm NEON 소개
압축 블록과 저장(stored) 블록
펌웨어는 되돌아 참조하는 복사 명령으로 압축됩니다. “그대로 담은” 블록을 저장 블록이라 하며, 바뀐 부분만 저장 블록으로 다시 넣어 원본 압축을 보존할 수 있습니다.
체크섬
파일 바이트를 32비트로 더한 검사 값입니다. 내용이 바뀌면 다시 계산해 맞춰야 합니다. 암호학적 서명이 아닙니다.

읽는 순서

이해하기 쉬운 순서로 세 문서를 둡니다. 뒤로 갈수록 범위가 넓어집니다.

  • 1단계

    수치 함수 C 재구현

    직접 만든 코드가 원본과 똑같이 계산하는가?

    SAD·SSD와 Q13 행렬 곱 두 함수를 C로 작성해, 합성 입력 237개에서 원본 기계어와 출력이 모두 같았습니다.

  • 2단계

    함수 배치·재패키징

    그 함수를 원래 자리에 넣고 패키지를 다시 만들어도 같은가?

    원래 주소와 실제 색 행렬 준비 호출자에서 출력·레지스터가 같았고, 원본의 헤더·체크섬 검사도 통과했습니다.

  • 3단계

    압축 블록 보존 재패키징

    파일을 원본에 가까운 크기로 줄일 수 있는가?

    블록 3,202개 중 4개만 바꿔 35,136,788바이트로 만들었고, 독립 디코더로 다시 풀어도 결과가 같았습니다.

  • 부팅 전제

    원본 할당에서 이름 조회까지

    원본 allocator가 반환한 포인터를 같은 VM에서 초기화하고 조회했습니다. 합성 RAM의 허용 범위와 호스트가 선택한 진입점은 보고서에 명시했습니다.
