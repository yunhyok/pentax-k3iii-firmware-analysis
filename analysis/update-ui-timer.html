타이머 슬롯에서 UI callback까지

완료 화면의 타이머 요청을 슬롯·이벤트 작업·큐·callback으로 연결했다. 오류 assertion이 복귀하는 경우와 멈추는 경우를 나누어 검사했다.

이전 UI 분석호출 연결예약·취소·오류검증 범위

생성자 0x528eb5c0은 service+0x24와 +0x28에 서로 다른 vptr을 기록한다. timer+0x10은 첫 listener를 가리킨다. 등록 callback에서 timer의 가상 함수를 거쳐 첫 listener의 slot+8을 호출하면 0x528eb47c가 event flag 1을 요청한다. 생성과 등록은 정적 근거이며 실제 OS 등록을 실행하지 않았다. 생성자·vtable 근거

0x528eb420은 event를 기다리고 clear를 요청한 뒤 work 0x1bc, 인수 0, callback=service+0x28을 큐에 넣는다. 두 번째 listener는 this를 보정해 0x528eb81c로 이동하며 ID가 0x1bc일 때만 poll 0x528eb7a4를 호출한다. 합성 검사에서는 event task 한 반복과 실제 enqueue·record dispatcher를 순서대로 실행했다. OS가 이 순서로 전달했다는 증거는 아니다.

0x528eb6b4ID가 0이거나 callback이 NULL인 첫 슬롯을 재사용한다. 모두 사용 중일 때의 할당 경로는 실행하지 않았다.
0x528eb758counter를 증가시키되 이전 값 0xffffffff는 1로 바꾼다. 슬롯에 ID·callback을 쓴 뒤 start wrapper를 호출하고, 복귀하면 counter를 반환한다.
0x528eb490첫 ID 일치 슬롯의 stop wrapper가 복귀하면 ID·callback을 지우고 1을 반환한다. 불일치는 0이다. ID 0도 비교 대상이다.
0x530ebac8OS 반환 0이며 조회 구조체+8이 정확히 1일 때만 1을 반환한다. 오류 후 0 반환은 assertion이 복귀하는 조건에 한정한다.

생성자는 counter+0x50에 1을 기록하므로 이 값에서 첫 예약 handle은 2다. start·stop wrapper는 OS 반환 0을 성공으로 계산하지만 오류일 때 먼저 assertion을 호출한다. assertion을 멈추게 한 시험과 복귀하게 한 시험을 분리했다. 실패에도 handle을 반환하거나 슬롯을 지운다는 결론은 wrapper가 복귀한 경우에만 적용한다. 원본 assertion 본체의 실제 정책은 검사하지 않았다.

poll은 ID 0 또는 callback NULL을 건너뛴다. status wrapper가 0이면 ID·callback을 보존한 뒤 slot+8, slot+4 순서로 0을 기록하고 callback의 slot+8을 호출한다. 이후 vector의 끝을 다시 읽는다. OS 오류 후 assertion이 복귀한 합성 사례도 status 0이 되어 같은 경로로 들어갔다. 39사례 결과

UserFwUpdateController+0x188을 callback으로 주면 원본 vtable의 thunk 0x5274e8c4를 거쳐 0x5274e88c에 도달한다. 전달된 handle이 저장값과 일치할 때 저장 handle을 지우고 byte+0x1ad를 1로 쓴다. 기존 +0x1ac·+0x1ae 조건도 실행했다. 후속 work 5 생산자는 진입 기록 stub이며 실제 work 5 소비와 재부팅은 미확정이다.

39사례와 로컬 의사코드

원본 ARM 39사례가 RTOS·decoded 입력에서 동일하게 통과했다. counter·슬롯 재사용·예약 오류·취소·조회 상태·poll·callback 중 기존 배열에서의 슬롯 재사용과 끝 증가·User callback·work 필터·명시적인 순차 연결을 포함한다. 실제 시간이 흐르거나 OS callback이 전달되는 시험은 아니다.

poll은 callback 뒤에 끝 주소만 다시 읽고 현재 커서를 유지한다. 따라서 이 결과는 배열 재할당이나 모든 축소 동작의 안전성을 입증하지 않는다. 이식 시 순회 중 기존 배열의 수명과 커서·끝 위치의 관계를 보장해야 한다. 현재 커서 유지 명령과 검증 한계

genuine C 12개와 지원 범위 15개, ARM 698 words를 로컬에 저장했다. 직접 전이 68개·간접 전이 5개·리소스 8개·포인터 10개·조건부 연결 4개의 주소와 해시를 대조했다. 자동 복원 C에는 poll의 iterator 오류와 tail call 누락이 있어 원본 ARM을 해석 기준으로 삼았다.

OS syscall·event·lock·assertion은 명시적인 stub이다. 실제 시간 단위·지연·재부팅·decoded 버퍼 최종 회수·비제로 bank 생산자·인증은 확인하지 않았다. 카메라·매체 I/O와 빌드·플래시는 수행하지 않았다. 하위 커널의 산술은 별도 분석으로 구분한다.
