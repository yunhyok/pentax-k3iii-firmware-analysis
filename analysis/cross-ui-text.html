K-3 III와 Q7이 sRGB 글자를 그리는 방식 비교

두 카메라의 색공간 화면에는 같은 sRGB라는 이름이 나옵니다. 화면을 다른 기종으로 옮길 때 그대로 넘겨도 되는 것과 기종마다 다시 맞춰야 하는 것을 가렸습니다.

핵심 요약

  • 두 기종이 공유할 수 있는 것은 표시할 이름과 화면에서의 역할까지입니다. 글꼴, 크기, 좌표와 클립, 픽셀 형식은 기종마다 다릅니다.
  • K-3 III는 커버리지 비트맵과 배경 워드를 섞어 32비트 색을 씁니다. Q7은 글꼴 셀을 가로로 4분의 3으로 줄인 뒤 8비트 팔레트 번호를 씁니다. 같은 값 1이 K-3 III에서는 0x838d97a2, Q7에서는 번호 2가 됩니다.
  • Q7은 그리기 컨텍스트 등록 슬롯이 비어 있으면 그리기 ID만 바뀌고 이전 컨텍스트가 남습니다. 이식할 때는 ID와 함께 실제로 받은 포인터를 확인해야 합니다.
  • 이 비교는 이미 공개한 두 기종의 원본 실행 기록과 산술 재계산으로 만들었습니다. 이 문서의 명령은 펌웨어를 실행하지 않으며, 실제 LCD 출력과 기종 간 이식은 확인하지 않았습니다.

확인 원본 실행 기록과 재계산으로 확인

  • K-3 III 32비트 전송의 좌표·커버리지·쓰기 수 (원본 기록)
  • Q7 축소 폭, 글자 x 좌표, Q16 소스 열 선택
  • 값 1의 32비트 혼합 결과 재계산

모델 시험 조건으로 정한 것

  • 두 기종의 합성 표면과 팔레트 준비 상태
  • Q7의 컨텍스트 등록표(ID 0·17, 빈 슬롯 18)
  • 합성 바이트 0x1b 반례

미확인 확인하지 않은 것

  • 실제 부팅 때의 컨텍스트 등록
  • 실제 팔레트 색과 LCD 출력
  • 한 기종의 화면을 다른 기종으로 옮긴 실행

배경: 글자를 그리는 약속은 크기·좌표·픽셀 형식으로 나뉩니다

화면 부품이 글자를 그리려면 그리기 코드와 몇 가지를 약속해야 합니다. 어떤 글꼴을 어떤 크기로 쓸지, 어느 좌표에 놓고 어디서 잘라 낼지, 표면의 픽셀 하나를 어떤 값으로 채울지입니다. 이 문서는 이 묶음을 기종별로 비교합니다.

픽셀 형식이 특히 다릅니다. K-3 III 표면은 픽셀마다 4바이트 색 값을 담습니다. Q7 표면은 픽셀마다 1바이트 번호를 담고, 실제 색은 그 번호로 팔레트(색 목록)를 찾아 정합니다. 같은 비트맵 값을 넘겨도 두 기종에서 뜻이 달라집니다.

두 기종의 시험 조건

K-3 III는 256×144 32비트 표면에 문자열 전체를, Q7은 피치 736바이트 8비트 표면에 네 글자를 하나씩 그렸습니다.

K-3 III의 자식 위치와 스냅샷은 원본 좌표 함수 두 개가 준비했습니다. Q7은 별도 속성 시험에서 48×48 요청을 합성 컨텍스트에 적용해 그렸습니다.

같은 값 1이 두 기종에서 다른 픽셀이 됩니다

K-3 III는 값 1을 float32 혼합 색 0x838d97a2로, Q7은 팔레트 번호 2로 바꿉니다. Q7의 가로 축소는 잘라 낸 Q16 역배율을 쓰므로 정확한 중점 계산과 열이 다를 때가 있습니다.

K-3 III: 배경 워드 하나와 가중치로 섞기

K-3 III는 교차 영역 왼쪽 위의 기존 워드를 읽어 전송 전체의 배경으로 씁니다. 각 바이트에 전경·배경 가중치를 적용해 float32로 계산한 뒤 정수로 잘라 표를 만듭니다. 값 1의 대조에는 프로필 0의 전경 0xffffffff, 시험 배경 0x31425364, ROM 가중치 0.4와 0.6의 float32 값을 썼습니다. 계산 과정은 sRGB 글자의 래스터와 픽셀 전송의 그림에 있습니다. 바이트가 LCD에서 어떤 색 채널인지는 따로 확인해야 합니다.

Q7: Q16 고정소수점으로 가로 축소

Q7은 가로 배율 factor=(48<<16)//64(= 49,152, 0.75)를 먼저 계산합니다. 각 글자의 출력 폭은 (원본 폭×factor)>>16입니다. 이어서 가로 역배율 나눗셈과 절반 간격을 적용해 출력 열 j가 읽을 소스 열을 정합니다. 2비트 코드는 소스 바이트의 높은 비트부터 꺼냅니다. 이 계산은 고정소수점 Q16 형식입니다.

step = (원본 폭 << 16) // 출력 폭
소스 열 = (j * step + (step >> 1)) >> 16
픽셀 표현과 축소 계산의 반례 (열 번호는 0부터)
비교 입력원본 경로에 따른 결과
값 1K-3 III는 0x838d97a2를 계산합니다. Q7은 팔레트 번호 2를 씁니다.
Q7 폭 24 → 18, 출력 열 1잘라 낸 Q16 역배율(87,381)로는 소스 열 1입니다. 정확한 유리수 중점 계산은 열 2를 고릅니다.

합성 바이트 0x1bQ7은 네 코드 0,1,2,3으로 풉니다. K-3 III에 그대로 넘기면 값 27이 되어 검증한 커버리지 범위를 벗어납니다.

합성 바이트 반례에는 원본 글꼴 데이터를 쓰지 않았습니다. 계산한 소스 열 전체와 수치 반례는 cross-ui-text.json에 있고, Q7 쪽 수식과 독립 프레임 계산은 Q7 축소 수식과 독립 프레임 계산에 있습니다.

그리기 대상과 클립은 기종마다 따로 확인해야 합니다

K-3 III는 같은 StringView가 하네스의 표면 포인터에 그리고, Q7은 활성 컨텍스트 포인터가 가리키는 곳에 그립니다. Q7에서는 ID가 바뀌어도 포인터가 그대로일 수 있습니다.

K-3 III의 그리기 슬롯 0x52bedb40은 같은 StringView와 하네스가 공급한 표면 포인터를 이어서 씁니다. 프로필 0에서 원본이 채운 팔레트 26·28번을 읽었고, 팔레트 생성자는 0x529191b0의 UserData 읽기 전에 멈췄습니다. A5 사례에서 전송 재개부터 원본 그리기 함수 복귀까지 모형 호출은 0건이었습니다. 앞 단계의 준비 플래그와 파일·할당 모형은 남아 있습니다(K-3 III 사례별 실행·모델 기록).

Q7 속성 시험은 ID 0과 17이 같은 컨텍스트를 쓰도록 공급했습니다. 별도 등록표 시험에서 다음 슬롯이 비어 있으면 그리기 ID는 18로 바뀌었지만 활성 포인터 0x800eb4d8는 이전 컨텍스트를 유지했습니다. 그래서 버퍼 교대 뒤에는 ID와 함께 속성·텍스트 호출이 실제로 받은 포인터를 확인해야 합니다(Q7 등록표·빈 슬롯 대조).

그 뒤의 960×480 합성 실행은 등록표와 큐 전달 모형을 써서 원본 갱신부터 두 텍스트 행과 마커까지 실행했습니다. 같은 sRGB 글리프 네 번의 호출을 확인했고, 바깥 소비자로 복귀하기 전인 0x80adf468에서 멈췄습니다(Q7 갱신에서 원본 픽셀까지).

Q7 축소 루프의 0x80226a5c..0x80226a90에는 프레임 행 포인터와 가로 좌표 검사가 있습니다. 이 비교의 고정 입력에는 부분 잘림의 원본 실행이 들어 있지 않습니다. 별도 실험에서 일곱 배치를 원본 코드로 실행했고, (−9, −12)에서 행 주소 검사로 보이는 8픽셀이 생략됐습니다(Q7 원본 글리프의 가장자리 처리, K-3 III 쪽은 화면 경계 문서).

정정

원본 명령을 다시 대조해 Q7의 가로 나눗셈 주소를 0x8022684c로 고쳤습니다. 그 몫은 0x802268a4에서 읽습니다. 예전에 적은 0x802268a8은 세로 나눗셈입니다. Q16 열 번호와 픽셀 대조 결과는 같았습니다(정정 주소·원본 구간 해시).

이식에서 다음으로 검증할 조건

기종 간에는 이름과 역할만 넘기고, 나머지는 대상 기종의 글꼴·컨텍스트·표면에서 다시 대조해야 합니다.

  1. 글리프 위치 표시할 이름과 역할을 넘기고, 대상 기종의 문자열·글꼴에서 각 글리프 위치와 합성 프레임을 대조합니다.
  2. 컨텍스트 Q7에서 등록 슬롯이 있는 경우와 빈 경우를 나눠, 속성 설정과 글자 그리기가 의도한 컨텍스트에 닿는지 확인합니다.
  3. 경계와 색 Q7 합성 표면 경계에 글자를 걸쳐 팔레트 번호 쓰기와 보호 바이트를 확인합니다. 실제 색은 팔레트가 표시 경로로 전달되는 과정에서 따로 확인해야 합니다.

세 기종 전체의 이식 조건은 세 기종 UI 이식 조건에 정리했습니다.

한계와 남은 과제

  • 이 비교는 고정된 텍스트 경로만 다룹니다. 부분 잘림은 이 비교기가 재현하지 않으며 Q7 별도 실험에 있습니다.
  • 이 문서의 명령은 원본 펌웨어, ROM 데이터, 글꼴, 비트맵, 프레임을 읽지 않습니다.
  • 실제 팔레트와 LCD는 검증하지 않았고, 기종 간 UI 이식도 실행하지 않았습니다.

재현 방법

검증기는 공개 JSON 다섯 개(K-3 III 세 개, Q7 두 개)의 고정 해시를 확인한 뒤 좌표·픽셀 표현·Q16 열 선택을 산술로 다시 계산합니다. 기존 원본 실행 기록을 입력으로 쓰며 원본 코드를 실행하지 않습니다. 소스 기준은 K-3 III fdadab5와 Q7 77dfa9d입니다. --q7-root에는 Q7 저장소 경로를 줍니다.

python -B tools/check_cross_ui_text.py --q7-root "../Pentax Q7" --output cross-ui-text-replay.json
python -B -m unittest discover -s tests -p test_check_cross_ui_text.py
기록 정정 이력

K-3 III 최초 기록의 사례별 표면 높이 40은 fdadab5에서 144로 정정됐습니다. 글자 비트맵 높이 40과 최종 프레임 해시는 그대로입니다(고정 입력·정정 이력·재현 결과).
