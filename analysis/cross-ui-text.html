K-3 III와 Q7의 sRGB 글자 그리기 비교

색공간 선택 화면의 sRGB 이름은 공유할 수 있습니다. 실제로 글자를 그릴 때 K-3 III는 32비트 색상 워드를 계산하고, Q7은 8비트 팔레트 번호를 씁니다. 같은 값 1이 두 경로에서 다른 픽셀을 뜻합니다.

이 문서에서

  1. 기종별로 글자가 픽셀이 되는 순서
  2. 샘플 값과 축소 수식의 차이
  3. 클립과 그리기 대상은 각 기종에서 확인
  4. 이식에서 다음으로 검증할 조건

기종별로 글자가 픽셀이 되는 순서

K-3 III 시험은 하네스가 공급한 256×144 타입 5 표면을 사용했습니다. 원본 0x52c003f0과 0x52c02538이 자식 위치와 스냅샷을 준비하고, 텍스트 사각형 [110,22,76,40]을 뷰 클립 [110,22,80,40]과 교차했습니다. 교차 영역이 비트맵 전체를 덮었고, 피치는 256워드였습니다. 비트맵의 0인 샘플 2,335개는 기존 픽셀을 보존했고 부분 커버리지 705개가 각각 한 워드를 썼습니다. 0xff 샘플은 없었습니다. K-3 III 원본 래스터·전송 기록

Q7의 별도 속성 시험은 피치 736바이트, 176행, 시작점 (96,64)를 사용했습니다. 요청한 48×48 크기에 맞춰 원본 글리프 폭 24·29·34·29를 18·21·25·21로 줄였고 높이는 48로 유지했습니다. x는 96·114·135·160이었습니다. 글리프 코드 0은 투명 모드 1에서 쓰기를 건너뛰고, 코드 1·2·3은 이 시험의 팔레트 번호 2·1·3에 대응합니다. 실제로 쓴 번호는 1과 2였습니다. Q7 고정 속성·픽셀 기록

샘플 값과 축소 수식의 차이

K-3 III의 0x528c2664는 교차 영역 좌상단의 기존 워드를 읽어 전송 전체의 배경으로 씁니다. 0x528c21f8은 각 바이트 성분에 전경·배경 가중치를 적용하고 float32 연산 뒤 정수로 잘라 테이블을 만듭니다. 이 경로의 부분 커버리지 값은 1~15입니다. 아래 값 1의 대조는 프로필 0의 전경 0xffffffff, 시험 배경 0x31425364, 해당 ROM 가중치 0.4와 0.6의 float32 값을 사용합니다. 바이트 성분의 실제 LCD 색상 배치는 별도 확인이 필요합니다. K-3 III 원본 관측값과 가중치 범위

Q7은 가로 배율 factor=(48<<16)//64를 먼저 계산합니다. 각 글자의 출력 폭은 (원본 폭×factor)>>16입니다. 0x8022684c의 가로 역배율 나눗셈과 0x80226938의 절반 간격을 적용하면 출력 열 j는 다음 소스 열을 읽습니다. 2비트 코드는 각 소스 바이트의 높은 비트부터 꺼냅니다. Q7 축소 수식과 독립 프레임 계산

step = (원본 폭 << 16) // 출력 폭
소스 열 = (j * step + (step >> 1)) >> 16
비교 입력원본 경로에 따른 결과
샘플 값 1K-3 III는 0x838d97a2를 계산합니다. Q7은 팔레트 번호 2를 씁니다.
Q7 폭 24 → 18, 출력 열 1잘라낸 Q16 역배율로는 소스 열 1입니다. 정확한 유리수 중점 계산은 열 2를 고릅니다.
Q7 폭 24 → 18, 출력 열 2원본 수식은 소스 열 3, 왼쪽 끝을 고르는 수식은 열 2입니다.
합성 바이트 0x1bQ7은 네 코드 0,1,2,3으로 풉니다. K-3 III에 그대로 넘기면 값 27은 검증한 커버리지 범위를 벗어납니다.

열 번호는 0부터 셉니다. 합성 바이트 반례에는 원본 글꼴 데이터를 사용하지 않았습니다. 계산한 소스 열과 수치 반례

클립과 그리기 대상은 각 기종에서 확인

K-3 III의 그리기 슬롯 0x52bedb40은 같은 StringView와 하네스가 공급한 표면 포인터를 이어 씁니다. 프로필 0에서 원본이 채운 인덱스 26·28을 읽었고, 팔레트 생성자는 0x529191b0의 UserData 읽기 전에 멈췄습니다. A5 사례에서 전송 재개부터 원본 그리기 함수 복귀까지 모델 호출은 0건이었습니다. 앞 단계의 준비 플래그, 파일·할당 모델은 남아 있습니다. K-3 III 사례별 실행·모델 기록

Q7 속성 시험은 ID 0과 17이 같은 컨텍스트를 쓰도록 공급했습니다. 별도 등록표 시험에서 다음 슬롯이 비었을 때 그리기 ID는 18로 바뀌었지만 활성 포인터 0x800eb4d8는 이전 컨텍스트를 유지했습니다. 따라서 교대 뒤에는 ID와 함께 실제 속성·텍스트 호출이 받은 포인터를 확인해야 합니다. 이후 960×480 합성 실행은 등록표와 큐 전달 모델을 사용해 원본 갱신에서 두 텍스트 행과 마커까지 실행했습니다. 같은 sRGB 글리프 네 호출을 확인했고 바깥 소비자 복귀 전인 0x80adf468에서 멈췄습니다. Q7 등록표·빈 슬롯 대조 · Q7 갱신에서 원본 픽셀까지

Q7 축소 루프의 0x80226a5c..0x80226a90에는 프레임 행 포인터와 가로 좌표 검사가 있습니다. 이 비교기의 고정 입력은 부분 잘림의 원본 실행을 포함하지 않습니다. 별도 후속 시험에서는 일곱 배치를 원본 코드로 실행했고, (−9, −12)에서 행 주소 검사로 보이는 8픽셀이 생략됐습니다. Q7 원본 글리프의 가장자리 처리

원본 명령을 다시 대조해 가로 나눗셈 주소를 0x8022684c로 정정했습니다. 그 몫은 0x802268a4에서 읽고, 종전에 적은 0x802268a8은 세로 나눗셈입니다. Q16 열 번호와 픽셀 대조 결과는 같았습니다. 정정 주소·원본 구간 해시

이식에서 다음으로 검증할 조건

  1. 표시할 이름과 역할을 넘기고, 대상 기종의 문자열·글꼴에서 각 글리프 위치와 합성 프레임을 대조합니다.
  2. Q7에서 등록 슬롯이 있는 경우와 빈 경우를 나눠 속성 설정과 글자 그리기가 의도한 컨텍스트에 도달하는지 확인합니다.
  3. Q7 합성 표면 경계에 글자를 걸쳐 팔레트 번호 쓰기와 보호 바이트를 확인합니다. 실제 색은 팔레트가 표시 경로에 전달되는 과정에서 따로 확인해야 합니다.

검증기는 공개 JSON 다섯 개의 고정 해시를 확인하고 좌표·픽셀 표현·Q16 열 선택을 산술로 다시 계산합니다. 기존 원본 실행 기록을 입력으로 쓰며, 이번 명령은 펌웨어나 글꼴을 읽거나 원본 코드를 실행하지 않습니다. 소스 기준은 K-3 III fdadab5와 Q7 77dfa9d입니다. K-3 III에서 최초 기록의 사례별 표면 높이 40은 fdadab5에서 144로 정정됐습니다. 글자 비트맵 높이 40과 최종 프레임 해시는 같았습니다. 고정 입력·정정 이력·재현 결과

python -B tools/check_cross_ui_text.py --q7-root "../Pentax Q7" --output cross-ui-text-replay.json
python -B -m unittest discover -s tests -p test_check_cross_ui_text.py

이 결과는 시험용 표면에 그린 글자의 비교입니다. 실제 부팅의 컨텍스트 등록, LCD 출력과 기종 간 UI 이식은 별도 검증이 필요합니다. 산술 검증기 · 산술·입출력 시험 · 세 기종 UI 이식 조건
