DCP와 Enhanced XMP의 적용 위치

단계표현하는 변환
DCP 행렬ColorMatrix는 XYZ에서 기준 카메라 색공간으로, ForwardMatrix는 화이트밸런스를 적용한 카메라 색에서 XYZ D50으로 변환한다. 단순히 역행렬 관계에 있지 않다.
DCP HSV 표ProfileHueSatMap은 XYZ D50 변환 후 선형 ProPhoto RGB 원색으로 만든 HSV를 보정한다. ProfileLookTable은 같은 색공간에서 노출 보정 뒤, 톤 곡선 전에 적용한다. 인코딩 1은 3차원 표에서 HSV의 V에 sRGB 전달 함수를 적용하는 방식이다.
Enhanced XMPRAW에서는 지정한 기준 DCP 위에 적용할 수 있다. 별도의 HSV Look Table 또는 처리 후반에 적용되는 RGB→RGB LUT를 포함할 수 있다. Adobe의 2018 SDK는 Camera Raw에서 .cube 파일을 불러오는 절차와 32×32×32 한도를 설명한다.

독립 보정값으로 DCP 만들기

내보내기 도구는 파이썬 표준 라이브러리만 쓴다. JSON에 데이터의 출처를 provenance로 적고, RAW의 UniqueCameraModel을 정확히 입력한다. ProfileName, ColorMatrix1, CalibrationIlluminant1도 필수다. 아래 숫자는 파일 형식 시험용이며 실제 PENTAX 기종에 사용할 값은 아니다.

{
  "provenance": "Synthetic serialization test only",
  "UniqueCameraModel": "TEST camera, not a real model",
  "ProfileName": "Bridge Format Test",
  "CalibrationIlluminant1": 17,
  "ColorMatrix1": [[0.85, -0.125, 0.0625], [0, 1, 0], [0, 0, 1]]
}

위 JSON을 저장소 안 .private/profile-input.json에 저장한 뒤 실행한다. 출력 경로에 파일이 이미 있으면 작업을 중단하며, 입력·출력 SHA-256과 출처는 표준 출력으로 기록한다.

python tools/profile_bridge.py .private/profile-input.json .private/profile-output.dcp
python inspect_adobe_profiles.py .private/profile-output.dcp
python -m unittest discover -s tests -p test_profile_bridge.py -v
exiftool -validate -Warning -Error -FileType .private/profile-output.dcp
  • 3채널 SDR 기준이며 조명은 한 개 또는 두 개다. A(17), D55(20), D65(21), D75(22), D50(23)을 받는다. 두 번째 조명에는 CalibrationIlluminant2와 ColorMatrix2가 필요하다. ForwardMatrix1/2는 선택 입력이며, 조명이 두 개일 때는 둘 다 제공하거나 둘 다 생략한다. 행렬은 행 우선 3×3이고 10−6 단위의 부호 있는 유리수로 저장한다.
  • 선택 입력 ProfileHueSatMapDims와 ProfileHueSatMapData1, 또는 ProfileLookTableDims와 ProfileLookTableData는 각각 함께 제공한다. 조명 두 개에 다른 HueSatMap을 적용하려면 ProfileHueSatMapData2를 추가한다. 차원은 [H,S,V], 데이터는 [hue_shift_deg,sat_scale,value_scale]의 배열이며 S→H→V 순으로 인덱스가 증가한다. V 차원이 1보다 크면 각각의 …Encoding에 0(선형) 또는 1(sRGB V 인코딩)을 명시한다. ProfileToneCurve는 [0,0]에서 [1,1]까지 x가 증가하는 선형 감마 좌표 쌍이다.

기존 파서로 태그를 확인하고, ExifTool 13.59가 합성 파일을 DCP로 읽어 Validate: 0 0 0을 반환했다. 단위 테스트 5개는 두 조명의 태그와 배열 값, 잘못된 입력 거부, 기존 출력 보존을 검사한다. Adobe SDK가 행렬을 정규화하고 소수 네 자리로 반올림한 뒤에도 유효한지 검사하며 톤 곡선은 8,192점으로 제한한다. 테스트 · 검사값과 합성 파일 해시 · Adobe DNG SDK 안내

카메라 색을 맞추기 위해 남은 확인

  1. 입력 좌표: RAW의 검정·백색 레벨과 채널 배열, 노출 배율, B2r의 WB gain 단위 및 적용 전후 좌표를 확인한다. Q13으로 계산한 펌웨어 행렬은 아직 DNG가 정의하는 방향의 행렬로 바꿀 수 없다. 각 RGB·YCbCr 구간의 원색, 백색점, 선형성과 행렬 순서가 필요하다.
  2. 픽셀 처리: 모드·출력 형식·bypass에 따른 분기와 실제 MultiAxial·ColorReference 보간, M2P/R2y 포화 및 감마·톤의 순서를 확인한다. 펌웨어에서 찾은 설정값과 ARM 계수 산술은 이 처리 순서의 증거 일부다. 하이라이트 클리핑, 히스토그램에 의존하는 처리, 노이즈 감소나 샤프닝까지 전역 LUT 한 개로 맞출 수는 없다. 계수와 설정 근거 · 픽셀 경로와 검증 조건
  3. 같은 RAW의 출력 쌍: 기종별로 같은 RAW를 카메라에서 여러 Custom Image로 현상한다. 두 K-3 기종은 TIFF 또는 JPEG, Q7은 JPEG로 출력할 수 있다. WB, 노출, 출력 색공간과 모드 세부값, 자동 보정, 렌즈·펌웨어 버전을 기록한다. Auto Select는 실제 선택된 모드를, Cross Processing은 고정 프리셋을, Monochrome은 필터·토닝 값을 구분한다. K-3 Mark III · K-3 II · Q7
  4. 별도 장면으로 확인: Adobe에서 기준 DCP, Process Version, WB, 노출과 자동 보정을 고정한다. 색상표와 회색 계조를 두 조명과 여러 노출에서 촬영하고, 적합에 사용하지 않은 피부·잎·고채도·하이라이트 장면을 별도로 확보한다. 같은 출력 색공간으로 변환한 다음 패치별 ΔE00 분포, 중성축, 계조, 채널별 클리핑을 비교한다. 그 결과로 DCP HSV 표와 후반 RGB LUT 중 어느 쪽이 목표 변환을 잘 표현하는지 판단할 수 있다.

이 도구는 계수 추정, XMP 작성, Lightroom 설치를 수행하지 않는다. 구조 검사와 기종별 색 검증을 구분한다. 생성 파일은 DNG 명세의 기본 ProfileEmbedPolicy(0)를 따르므로 현재 시험 대상은 DNG다. PEF에서의 적용은 별도 검증이 필요하다. Q7의 Smart Effect는 Ricoh 사양상 Custom Image와 별도이며, 다른 기종에서 이름이 같은 모드도 별도 보정이 필요하다. Q7 촬영 설정

설치 파일 검사 재현

$profilePaths = @(Get-ChildItem -LiteralPath 'C:\ProgramData\Adobe\CameraRaw\CameraProfiles' -Recurse -File |
  Where-Object { $_.Name -match '^PENTAX (?:K-3 Mark III|K-3 II|Q7) (?:Adobe Standard|Camera .+)\.dcp$' } |
  ForEach-Object FullName)
python inspect_adobe_profiles.py @profilePaths

Lightroom Classic 내장 파일의 경우 위 경로를 프로그램의 Resources\CameraProfiles로 바꿔 실행한다. 공개 기록은 파일 크기, 태그 형식과 개수, 차원 및 SHA-256을 포함한다.
