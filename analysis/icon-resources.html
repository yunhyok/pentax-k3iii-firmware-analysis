PENTAX K-3 MARK III · FIRMWARE 2.20 · 2026-11-08

ICONBIN의 저장 형식과 GUI 호출 경로

아이콘 포인터 배열, 원본 ARM의 픽셀 복사, 기존 IconView 필드 연결을 확인했다. ID 5의 44픽셀을 바꾼 로컬 후보와 원복 검사도 완료했다.

연구 개요 · 업데이트·리소스 적재 · 셔터·AF

1,666개 슬롯이 가리키는 데이터

런타임 주소 0x54521140은 descriptor 자체가 아닌 포인터 배열이다. 원본 ROM 주소는 0x53d08e80이며 배열 간격은 4바이트다. 각 포인터가 가리키는 descriptor는 이 펌웨어에서 12바이트다. 활성 슬롯 1,665개와 비활성 ID 0을 확인했다. 활성 픽셀 범위는 ICONBIN의 26,219,192바이트를 빈틈이나 겹침 없이 정확히 나눈다. 배열·범위·원본 해시

descriptor 필드확인된 접근해석
+0 · u8528c3f68 / 528c48540이면 그리기를 생략한다. 픽셀 형식 번호인지는 미확정이다.
+1 · u8, +6 · u16해당 버전의 모든 슬롯에서 0의미 미확정. 로컬 parser는 다른 값을 거부한다.
+2 / +4 · u16528c3fd4 / 528c3ff4폭 / 높이
+8 · u32528c4884 → 528c489032비트 픽셀 단위 offset. source = ICONBIN base + 4 × offset.

ICONBIN payload 안에는 이 descriptor 배열이 없다. 따라서 픽셀 크기를 바꾸려면 payload뿐 아니라 RTOS에 있는 descriptor와 뒤따르는 offset도 함께 검토해야 한다. 이번 후보는 크기와 descriptor를 보존했다.

기존 GUI에서 픽셀까지

IconView의 ID setter는 값이 달라질 때만 0x52c0205c로 invalidation을 요청한다. snapshot은 ID와 사각형을 그리기용 필드에 복사한다. nested draw 객체의 vtable 연결과 config 전달까지 확인했지만 실제 메뉴 이벤트가 ID 5를 선택하는 지점은 찾지 못했다. 아이콘 모양만으로 메뉴 이름을 붙이지 않았다. 함수 범위·전이·핵심 명령

0도 blitter 0x528c3ffc는 픽셀을 u32로 읽고 같은 word를 저장한다. source 행 간격은 4 × width, destination 행 간격은 4 × pitch다. 픽셀 상위 byte가 draw 객체의 +7과 같으면 복사를 생략한다. 이 함수에는 팔레트 lookup, 압축 해제, 알파 가중 혼합이 없다. 다른 GUI 경로나 이후 디스플레이 처리까지 같은 방식이라고 단정하지 않는다.

copyWidth  = min(requestedWidth, descriptor.width)
copyHeight = min(requestedHeight, descriptor.height)
srcStart   = source + 4 * (offsetY * descriptor.width + offsetX)
dstStart   = destination + 4 * ((y + offsetY) * pitch + x + offsetX)
copy u32 pixel only when (pixel >> 24) != drawObject.byte7

원본 함수는 offset을 더한 뒤 폭을 다시 줄이지 않는다. 자체 작성 모델은 source와 destination 사각형이 모두 유효한 경우만 허용한다. 이 입력 검사는 로컬 도구의 정책이며 펌웨어가 같은 검사를 수행한다는 뜻은 아니다.

되돌릴 수 있는 단일 아이콘 후보

ID 5는 40 × 40 픽셀이며 payload의 [25,600, 32,000) 범위를 사용한다. 우하단에 7 × 7 크기의 + 표식을 새로 작성해 44개 pixel word를 변경했다. 상위 byte, descriptor, 다른 아이콘의 바이트는 유지했다. 원본 아이콘을 다시 넣었을 때 전체 ICONBIN의 SHA-256이 원본과 일치했다. 원본 픽셀과 미리보기는 로컬에 보관한다. 후보·원복 해시

미리보기는 하위 세 byte가 같고 상위 byte가 0 또는 255인 아이콘만 표시한다. 이 제한 때문에 RGB 채널 순서의 영향을 피할 수 있지만 LCD의 색 의미·감마·알파 합성을 재현한 것은 아니다. 추출 도구는 기존 출력 디렉터리를 거부하며 원본 입력을 읽기만 한다.

이 후보를 넣은 오프라인 패키지는 구조·체크섬 검사와 원본 ARM 검사 8건을 통과했다. 수정 패키지는 stored block으로 다시 인코딩해 78,690,708바이트가 됐다. 파일 로더의 할당 한계와 하드웨어 디코더, 전체 updater, 카메라 동작은 검증하지 않았다. 무변경 재포장은 원래 압축 stream을 재사용하여 원본과 바이트 단위로 일치한다. 원본 compressor를 복원했다는 의미는 아니다. 재포장 방식과 한계 · 검사 결과 · 후보 레코드 해시

원본 ARM과 의사코드를 대조한 결과

parser·경계 검사 28건과 원본 ARM 실행 33건을 독립 재실행해 통과했다. ARM 검사는 합성 blit 23건, 원본·후보 아이콘 blit 2건, ID setter 5건, snapshot 3건이다. blitter와 destination getter는 stub 없이 실행했다. setter의 invalidation만 stub으로 받아 호출 횟수를 확인했다. 상세 결과 · 재현 코드

추가 의사코드 6개와 보조 범위 8개를 로컬에 저장했다. 원본 ARM 573개 word, 전이 96개, 데이터 범위 16개와 포인터 word 1,728개를 대조했다. angr가 만든 blitter C는 조건부 STRNE를 무조건 저장으로 표현했고 setter C는 invalidation tail call을 생략했다. raw C는 그대로 보존하고 분석과 모델은 원본 명령·실행 결과를 근거로 삼았다. 범위·해시·오류 위치

로컬 재현 방법
python icon_resource_probe.py decoded.bin --output-dir NEW_LOCAL_DIRECTORY
python verify_icon_resources.py decoded.bin --output checks.json

첫 도구는 Pillow, 검사 도구는 Unicorn을 사용한다. 입력은 이 버전의 decoded.bin이어야 하며 SHA-256도 일치해야 한다. 출력에는 추출 픽셀이 포함되므로 공개 저장소에 추가하지 않는다. 자체 작성 추출·후보 도구

K-3 II·Q7 이식 연구에 남은 조건

이번 결과는 K-3 Mark III의 asset 편집 근거다. 다른 기종으로 옮기려면 descriptor, 픽셀 표현, GUI 객체 구조, 이벤트 ID와 화면 출력을 각 대상 펌웨어에서 별도로 연결해야 한다. Ricoh의 K-3 III·K-3 II 메뉴 대응표는 메뉴 의미와 배치 비교에 사용할 수 있지만 바이너리 호환성의 근거는 아니다.

실제 GUI event loop, 디스플레이, 카메라 플래시는 실행하지 않았다. 공개 자료는 자체 작성 도구와 검증 메타데이터이며 원본 펌웨어·픽셀·디컴파일 C는 로컬에 보관한다.
