PafMotor의 두 필드와 주변 입력값 경로

K-3 III 펌웨어 2.20의 PafMotor 생성자는 +0x56과 +0x68을 0으로 초기화합니다. 두 필드의 비영값 출처는 미확인입니다. 디버그 요청이 쓰는 Motor 필드와 렌즈 정보 계산이 읽는 Pulse 필드를 원본 ARM에서 대조했습니다.

원본 포인터로 구분한 세 경로

PafControlDebug의 원본 포인터 저장은 0x52cb4610, PafLensInfo의 두 저장은 0x52f06194와 0x52f061c0입니다. 원본 생성자가 쓴 vptr와 ROM RTTI 이름으로 객체를 대조했습니다. 원본 구간 SHA-256과 재생 기록

Pulse 입력의 설정 레코드

원본 호출 0x52cb19f4와 0x52cb3240은 PafControl +0x34의 Pulse를 대상으로 합니다. 두 호출은 앞서 0x52caad00을 불러 PafSensorAccessor +0x10이 가리키는 PafIntegralConfig의 +0xec u16을 스택 인자로 넘깁니다. 0x52caa2c0의 바인더와 0x52ca4524부터 이어지는 factory 할당 루프를 대조했습니다.

PafIntegralConfig 생성자 0x52cea934는 +0xec을 0으로 초기화합니다. 별도 설정 복사 경로는 호출 0x52cf1874에서 상위 객체 +0x48의 포인터를 받고, 0x52ceac04에서 그 소스 +0x98의 u16을 읽어 0x52ceac10에서 PafIntegralConfig +0xec에 씁니다. 재현에서는 소스 halfword와 객체 포인터를 공급한 뒤 복사와 accessor를 별도 진입으로 실행하고, 실제 accessor 반환값을 Pulse 계산의 진입 인자로 전달했습니다. 상위 객체가 이 소스 값을 처음 얻는 경로와 레코드 수명은 미확인입니다.

원본 분기에서 0x52f0e200 반환이 0일 때, 0x52f0e3d0은 그 스택 인자와 [Pulse+0xc]+0x34의 u16 중 작은 값을 선택합니다. 이어서 0x52f0e2f4는 렌즈 객체 +0x198c의 word에서 상위 10비트와 하위 6비트를 지운 값이 0x000dafc0이고, 같은 객체의 +0x167 바이트가 0xf0일 때만 v−(v >> 5)로 조정합니다. 0x52f0e3f4에서 결과를 Pulse +0x56에 저장합니다.

재현은 최솟값 선택 직전에서 시작해 원본 조정 함수와 저장 명령을 실행했습니다. 앞선 분기와 호출은 정적으로 확인했습니다. 별도 LensInfo 진입 0x52f0671c은 Motor +0x1a를 읽고, 0x52f06734는 Pulse +0x56을 분모로 읽습니다. Motor 플래그가 0이면 0x52f0674c에서 Pulse +0x40에서 요청값을 뺍니다. 플래그가 0이 아니면 0x52f06740에서 요청의 하위 16비트를 부호 확장한 뒤 0x52f06750에서 Pulse +0x40에서 뺍니다. 공통 UXTH 명령 0x52f06754가 남기는 하위 16비트는 같습니다.

분모가 0이면 결과도 0입니다. 분모가 비영이면 차이의 하위 16비트를 8비트 왼쪽으로 시프트한 뒤 분모로 나누고 65,535에서 상한을 적용합니다. 별도 대조는 요청값 4개를 A7 기본, 초기 레지스터·NZCV를 바꾼 A7과 A15에서 각각 실행했습니다. 같은 요청에서 플래그만 바꾼 12쌍은 서로 다른 로드 명령을 거쳤고 모든 쌍의 비율이 같았습니다. 24회 실행의 로드 주소와 결과

원본 재생 10건

실행 구간관찰한 변화Motor +0x56/+0x68
생성자0xa5로 채운 객체에서 원본 두 halfword 쓰기0 / 0
초기화 앞부분Motor +0x54와 Pulse +0x2e를 0으로 씀공급한 0xc345 / 0x8137 유지
디버그 설정요청 0x9abc1232에서 Motor +0x78/+0x7a에 0x9abc / 0x123두 시험값 유지
디버그 해제 2건요청 bit 0·1과 Debug +0x2c가 모두 0인 조건입니다. Motor +0x33이 0이면 두 값을 유지하고, 활성 상태에서 핸들 +0x74가 0이면 +0x78/+0x7a를 지웁니다.두 시험값 유지
Pulse 쓰기와 LensInfo 5건Pulse +0x56에 차례로 320, 320, 310, 0, 1을 썼습니다. 별도 LensInfo 계산의 결과는 160, 0, 53789, 0, 65535입니다.두 시험값 유지

요청 bit 0·1이 모두 0이어도 Debug +0x2c가 비영이면 0x52cb4c74–0x52cb4c84에서 Debug +0x2c/+0x31을 지우고 반환합니다. 이 정적 분기는 Motor 활성 플래그를 읽기 전에 끝납니다.

Cortex-A7 기본, Cortex-A7과 A15의 진입 레지스터·NZCV 변경 대조에서 결과가 같았습니다. 서비스 반환값을 대입한 훅은 없었습니다. 명령 주소와 원본 바이트, 지정 객체의 읽기·쓰기 범위를 검사했고, 실행 전후 매핑한 RTOS의 SHA-256이 일치했습니다.

미확인 입력 생산자

이번 시험은 PafMotor 두 필드의 비영값을 미리 넣었습니다. 요청 3에서 두 필드를 읽는 코드의 앞 단계까지 추적하려면, factory +0xc에서 나온 Motor 포인터로 실제 데이터를 전달하는 외부 호출을 찾아야 합니다. Pulse 쪽에서는 0x52cf0254가 상위 객체 +0x48이 가리키는 레코드의 +0x98에 값을 쓰는 후보입니다. 두 호출에서 같은 객체가 전달되는지 확인하는 일이 남았습니다. 앞선 Motor 필드 조사 · 요청 3의 계산과 수치 진입점

렌즈별 저장 보정 레코드, 물리 단위, 바디 모터와 렌즈 모터의 배정은 미확인입니다. 초기화 후속 서비스와 핸들 생성, 카메라 및 렌즈 동작은 실행 범위 밖입니다.

후속 조사에서는 같은 Motor 객체를 가리키는 포인터와 하위 드라이버·PWM의 등록 및 콜백을 구분했습니다. Motor 별칭과 PWM 서비스 경로

재현과 결과 비교

저장소 루트에서 Python과 Unicorn 2.1.4로 실행합니다. 원본 decoded 또는 RTOS의 길이와 SHA-256을 검사합니다. -O 없이 실행하고 출력에는 새 파일을 지정합니다. 재현기 · 검증기 경계 시험 · 공개 결과

python -B verify_af_motor_fields.py decoded.bin --output af-motor-decoded.json --compare analysis/af-motor-field-checks.json
python -B verify_af_motor_fields.py rtos.bin --output af-motor-rtos.json --compare analysis/af-motor-field-checks.json
python -B -m unittest discover -s tests -p test_af_motor_fields.py

두 입력의 결과는 바이트 단위로 일치했습니다. 검증기는 원본 10건 전체와 플래그 대조 전체의 SHA-256을 각각 확인한 뒤 공개 JSON을 만듭니다. 원본 10건의 입력과 관측값을 그대로 유지했습니다.
