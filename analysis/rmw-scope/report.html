기존 실행 기록에서 초기 메모리를 읽는 48바이트를 세 구간·여섯 레코드로 분류했습니다. 그중 0x56493260의 한 워드는 명시한 전제 아래 최종값이 초기 32비트와 무관함을 증명했습니다. 공개 결과 JSON은 원본 35번 결과 전체를 재구성하고 정본 검사를 통과한 뒤 필요한 필드를 추린 것입니다.

실제 초기 기록자는 아직 모릅니다. 이번에 분류한 나머지 44바이트는 이 증명에 포함되지 않으며 기존 56바이트 RMW 허용 목록도 유지합니다. 중간 바이트 저장값은 초기값에 의존합니다. 초기화 완료나 전체 부팅 성공을 입증한 결과가 아닙니다.

1. 세 구간과 기록 순서

주소 범위는 시작 주소를 포함하고 끝 주소를 제외합니다. 기준 주소는 0x56492c80, 레코드 간격은 8바이트입니다. 역할 이름은 할당 흐름과 저장값을 바탕으로 붙인 분석상 해석입니다.

00·A5 초기 RAM 패턴마다 guest store 4,473개를 조사했습니다. 관련 메모리 이벤트의 (stage, PC)가 명령 추적에 정확히 한 번 나타날 때만 순서를 연결합니다. 바이트별 생산 집합을 재계산한 결과는 raw read의 미생산 바이트 수와 일치했습니다. 두 패턴 모두 48바이트의 첫 raw read 앞에는 guest store가 없고, 선택 실행 구간의 끝에는 모두 guest store가 있었습니다. projection.cases에 각 바이트의 첫 읽기·첫 기록과 후속 저장 순서가 있습니다.

최종 두 워드는 이 기록의 마지막 저장값입니다. 호스트가 넣은 00·A5 패턴이나 선택된 실행 구간을 실제 하드웨어의 초기 상태와 동일시할 수는 없습니다. 읽기 로그는 모든 guest read를 담지 않으며, 조건부 미실행 명령이 명령 hook에 나타날 수 있어 실제 쓰기는 별도 메모리 이벤트로 확인합니다.

2. 선택한 4바이트의 최종값

대상은 [0x56493260, 0x56493264)입니다. 원본의 [0x525d8774, 0x525d8790), 7개 A32 명령·28바이트에 대응하는 작성한 의사코드와 수동 모형을 검증했습니다. 의사코드는 제조사 원본 소스나 빌드 대상이 아닙니다.

byte   = (old_word & 0xff) | 3
staged = (old_word & 0xffffff00) | byte
final  = (staged & 3) | ((requested_pages & 0x3fffffff) << 2)
       = (requested_pages << 2, 32-bit) | 3

부호 있는 페이지 수가 2보다 커서 tail 경로에 진입하고, 원본 0x525d8740이 LR에 페이지 수의 하위 30비트를 넣는다는 조건입니다. 대상은 고정된 little-endian 일반 RAM이며, 순차적으로 정상 종료하고 동시 쓰기·비동기 관찰·fault가 없다고 가정합니다. 주소 계산과 전체 레지스터·제어 흐름을 실행한 증명은 아닙니다.

최종식의 반례와 서로 다른 초기 32비트에 따른 최종값 차이의 반례는 Z3에서 모두 UNSAT였습니다. 하위 2비트 설정 또는 상위 30비트 교체를 수동 모형에서 각각 생략하면 SAT 반례가 나옵니다. 원본 firmware를 변경한 실험은 아닙니다.

기존 기록의 남은 페이지 수 0x2f50 → 0x2e94에서 할당량 0xbc를 얻었습니다. 그 값으로 계산한 두 저장값이 기존 기록과 일치합니다. 중간 바이트가 달라지므로 원래 읽기가 불필요하다거나 중간 상태도 초기값과 무관하다고 해석하면 안 됩니다.

3. 전체 기록 검사 후 공개 필드 추리기

검증 CLI는 사용자가 따로 제공한 decoded 이미지와 accepted31 JSON을 읽습니다. 일반 파일 여부·정확한 크기·SHA-256을 확인하고 정해진 크기보다 1바이트까지만 더 읽습니다. RTOS 구간과 모형 블록의 해시를 확인한 뒤 원본 35번의 모든 필드를 메모리에서 재구성합니다.

정본 검사는 dict·list·str·int·bool을 구분하며 float·null을 허용하지 않습니다. 전체 기록을 키 정렬·공백 없는 UTF-8 JSON으로 정규화해 고정된 SHA-256과 비교합니다. bool을 정수로 바꾸거나 공개하지 않는 원본 역어셈블리 필드를 바꿔도 검사에 실패합니다. 이 검사를 통과해야 공개 필드를 추리는 함수가 실행됩니다. 정본 검사는 기존 결과 전체의 일치를 확인하며 실제 초기화 경로의 증거를 추가하지는 않습니다.

명령 바이트·48개 원본 역어셈블리 목록·전체 accepted31 기록은 배포하지 않습니다. 원본 명령 정보는 재구성·정본 검사 중 메모리에서만 사용합니다. 공개 JSON의 historical35는 과거 결과와 환경의 출처이고, current_execution은 이번 CLI·helper 해시와 실제 실행 환경입니다. 둘을 같은 실행 기록으로 취급하지 않습니다. 입력·구간·정본 핀

4. 기본 검사와 입력을 사용한 검사

표준 라이브러리만 사용하는 기본 검사는 -S 환경에서 22개 항목을 통과했습니다. 패키지 변조, 입력 크기·해시, 출력 별칭·기존 파일·hardlink·dangling symlink, 타입 구분과 투영 우회를 검사합니다. -O 실행을 거부하며 Capstone·Z3를 가져오지 않습니다. 기본 검사 기록

두 입력을 제공한 모드는 33개 항목을 통과했습니다. 다른 폴더로 옮긴 CLI의 두 실행 결과가 공개 JSON과 바이트 단위로 일치했고 입력도 보존됐습니다. 전체 기록의 공개 필드와 비공개 필드를 바꾼 10개 변형도 거부했습니다. 입력 기반 검사 기록에도 새 원본 CPU 실행은 없음을 구분해 기록했습니다.

5. 재현 방법

Python 3.12.3에서 확인했습니다. 실제 재구성에는 capstone 5.0.9와 z3-solver 5.3.1.0을 사용했습니다. 런타임 모듈 표시는 각각 5.0.7과 5.3.1입니다. 다른 버전에서 디코딩 표기나 solver 반례가 바뀌면 전체 정본 검사가 실패할 수 있습니다. 기존 결과와 일치하지 않은 실행을 성공으로 완화하지 않습니다.

# firmware-free guards; existing work directory, fresh output
python -S test_verify.py --work-dir /existing/temp-parent --output /path/to/new-guards.json

# two separately supplied, pinned inputs; no native CPU execution
python -m pip install -r requirements-proof.txt
python verify.py /path/to/decoded.bin /path/to/accepted31.json --output /path/to/new-result.json
python test_verify.py --work-dir /existing/temp-parent --decoded /path/to/decoded.bin --accepted31 /path/to/accepted31.json --output /path/to/new-proof-tests.json

명령은 이 패키지 폴더에서 실행하는 예입니다. 다른 위치에서는 스크립트의 절대 경로를 사용하십시오. decoded는 업데이트 파일 자체가 아니며 78,683,892바이트, accepted31은 7,200,103바이트입니다. 정확한 해시는 source.json에 있습니다. accepted31은 별도로 공급해야 하므로 decoded만으로는 이 재검증을 완료할 수 없습니다. 기본 검사는 두 파일 없이 실행합니다.

6. 이전 8바이트 증명과 남은 범위

이전 free 길이 8바이트 증명은 다른 레코드의 두 워드 ((count << 2) | 1, 0)을 다뤘습니다. 이번 증명은 할당 tail의 첫 워드와 flag 값 3을 다룹니다. 두 결과를 합쳐 초기화 완료나 허용 목록 축소의 근거로 사용할 수는 없습니다.

기존 31번 기록에서 관측한 CP15 중단점은 0x525b5a54입니다. 그 뒤의 단계는 호스트가 별도로 선택한 진입점이며, 해당 중단점에서 연속 부팅을 재개한 결과가 아닙니다. 이번 패키지는 원본 CPU 명령을 새로 실행하거나 CP15·MPIDR 값을 대신 넣지 않습니다.

실제 초기 writer, 나머지 44바이트의 임의 초기값 의존성, MMIO·동시 접근·fault·전체 부팅 동작은 미확정입니다. 카메라 실행·빌드·플래시는 수행하지 않았습니다.
