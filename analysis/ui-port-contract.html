UI 이식 설계: 색공간 선택 화면으로 세 기종 비교하기

K-3 Mark III의 메뉴 화면을 K-3 II와 Q7에 옮길 수 있는지 알아보는 주제입니다. 옮긴 화면은 아직 하나도 없습니다. 세 기종이 모두 가진 색공간 선택 화면 하나를 골라, 화면이 열리고 값이 기록되기까지를 기종별로 비교해 설계의 출발점을 만들었습니다.

이 문서에서

  3. 배경 지식
  4. 화면 하나를 옮기려면 맞춰야 하는 다섯 접점
  5. 세 기종에 공통으로 둘 동작과 기종별로 지킬 차이

핵심 요약

  • 이 주제는 “화면 하나를 다른 기종으로 옮기려면 무엇을 맞춰야 하는가”에 답합니다. 첫 대상은 색공간(sRGB·AdobeRGB) 선택 화면입니다. 세 기종의 공식 설명서에 모두 있고 선택지가 둘뿐입니다.
  • 세 기종은 같은 화면을 다르게 처리합니다. K-3 Mark III와 K-3 II는 고르는 동안 임시값만 바꾸고 확정할 때 기록합니다. Q7은 포커스를 옮기는 즉시 기록하고, 취소하면 화면을 열 때 저장해 둔 값으로 되돌립니다.
  • K-3 Mark III 쪽은 화면의 선택·확정·취소, 방향 입력과 포커스, 아이콘의 저장 형식과 복사를 원본 코드 실행으로 확인했습니다. 화면 객체와 입력 이벤트는 시험용으로 만들어 넣은 것입니다.
  • 이식은 시작하지 않았습니다. 물리 버튼에서 화면 이벤트까지, 글자와 포커스 표시의 최종 합성과 LCD, 설정의 영구 저장은 세 기종 모두 확인하지 못했습니다. 다음 단계는 카메라가 아니라 PC에서 화면을 그려 보는 일입니다.

한눈에 보기

색공간 화면의 한 살이는 열기 → 포커스 이동 → 확정 또는 취소 → 기록 뒤의 일로 나눌 수 있습니다. 세 기종은 설정값을 기록하는 시점이 서로 다릅니다.

세 기종이 모두 제공하는 설정이고 값이 둘뿐입니다. 설정의 뜻은 같게 두고, 화면과 입력만 기종별로 나눠 확인할 수 있습니다.

정정

이전 판과 근거 JSON은 Q7의 메뉴 위치를 ‘E3’이라고 적었습니다. 공식 설명서 20쪽의 표기는 C3(커스텀 설정 3)입니다. 설명서 PDF에서 글자를 뽑으면 메뉴 아이콘 ‘C’가 ‘E’로 나오는데, 같은 현상이 K-3 II 설명서 84쪽에도 있습니다. Q7 저장소의 문서에 나오는 ‘E3’은 이 C3 메뉴를 가리킵니다.

후보에서 뺀 항목: RAW 파일 형식

대응표 1쪽은 두 K-3 기종의 RAW 파일 형식(PEF/DNG) 항목도 서로 대응시킵니다. 그러나 Q7의 RAW 저장 형식은 DNG 하나여서(Q7 설명서 78쪽) 같은 PEF/DNG 선택 화면을 확인할 수 없습니다. JPEG·RAW·RAW+를 고르는 기록 형식 선택은 별개의 항목입니다. K-3 II의 RAW 형식 메뉴는 K-3 II 저장소에서 따로 분석했습니다.

배경 지식

이 주제의 문서를 읽는 데 필요한 개념만 짧게 정리합니다.

색공간 설정
카메라가 만드는 이미지에 쓸 색공간을 sRGB와 AdobeRGB 중에서 고르는 설정입니다. 세 기종 모두 AdobeRGB를 고르면 파일 이름의 앞머리가 IMGP에서 _IMG로 바뀝니다(K-3 Mark III 설명서 113쪽, K-3 II 84쪽, Q7 66쪽). K-3 Mark III 안에서 이 값이 색 처리에 전달되는 과정은 JPEG·ISP와 색 재현 경로에 있습니다.
위젯과 포커스
위젯은 화면을 이루는 부품(행, 글자, 아이콘)이고, 포커스는 지금 고르고 있는 부품을 가리키는 표시입니다.
확정값과 보류값
확정값은 설정 메모리에 들어 있는 값이고, 보류값은 화면에서 고르는 중이라 아직 반영되지 않은 값입니다. 기종에 따라 보류값을 따로 두기도 하고(K-3 Mark III, K-3 II), 고르는 즉시 설정에 써 버리기도 합니다(Q7).
setter와 observer
setter는 설정값을 기록하는 함수입니다. observer는 기록 뒤에 불려 사본을 맞추거나 다른 부분에 변경을 알리는 함수입니다.
설정 RAM과 영구 저장
이 주제에서 ‘기록’은 모두 실행 중 메모리(RAM)에 쓰는 것입니다. 전원을 꺼도 남는 저장 장치에 쓰는 단계는 따로 있으며 세 기종 모두 실물로 확인하지 않았습니다.
화면 자원
아이콘, 문자열, 글꼴처럼 화면을 그리는 데 쓰는 데이터입니다. K-3 Mark III의 아이콘은 32비트 픽셀을 그대로 이어 붙인 ICONBIN에 있습니다. Q7은 픽셀마다 팔레트 번호 1바이트를 쓰는 다른 방식입니다.
ABI와 렌더러
ABI는 함수 호출 방법과 객체의 메모리 배치 같은 기계어 수준의 약속이고, 렌더러는 화면 버퍼에 픽셀을 쓰는 코드입니다. 세 기종은 이 둘이 모두 다릅니다. 그래서 화면 코드를 그대로 복사하는 것이 아니라, 같은 동작을 대상 기종의 방식으로 다시 만드는 쪽을 전제로 합니다.

갱신

이전 판은 Q7의 색공간 화면에서 입력·상태·표시가 이어지는 부분을 ‘미확인’으로 적었습니다. 그 뒤 Q7 저장소에서 이 화면을 직접 추적해 즉시 기록과 취소 복원을 확인했습니다. 위 표의 Q7 칸은 그 결과와 세 기종 연구 본부의 요약을 따릅니다. 근거 파일 ui-port-contract.json은 설계를 처음 정리한 때의 상태 그대로이며 고치지 않았습니다.

세 기종에 공통으로 둘 동작과 기종별로 지킬 차이

이식할 화면의 뼈대는 동작 넷(열기·선택·확정·취소)과 값 둘(확정값·보류값)로 잡았습니다. 이것은 설계안입니다. 원본 카메라가 모두 이렇게 동작한다는 관측이 아니며, Q7의 원본은 이 뼈대와 다릅니다.

  1. 열기 대상 기종의 현재값을 읽어 확정값과 보류값을 초기화합니다.
  2. 선택 보류값과 화면만 바꿉니다.
  3. 확정 같은 값이어도 대상 기종의 setter와 콜백 조건을 그대로 따릅니다. RAM 기록과 섹터 쓰기 요청은 따로 확인합니다.
  4. 취소 대상 기종의 닫기와 통지 동작을 그대로 따릅니다. 화면을 다시 열면 대상 설정의 현재값을 읽습니다.

그리기는 대상 기종의 문자 경로로 두 값과 포커스만 표시합니다. 자원, 출력 형식, 사각형, stride는 기종별 어댑터에서 다룹니다. 버튼 대응, 이벤트 번호, 설정값, 자원 형식은 기종마다 확인한 값을 씁니다.

주의

‘선택은 보류값만 바꾼다’는 규칙은 Q7의 원본과 맞지 않습니다. Q7 저장소의 결론은, Q7에 맞춘 어댑터라면 열 때 백업, 포커스 이동 때 즉시 기록, 확정 때 유지, 취소 때 복원으로 모델을 잡아야 한다는 것입니다. 이 차이를 어느 쪽으로 맞출지는 화면을 구현하기 전에 정해야 합니다.

‘확인’과 ‘모델’이 함께 붙은 항목은 원본 코드를 실행했지만 화면 객체나 입력을 시험이 만들어 넣었다는 뜻입니다. 배지의 뜻은 검증 수준 읽는 법에 있습니다.

남은 실험 세 가지

  1. 입력 연결 두 K-3 기종에서 물리 입력이 색공간 위젯의 논리 이벤트로 이어지는 경로를 확인합니다. Q7은 색공간 화면을 이미 확인한 입력·설정 경로에 이어 붙여 검증합니다.
  2. 상태 재생 양방향 변경 후 확정, 변경 후 취소, 같은 값 확정에서 setter 호출, RAM 기록, 콜백과 하위 요청, 섹터 쓰기 요청을 구분해 기록합니다. 창을 닫고 다시 열 때의 값과 재부팅 뒤의 값은 따로 확인합니다.
  3. 그리기 재생 그 화면의 무효화부터 실제 문자·포커스 렌더러를 거쳐 출력 버퍼까지 추적합니다. 기종별 출력 형식과 stride로 PC의 합성 버퍼에 그려, 바뀌어야 하는 영역과 그 양옆 바이트를 대조합니다. 처음 시험에 쓰는 표식은 새로 그립니다.

세 실험의 중심은 PC에서 하는 추적과 재생입니다. 재부팅 뒤의 값처럼 실물이 있어야 하는 확인은 그 뒤의 일입니다. 세 기종 연구 본부의 UI 목표도 자원 형식 → 렌더러·메뉴·입력 ABI → PC 화면·입력 모형 → 대상 기종 구현과 실기의 순서로 관문을 두고 있습니다. 카메라에 넣는 단계는 맨 마지막이며 아직 시작하지 않았습니다.

주의

이 문서는 이미 있는 분석 결과를 비교해 만든 화면 설계입니다. 이 문서를 쓰면서 새로 펌웨어를 실행하거나 장치에 이식하지 않았습니다. 기종 사이에 이벤트 번호, 값의 번호, 객체 배치, 픽셀 형식이 같다고 가정하지 않습니다.

    고르는 동안에는 보류 선택만 바뀌고, 확정할 때만 설정 함수로 넘어갑니다. 16개 사례로 확인했습니다.

  • 2단계

    색공간 화면: 방향 입력·포커스

    방향 입력은 포커스를 어떻게 옮기는가?

    이벤트 네 가지 중 둘은 끝에서 순환하고 둘은 멈춥니다. 포커스 변경은 콜백으로 메뉴에 전달됩니다. 50개 사례입니다.

  • 3단계

    ICONBIN 아이콘 자원

    아이콘은 어디에 어떤 모양으로 있고 어떻게 화면 버퍼로 가는가?

    목록은 RTOS에, 32비트 픽셀은 ICONBIN에 있습니다. 아이콘 하나를 바꿨다가 되돌리는 시험도 했습니다.
