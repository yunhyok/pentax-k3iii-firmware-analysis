카메라 내부 색 처리 · 설정의 효과

모드·채도·대비를 하나씩 바꾸면 행렬과 감마 중 무엇이 달라지는가

색 설정 손잡이가 여러 개일 때 어느 손잡이가 어느 설정값을 움직이는지 알면, Lightroom 프로파일에서 무엇을 행렬로 옮기고 무엇을 곡선으로 옮길지 정할 수 있습니다. 네 모드에서 채도와 대비를 하나씩 바꿔 원본 코드의 출력을 비교했습니다.

이 문서에서

  1. 배경: 손잡이 세 개와 설정값 두 가지
  2. 실험 방법: 16조건에서 원본 함수 두 개를 따로 실행
  3. 결과: 채도는 행렬을, 대비는 일반 감마를 바꿉니다
  4. 원본 코드에서 확인한 범위
  5. Adobe 프로파일의 구조와 닮은 점, 그리고 세 기종의 다음 시험
  6. 한계와 남은 과제
  7. 재현 방법
  8. 근거 파일과 참고 자료

핵심 요약

  • Natural, Portrait, Bright, Reversal Film 네 모드에서 채도 두 값과 대비 두 값을 조합한 16조건으로 원본 함수 두 개를 실행했습니다. 하나는 색 행렬을 준비하는 함수이고 다른 하나는 감마 곡선을 고르고 만드는 함수입니다.
  • 채도를 바꾸면 행렬만 달라졌고 감마 곡선은 그대로였습니다. 대비를 바꾸면 일반 감마 곡선만 달라졌고 행렬은 그대로였습니다.
  • 같은 제어값에서 Natural, Portrait, Bright는 감마 곡선이 같고 행렬이 달랐습니다. Reversal Film은 별도 생성기를 써서 곡선도 달랐고 대비를 바꿔도 곡선이 변하지 않았습니다.
  • 비교한 것은 설정 계수와 곡선입니다. 이 차이가 실제 사진의 픽셀에 어떻게 나타나는지, 카메라 메뉴가 같은 값을 만드는지는 확인하지 않았습니다.

확인 원본 코드 실행으로 확인

  • 16조건의 행렬 계수와 감마 곡선, 조건 사이의 차이
  • 행렬 준비 16회의 출력이 앞선 검증의 해시와 일치
  • 일반 생성기 12회, Reversal 생성기 4회, 재호출 16회의 곡선 재사용

모델 시험 조건으로 정한 것

  • 직접 만든 파라미터 블록. 두 함수를 따로 실행
  • 색공간 파라미터, gain, 키, 감마 비율은 한 값으로 고정
  • 모드에 맞춰 감마 분기 플래그를 직접 설정

미확인 확인하지 않은 것

  • 카메라 메뉴가 이 합성 블록과 같은 값을 만드는지
  • 다른 노출·제어값에서도 같은 차이가 나는지
  • 실기에서의 톤 적용, 픽셀 처리 순서, JPEG 색

배경: 손잡이 세 개와 설정값 두 가지

카메라의 Custom Image(이 문서에서는 컬러모드)는 모드를 고른 뒤 채도, 대비 같은 값을 더 조절할 수 있습니다. 펌웨어는 이 설정으로 여러 설정값을 계산하는데 그 가운데 색을 정하는 것이 색 행렬이고 밝기 분포를 정하는 것이 감마 곡선입니다. 두 계산의 식은 색 행렬·감마·톤 설정값을 만드는 계산식에 있습니다.

식을 아는 것과 별개로, 손잡이 하나가 두 설정값 가운데 어느 쪽을 움직이는지는 직접 돌려 봐야 분명해집니다. 그래서 다른 값을 고정하고 한 번에 한 값만 바꿔 출력을 비교했습니다. 이 구분은 Lightroom 프로파일을 만들 때 쓸모가 있습니다. Adobe의 프로파일도 색 변환(행렬과 표)과 톤 곡선을 따로 담기 때문입니다.

쉽게 말하면

손잡이 세 개(모드, 채도, 대비)와 계기 두 개(행렬, 감마)가 있는 기계에서, 손잡이를 하나씩 돌려 어느 계기의 바늘이 움직이는지 적은 표입니다. 다만 기계 전체를 켠 것이 아니라 계기 두 개를 떼어 따로 시험했습니다.

실험 방법: 16조건에서 원본 함수 두 개를 따로 실행

네 모드 × 채도 2 × 대비 2의 합성 설정을 만들어, 색 행렬 준비 함수와 감마 선택·생성 함수에 각각 넣고 출력을 기록했습니다.

바꾼 값은 세 가지입니다. 모드는 Natural, Portrait, Bright, Reversal Film, 채도 인덱스는 4와 5, 대비 칸의 값은 4와 6입니다. 값을 하나만 바꾼 비교에서는 다른 값을 4에 두었고 모드끼리 비교할 때는 채도와 대비를 모두 4로 고정했습니다.

  • 네 모드는 공통 행렬과 채도 행렬 표를 함께 씁니다. Natural의 모드 행렬은 Q13 단위행렬입니다.
  • 실행하기 전에 원본 바이트에서 모드 번호의 대응과 자원 포인터 표 세 행의 디스크립터 포인터를 확인했습니다.
  • 대비 칸의 값 4는 가운데 값입니다. 이 값으로 만든 Natural 곡선이, 생성기를 제어값 0으로 직접 실행한 앞선 검증 결과와 같았습니다.

결과: 채도는 행렬을, 대비는 일반 감마를 바꿉니다

채도와 대비는 서로 다른 설정값을 움직였습니다. 모드를 바꾸면 행렬이 항상 달라졌고 감마는 Reversal Film으로 바꿀 때만 달라졌습니다.

가장 큰 차는 각 출력의 정수 눈금 그대로입니다. 행렬 계수는 −2048~2047 범위의 12비트 값이고 감마 곡선은 상한이 16384인 값입니다.

  • 채도 — 채도 인덱스가 바뀌면 채도 행렬이 바뀌므로 합성된 색 행렬이 달라집니다. 감마 함수는 같은 곡선을 냈습니다.
  • 대비 — 대비는 일반 감마 생성기의 제어값으로 들어가 곡선을 바꿉니다. 행렬 준비 함수의 출력은 대비와 무관했습니다.
  • 모드 — Natural, Portrait, Bright는 모드 행렬이 달라 행렬 계수가 모두 달랐지만 같은 일반 생성기와 같은 제어값을 써서 곡선이 같았습니다.
  • Reversal Film — 별도 감마 생성기를 불렀습니다. 그래서 Natural과 곡선이 달랐고 이번 대비 변경에는 곡선이 변하지 않았습니다. 분기 선택 함수가 Reversal 분기에서 가운데 기준 제어값 네 개를 0으로 놓는다는 코드 분석(감마 곡선 절)과 맞는 결과입니다.
주의

이 비교의 출력은 설정 계수와 곡선입니다. 실기에서 톤이 어떻게 적용되는지, 픽셀이 어떤 순서로 처리되는지, JPEG의 색이 어떻게 달라지는지는 따로 확인해야 합니다.

Adobe 프로파일의 구조와 닮은 점, 그리고 세 기종의 다음 시험

Adobe의 Camera Natural과 Camera Portrait 프로파일도 톤 곡선은 같고 행렬 하나가 다릅니다. 펌웨어의 관측과 모양은 닮았지만 두 행렬이 같은 변환이라는 증거는 아닙니다.

Natural과 Portrait를 두 곳에서 비교
비교 대상같은 것다른 것상태
펌웨어의 설정 출력감마 곡선(같은 대비에서)준비된 색 행렬확인 합성 설정으로 실행
Adobe DCP 파일ColorMatrix1·2, LookTable, 톤 곡선ForwardMatrix1·2확인 설치 파일의 태그 대조

DNG 규격에서 ColorMatrix는 XYZ를 기준 카메라 색공간으로 보내는 행렬이고 ForwardMatrix는 화이트밸런스를 적용한 카메라 색을 XYZ D50으로 보내는 행렬입니다. 이번에 비교한 펌웨어 행렬이 어떤 원색과 전달함수의 색을 받는지는 확인하지 못했습니다. 그래서 펌웨어 행렬을 이 두 태그 가운데 어느 것과도 곧바로 대응시킬 수 없습니다. Adobe 태그의 대조는 DCP 생성·검증 개요와 컬러모드 자원과 Lightroom에 있습니다.

기종별로 프로파일 시험에 쓸 수 있는 근거

기종프로파일 시험에 쓸 근거
K-3 Mark III같은 합성 대비에서 Natural과 Portrait는 감마 곡선이 같았고 행렬은 달랐습니다. 같은 RAW를 카메라에서 모드별로 현상하면 실제 출력의 차이를 확인할 수 있습니다. (설정 출력 비교)
K-3 II이 기종에서는 Reversal Film이 selector 6에서 별도 톤 생성기를 씁니다. Natural로 찍은 표본 #1376은 기존 A·D65 보정을 고정하고 톤 후보를 비교하는 첫 자료이고 이 표본으로 한 Lightroom 비교가 실제 TIFF 6개 비교와 톤 곡선 비교에 있습니다. (K-3 II의 톤 경로 · #1376 색차 절차)
Q7색 행렬 설정과 Cross Process의 채널별 감마 합성을 확인한 근거가 있습니다. 따로 추적한 77워드 LUT는 센서 통계용이고 JPEG에 적용되는 곡선은 확정하지 못했습니다. (Q7의 색 연산 · Q7의 감마 경계)

K-3 II와 Q7의 링크는 이 비교를 쓴 시점의 커밋에 고정되어 있습니다.

모드에 따라 카메라가 DNG에 기록하는 보정값이 달라지는지는 이 실험에서 시험하지 않았습니다. 설정의 차이가 픽셀에 어떻게 나타나는지 보려면, 같은 RAW에서 화이트밸런스·노출·출력 색공간을 고정하고 채도와 대비를 하나씩 바꾼 카메라 출력이 필요합니다. 기종별 DNG 보정과 내장 JPEG 표본은 시험용 RAW 준비에 있습니다.

한계와 남은 과제

  • 모델 입력 — 파라미터 블록은 직접 만든 것입니다. 모드 번호와 자원 디스크립터는 원본 바이트로 확인했지만 메뉴에서 이 블록을 만드는 상위 코드는 실행하지 않았습니다.
  • 모델 따로 실행 — 두 함수를 이어진 영상 처리 흐름 안에서 실행한 것이 아닙니다. 외부 콜백도 실행하지 않았습니다.
  • 미확인 값의 범위 — 채도는 4와 5, 대비는 4와 6만 시험했습니다. 다른 값과 다른 모드에서도 같은 구분이 성립하는지는 모릅니다.
  • 미확인 픽셀과 사진 — 픽셀 처리, 카메라 하드웨어, Lightroom은 실행하지 않았습니다. RAW나 DCP도 읽지 않았습니다. K-3 Mark III에서 Lightroom 출력과 카메라 JPEG의 색차는 아직 재지 않았습니다.

재현 방법

Python 3.11 이상과 Unicorn 2.1.4가 필요합니다. RAW, DCP, Lightroom은 필요 없습니다.

입력
K-3 Mark III 2.20의 전체 해제 BIN. 78,683,892바이트, SHA-256 7ff301d585ef7adcd620a15575faa39b4227cc5a27eaa8d754efe50f667a30f9. 도구가 크기와 해시를 확인합니다.
기준 JSON
공개 JSON 네 개(color-resources.json, color-math-checks.json, gamma-tone-checks.json, lightroom-bridge.json)의 SHA-256을 줄바꿈을 LF로 맞춘 뒤 확인합니다.
출력
결과 경로는 새 파일이어야 합니다. 코드 구간, 출력 해시, 달라진 항의 수만 기록합니다.
