K-3 III 텍스트 viewport의 생산 경로

부모와 자식의 클립으로 계산한 StringView의 +0x50 사각형이 텍스트 설정 +0x14로 직접 복사됩니다. 원본 RTOS에서 이 설정이 비회전 글자 전송에 전달되는 경로를 확인했습니다.

viewport와 텍스트 설정

V는 StringView이며, 생성자는 V+0x114에 내부 객체 N=V+0x11c의 포인터를 씁니다. 따라서 객체의 설정 주소 V+0x188과 내부 객체의 N+0x6c가 같습니다. 오프셋 단위는 바이트입니다. 원본 구간과 명령 주소

설정 생산자와 비회전 호출
데이터 이동원본 주소관측한 계약
V+0x50 → N+0x2c0x52c02590일반 스냅샷에 16바이트를 복사합니다.
V+0x50 → 임시 config+0x140x52beea24, 0x52beea54–0x52beea5cviewport의 직접 복사입니다. 원본 주소는 StringView의 V+0x50입니다.
정렬한 텍스트 사각형 → config+40x52bee9fc → 0x52bee61c, 0x52beea4cV+0x30 절대 좌표와 텍스트 측정 크기로 만든 사각형입니다.
임시 config → V+0x188[0x52beebec,0x52beec40)48+12+2+1=63바이트를 복사합니다. 마지막 쓰기는 0x52beec3c입니다. config+0x3f는 이 복사 범위 밖입니다.
surface → N+0x6c → 스택 config0x52bedb78, [0x52bedba8,0x52bedbc8)선택된 그리기 분기에서 첫 워드에 표면 포인터를 쓰고 64바이트를 스택으로 복사합니다. 마지막 쓰기는 0x52bedbc4입니다.
스택 config → 비회전 전송0x52bedbd0 → 0x528c2e30, 0x528c2fe0 → 0x528c24e4디스패처가 surface+2에서 타입 5를 확인하고 config+0x28의 회전값 0을 선택합니다.

두 사각형은 config+4..+35 안에 있어 두 복사에 모두 포함됩니다. 별도 정적 대조에서는 StringView 생성자의 표 리터럴 0x52bee40c와 내부 객체 표 리터럴 0x52bee414를 확인했습니다. 내부 표 0x5386fec0의 +0x14 슬롯은 0x52bedb40을 가리킵니다. A32 정렬 워드의 직접 분기 검사에서는 전송 함수로 향하는 0x528c2fe0 한 곳이 일치했습니다. 실제 호출 순서와 메뉴 도달성은 추가 실행 검증이 필요합니다. 정본 관측과 추가 정적 근거

부모 클립과 폭 80

부모가 있는 분기의 0x52c003f0은 부모의 절대 원점 P+0x30과 자식 로컬 원점 V+0x20을 더합니다. 자식의 로컬 클립 V+0x40을 새 절대 원점으로 옮긴 뒤 P+0x50의 클립과 교차시킵니다. 0x52c0053c–0x52c00584는 부호 있게 시작점의 큰 값과 끝점의 작은 값을 고르고, 끝점을 시작점 이상으로 제한합니다. 0x52c00588에서 결과를 V+0x50에 저장하는 함수를 호출합니다. geometry 원본 핀

기존 행 재현에서 부모의 절대 사각형과 클립 [10,12,180,60]은 호스트가 넣었습니다. 자식의 로컬 사각형 [100,10,580,40]은 원본 행 생성자에서 나왔습니다. 자식의 절대 원점은 (110,22)이며, viewport 폭 80은 부모 오른쪽 끝 190에서 110을 뺀 값입니다. 별도로 측정한 텍스트 크기는 76×40이며 config의 텍스트 사각형은 [110,22,76,40]입니다. 중앙 정렬 경로는 두 크기를 각각 절반으로 줄인 뒤 뺍니다. 기존 문자열 측정·전송 · 세 산술 사례

RAM 표면과 주소 단위

기존 실험의 RAM 표면은 호스트가 만든 256×144개의 32비트 워드입니다. 원본 전송은 0x531128a4에서 surface+8의 RAM 포인터를, 0x528c25bc에서 surface+0x18의 부호 없는 16비트 행 간격을 읽습니다. 대상 바이트 오프셋은 4 × (Y × pitchWords + X)입니다. 배경 시작 워드는 높이 0 검사 전에 읽습니다. 이 동작의 관측 범위는 기존 RAM fixture와 분석한 분기입니다. 이전 경계 접촉 사례

기존 7개 사례는 각각 준비에 모델 호출 72개를 사용했고 최종 전송에 모델 호출은 없었습니다. 기준 사례는 두 사각형을 그대로 두었고, 나머지 여섯 사례에서는 복사된 config의 +4..+35에 두 사각형을 공급했습니다. 기준에서도 부모와 표면은 호스트가 설정했습니다. 최상위 viewport와 실제 표면의 생산자, LCD 동작은 미확인입니다. 7개 역사적 관측

정적 검증 재현

Python과 Capstone 5.0.7에서 고정 decoded 입력을 사용합니다. 도구는 원본 RTOS 25구간과 명령 계약 73개, 별도 검토 5구간, 두 공개 역사 기록을 대조합니다. 세 산술 예시는 작은 정수 좌표의 수동 계산입니다. 정본의 모든 필드와 추가 확인을 포함한 전체 JSON이 정확히 일치할 때만 새 파일을 씁니다. CPU 에뮬레이터와 기존 7개 사례는 실행하지 않습니다.

python -B tools/verify_ui_viewport_producers.py decoded.bin --output viewport-replay.json
python -B -m unittest discover -s tests -p test_ui_viewport_producers.py
