글자 viewport가 만들어져 전송 함수에 닿는 경로

sRGB 글자를 시험 표면에 찍는 원본 코드는 이미 실행해 봤습니다. 다만 그때 글자를 잘라 낼 사각형은 시험이 넣어 준 값이었습니다. 이 문서는 그 사각형이 펌웨어 안에서 어디서 계산되어 어떤 복사를 거쳐 전송 함수에 닿는지 코드를 읽어 이었습니다.

이 문서에서

  1. 배경: 글자를 어디까지 그릴지 정하는 사각형
  2. viewport가 텍스트 설정을 거쳐 전송 함수에 닿기까지
  3. viewport 폭 80은 부모 클립에서 나옵니다
  4. 전송 함수가 RAM 표면의 주소를 계산하는 방식
  5. 한계와 남은 과제
  6. 재현 방법
  7. 근거 파일과 참고 자료

핵심 요약

  • 글자 객체(StringView)의 viewport는 부모 화면 요소의 클립과 자기 영역을 교차해 만든 사각형입니다. 이 값은 텍스트 설정에 그대로 복사됩니다. 그리기 직전에 스택으로 한 번 더 옮겨져 비회전 글자 전송 함수에 들어갑니다.
  • 이전 시험에서 나온 viewport 폭 80은 부모 오른쪽 끝(190)에서 글자 객체의 시작 X(110)를 뺀 값입니다. 시험용 RAM 표면의 폭 256과는 관계가 없습니다.
  • 이번 결과는 모두 코드를 읽어 얻은 정적 분석입니다. 원본 코드는 새로 실행하지 않았습니다. 세 가지 좌표 예시도 작은 정수로 손 계산한 값입니다.
  • 맨 위 부모의 클립을 누가 만드는지, 실제 메뉴에서 이 경로가 어떤 순서로 불리는지, 실제 표면과 LCD는 확인하지 못했습니다. 카메라에서 실행한 실험은 없습니다.

정적 분석 코드를 읽어 판단

  • 부모·자식 클립을 교차해 viewport에 저장하는 함수
  • viewport가 텍스트 설정 +0x14로 직접 복사되는 명령
  • 설정 63바이트 저장과 그리기 때의 64바이트 스택 복사
  • 표면 타입 5·회전 0에서 비회전 전송으로 가는 분기

확인 이전 실행 기록

  • 비회전 전송 함수가 viewport와 글자 사각형의 교차 영역에만 쓰는 동작(일곱 좌표 시험)
  • 이 문서는 그 기록을 다시 실행하지 않고 해시로만 대조했습니다

모델 시험 조건으로 정한 것

  • 이전 시험의 부모 사각형·클립 [10,12,180,60]
  • 256×144 워드 RAM 표면과 그 주소
  • 좌표 예시 세 개(손 계산)

미확인 확인하지 않은 것

  • 최상위 부모의 클립과 실제 표면을 만드는 코드
  • 실제 메뉴에서의 호출 순서와 도달 여부
  • 표면 높이·LCD 경계, 실제 LCD 출력

배경: 글자를 어디까지 그릴지 정하는 사각형

화면 요소는 부모 안에 자식이 들어가는 나무 구조입니다. 자식은 부모 밖으로 그려지면 안 되므로 그리기 전에 자기 영역을 부모의 클립과 겹쳐 봅니다. 겹친 부분이 viewport이며 전송 함수는 이 안에만 픽셀을 씁니다(Windows GDI의 클리핑 설명과 같은 개념).

K-3 Mark III에서 메뉴 행의 글자는 StringView 객체가 맡습니다. 아래에서 V는 StringView, P는 부모, N은 V 안의 내부 객체(V+0x11c)입니다. 생성자가 V+0x114에 N의 주소를 적어 두므로 V+0x188과 N+0x6c는 같은 메모리입니다. 오프셋은 바이트 단위 16진수이고 사각형은 32비트 정수 네 개(X, Y, 폭, 높이)로 적습니다.

viewport가 텍스트 설정을 거쳐 전송 함수에 닿기까지

viewport(V+0x50)는 임시 텍스트 설정의 +0x14로 직접 복사됩니다. 설정은 V+0x188에 저장되었다가 그리기 때 스택을 거쳐 비회전 전송 함수로 갑니다.

viewport와 글자 사각형은 설정의 +4~+35에 있어 63바이트 저장 복사와 64바이트 스택 복사에 모두 들어갑니다. 설정 +0x3f는 저장 복사 범위 밖이지만 두 사각형과는 관계가 없습니다.

viewport 폭 80은 부모 클립에서 나옵니다

글자 객체는 부모 오른쪽 끝을 넘어 길게 놓여 있었습니다. 부모 클립과 겹친 폭 80만 viewport로 남았습니다.

부모가 있는 분기에서 클립 계산 함수(0x52c003f0)는 세 단계를 거칩니다.

  1. 절대 원점 부모의 절대 원점 P+0x30과 자식의 로컬 원점 V+0x20을 더해 V+0x30을 만듭니다. 크기는 V+0x20에서 그대로 가져옵니다.
  2. 교차 자식의 로컬 클립 V+0x40을 새 원점으로 옮긴 뒤 부모 클립 P+0x50과 겹칩니다. 0x52c0053c–0x52c00584가 부호 있는 비교로 시작점은 큰 값, 끝점은 작은 값을 고릅니다. 끝점이 시작점보다 작아지지 않게 막는 처리도 있습니다.
  3. 저장 0x52c00588에서 사각형 저장 함수(0x530fa084)를 불러 결과를 V+0x50에 씁니다.

이전 시험에서 부모의 절대 사각형과 클립 [10,12,180,60]은 호스트가 넣었습니다. 자식의 로컬 사각형 [100,10,580,40]은 원본 행 생성자(0x52c10660)에서 나왔습니다. 측정한 글자 크기는 76×40이었고 설정의 글자 사각형은 [110,22,76,40]입니다. 가운데 정렬 경로는 상자 크기와 글자 크기를 각각 절반으로 줄인 뒤 뺍니다.

이 단계의 원본 연결
  • 행 0x52c10660이 타입 0x11을 x 100, y 10, 폭 580, 높이 40으로 만듭니다. 팩토리 슬롯 17 → 0x52c03700 → 0x52bee278(StringView 생성자) → 0x52c00a3c(뷰 생성자)로 이어집니다.
  • 0x52c00b7c가 V+0x40을 0, 0, 폭, 높이로 둡니다. 0x52c01148이 부모를 V+4에 저장합니다.
  • 최상위 부모의 +0x50을 쓰는 코드는 찾지 못했습니다. 이전 재현은 행의 +0x30과 +0x50을 호스트에서 넣었습니다.
  • 사각형 접근 함수: 끝점 0x530fa084, 사각형 0x530fa174, 점 0x530f9dc4, 크기 0x530fa75c. 원본 구간 해시는 ui-viewport-sources.json에 있습니다.

전송 함수가 RAM 표면의 주소를 계산하는 방식

전송 함수는 표면 기술자에서 RAM 시작 주소와 워드 단위 행 간격을 읽습니다. 바이트 오프셋은 4 × (Y × 행 간격 + X)입니다.

이전 시험의 RAM 표면은 호스트가 만든 256×144개의 32비트 워드입니다. 카메라에서 찾아낸 표면이 아닙니다. 원본 전송은 0x531128a4에서 surface+8의 RAM 포인터를, 0x528c25bc에서 surface+0x18의 부호 없는 16비트 행 간격을 읽습니다. 배경으로 쓰는 시작 워드는 높이 0 검사보다 먼저 읽습니다. 높이는 0x528c267c에서 하위 16비트로, 폭은 0x528c2688에서 uxth로 좁혀집니다.

한계와 남은 과제

이전에 실행한 일곱 사례(7개 기록)는 각각 준비 단계에서 모델 호출 72개를 썼고 최종 전송에는 모델 호출이 없었습니다. 기준 사례는 두 사각형을 그대로 두었습니다. 나머지 여섯 사례는 복사된 설정의 +4~+35 바이트에 두 사각형을 넣었습니다. 기준 사례에서도 부모와 표면은 호스트가 정했습니다. 이 문서는 일곱 사례를 다시 실행하지 않았습니다.

  • 연결 방식: 코드 사이의 연결은 정적 분석입니다. 이전 실행 기록은 별도 근거로만 대조했습니다.
  • 최상위 생산자: UI 스케줄러의 최상위 viewport와 표면 할당 코드는 찾지 못했습니다.
  • 복사 길이: 저장 복사 63바이트와 그리기 복사 64바이트는 길이가 다릅니다. 끝까지 따라간 것은 두 사각형 필드뿐입니다.
  • 실제 화면: 메뉴에서의 도달 여부, viewport와 실제 표면이 같은지, LCD 출력, 부팅 전체·MMIO는 확인하지 않았습니다.
  • 변경 없음: 원본 레지스터 값, 분기, 명령 바이트, 서비스 반환값은 바꾸지 않았습니다.

재현 방법

Python과 Capstone 5.0.7로 고정된 decoded.bin을 읽습니다. 도구는 원본 RTOS 25구간, 명령 73개, 별도 검토 5구간, 공개된 이전 기록 두 개(colorspace-clip.json, colorspace-text.json)를 대조합니다. 정본의 모든 필드와 추가 확인을 담은 JSON 전체가 정확히 같을 때만 새 파일을 씁니다. CPU 에뮬레이터는 쓰지 않으며 이전 일곱 사례도 실행하지 않습니다.

python -B tools/verify_ui_viewport_producers.py decoded.bin --output viewport-replay.json
python -B -m unittest discover -s tests -p test_ui_viewport_producers.py
