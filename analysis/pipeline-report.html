이번 분석에서 연결한 범위

PENTAX K-3 Mark III v2.20의 RAW 현상 경로를 하위 JPEG 드라이버와 R2y 레지스터 설정까지 추적했다. 컬러모드가 만든 행렬·곡선 설정이 하드웨어에 전달되는 위치와 JPEG 양자화 계산을 확인했다. 실제 픽셀을 처리하는 ISP 내부 산술, 카메라 출력과 Lightroom의 색 일치는 아직 검증하지 않았다.

분석 대상은 fwdc233b.bin에서 추출한 ARM RTOS다. 적재 기준 주소는 0x52500000, RTOS SHA-256은 342d2f35405e8daf1797dfe431d2e4aa70f4b52a2c242a29df48206672f1dfb4다. 함수명 일부는 분석용 이름이다. 호출 관계의 간접 연결은 기록한 생성자·vtable·객체 초기화가 유지된다는 조건 아래 성립한다. 검증 주소와 바이트 해시

하위 JPEG 압축기

상위 JPEG 매크로는 작업을 큐에 제출한다. JpegCodecPipeService의 생성자 0x5304c74c는 vtable을 설치한다. 이 vtable의 어댑터 0x5304d538은 실행 함수 0x5304cd4c로 연결된다. 이후 0x5304c7e8이 하위 드라이버의 0x5320b18c를 호출한다. 이 경로는 서비스 객체 초기화와 메시지 전달이 성공한 경우를 설명한다. 호출·vtable 근거

하위 드라이버는 JPEG 블록의 MMIO 기준 주소 0x298c0000을 사용한다. Y 주소는 +0x430, CbCr 주소는 +0x434, 압축 결과를 담는 code 주소는 +0x440에 설정한다. 시작 함수 0x5320bd68은 +0x4의 bit 0을 세운다. 버퍼 주소가 확인되었다고 해서 모든 입력 모드의 크로마 서브샘플링과 메모리 배치까지 확정되는 것은 아니다. 드라이버 근거

양자화 표의 품질 배율

0x5320ac78은 두 개의 64항 표에 품질 배율을 적용한다. 함수 인수 Q를 10으로 나눈 값을 q로 사용하며, 계산 중간마다 float32 반올림을 거친다. q가 50 이하이면 배율은 trunc(1000 × 50 / q), 그보다 크면 trunc(1000 × (100 − q) / 50)에 해당한다. 각 항목 t는 정수 연산 (t × 배율 + 500) / 1000으로 바꾸고 1~255로 제한한다. 간결한 수식의 연산 결합 순서만 바꾸어도 float32 경계값이 달라질 수 있으므로 공개 검증기는 원래 명령의 순서를 따른다.

결과는 RAM의 0x547bd374와 0x547bd3b4에 보관하고 4항씩 묶어 MMIO 0x298c0100과 0x298c0140에 기록한다. 합성 표 4쌍과 Q=1~1000을 사용해 원래 ARM 함수 및 하위 레지스터 함수를 실행했다. 4,000개 조건에서 표 항목 512,000개와 MMIO 워드 128,000개가 독립 계산식과 일치했다. MMIO는 에뮬레이터의 일반 RAM으로 대체했으며 카메라나 압축 엔진은 실행하지 않았다. 실행 검증기 · 검증 결과

이 시험은 양자화 표 생성과 전달을 검증한다. DCT, 실제 영상의 양자화 결과, 엔트로피 코딩은 시험 범위 밖이다. Q=0과 범위를 벗어난 인수도 시험하지 않았다. 카메라의 JPEG 품질 메뉴와 이 Q 값 사이의 전체 매핑은 별도 확인이 필요하다.

압축 크기와 완료 처리

0x5304ca20의 정책 경로는 Q=950으로 예비 압축한 뒤 실제 크기와 목표 크기로 품질을 추정하고 본 압축을 요청한다. 결과가 0이거나 용량을 넘으면 품질을 낮춰 재시도하는 분기가 있다. 기준 크기를 얻는 런타임 가상 호출은 미해결이며 이 정책 전체를 수치 재현하지는 않았다.

ImageInterruptService의 입력 0xd5는 JPEG 처리기 0x53201640으로 분기한다. 이 번호를 물리 CPU IRQ 번호로 확정하지 않았다. 처리기는 MMIO의 +0x480과 +0x2c에서 상태를 읽고 확인 응답을 기록한 뒤 관찰자 source 0x63 또는 0x64에 통지한다. source 0x64, 상태 bit 31, 드라이버 mode 0 조건에서는 +0x20의 압축 길이를 읽어 이벤트 0x00e00001로 전달한다.

파이프 콜백은 그 길이를 pipe+0x44에 저장하고 event bit 1을 깨운다. 압축 헬퍼는 길이를 출력 descriptor의 +0xc로 복사한다. 마지막 0x00c00003 콜백은 상위 JPEG 매크로의 event bit 2를 설정한다. 다른 오류·디코드 분기도 있으므로 모든 인터럽트를 압축 성공으로 해석하지 않았다. 조건부 콜백·상태 근거

컬러모드에서 하드웨어 설정으로

Develop의 반복 처리 0x52e5c088은 준비, 설정, 시작·대기, 종료 처리를 호출한다. 초기화 함수 0x52e5739c는 B2b·B2r·R2y 서비스를 매크로의 +0x9820, +0x9824, +0x9828에 연결한다. 시작 명령은 R2y, B2r, B2b 순서로 제출된다. 이것은 CPU가 시작을 요청하는 순서다. 센서 픽셀이 하드웨어 블록을 통과하는 순서로 해석하지 않았다. Develop·서비스 근거

R2y 매개변수 준비 함수 0x52e597c0은 설정 포인터를 P의 +0x94에 기록하고 갱신 플래그 7개를 세운다. 변환 함수 0x5307fdec은 설정의 +0x120에서 시작하는 0x5d24바이트를 드라이버 설정의 +0x644로 복사한다. 이 영역에는 이전 분석에서 계산한 Custom Image 행렬과 곡선이 들어 있다. 갱신 플래그와 선행 처리의 성공 조건을 통과하면 0x53253eac이 0x532512cc를 호출해 해당 설정을 적용한다.

하드웨어 생성자와 등록 테이블을 따라가면 R2y 레지스터 기준 주소는 0x28418000, 0x28518000, 0x28618000이다. 데이터 영역은 각각 0x294a0000, 0x295a0000, 0x296a0000으로 설정된다. 0x532512cc는 행렬 필드 +0x20..+0x30에서 signed 12-bit 계수를 꺼낸다. 첫 두 계수는 레지스터 기준 주소의 +0xa0에 각각 bits 0..11과 16..27로 기록된다. 초기화·필드 복사·레지스터 근거

이 연결로 모드별 행렬이 하드웨어 설정에 도달하는 지점까지 확인했다. 레지스터 기록 함수 자체는 픽셀별 행렬 곱을 계산하지 않는다. 내부 누산기의 비트 수, 행렬의 픽셀 연산 배율, 포화 시점과 출력 비트 깊이는 별도 근거가 필요하다.

감마·톤 테이블의 전달 위치

톤 포장 함수 0x5313775c는 16비트 항목 1024개를 설정의 +0x1568에 넣으며 하위 적용 함수는 이를 데이터 영역의 +0x0000으로 복사한다. 감마 포장 함수 0x53135c60이 만든 네 개의 0x800바이트 버퍼는 +0x8800, +0x9000, +0x9800, +0xa000으로 전달된다. 네 개의 0x200바이트 버퍼는 +0xaa00, +0xac00, +0xae00, +0xb000으로 전달된다. 이는 테이블의 저장·전달 위치를 확정한 결과이며 하드웨어 보간식까지 복원한 결과는 아니다. 설정 복사 근거

합성 설정 8개로 전체 적용 함수 0x532512cc와 실제 레지스터 함수, NEON memcpy를 실행했다. 원래 wrapper 생성자도 사용했다. 9개 행렬 필드, 4개 톤 필드, 감마 플래그 묶음, 18개 테이블 복사를 조건별로 대조해 지정 필드 외 비트의 보존도 확인해 총 312개 검사가 통과했다. 첫 번째 하드웨어 인스턴스의 레지스터와 데이터 영역을 일반 RAM으로 모델링한 시험이다. 센서 입력과 ISP의 픽셀 출력을 에뮬레이션하지 않았다. ISP 설정 검증기 · 검증 결과

색공간과 화이트밸런스

색공간 파서 0x52aed898은 sRGB와 AdobeRGB 문자열을 각각 선택값 0과 1로 변환한다. 0x52954be0 → 0x52954afc를 거쳐 UserData의 +0x35b에 저장하고 변경 알림에서 메시지 0x145를 보낸다. 같은 속성 ID를 쓰는 common setter와 RAW 모델의 0/1 변환도 확인했다. 다만 해당 메시지의 수신부에서 common+0x26b5로 기록하는 연결은 미확정이다. 색공간 설정 근거

common+0x26b5 == 1이면 P52가 1이 된다. 이 플래그는 모드 행렬에 추가 행렬을 곱하고 YCbCr 계수 조정과 감마 준비에도 영향을 준다. 따라서 색공간 선택을 행렬 하나의 교체로만 재현할 수는 없다. 각 행렬의 물리적인 입력·출력 좌표계는 아직 확정하지 않았다. 설정 분기 근거 · 이전 수치 분석

감마 변환 0x53136f4c는 입력 곡선 256항에 대해 y = min((flag ? L[x] : x) >> 4, 1023)을 계산한다. 인접 출력 차이는 0~240으로 제한한 뒤 8바이트 레코드를 고르는 인덱스로 사용한다. 마지막 항목에는 차이 0의 레코드를 넣는다. L은 펌웨어 lookup이며 표준 감마 지수로 단정하지 않았다. flag가 켜졌을 때 함수 내부에는 x의 lookup 범위를 확인하는 검사가 없다. 이번 시험 범위는 x=0~16384다. 두 flag 조건의 해당 입력을 모두 포함한 151개 전체 함수 시험과 WB 부분 구간 34개 시험이 통과했다. 색공간·WB 검증기 · 185개 검증 결과

화이트밸런스 서비스의 선택 경로 0x5314db1c는 선택한 객체의 16비트 값 4개를 오른쪽으로 5비트 이동해 common의 +0x30c10..+0x30c16에 기록한다. 별도 항등 분기는 256을 직접 저장한다. 다른 내부 항등값 8192와 >>5 변환은 두 표현 사이의 배율을 뒷받침하지만 채널 순서와 하드웨어에 적용되는 최종 gain이라는 해석은 소비 경로까지 확인한 뒤 판단해야 한다.

선택 이후의 GM/BA 미세 조정은 채널 0과 3에 lookup 곱과 13비트 이동을 적용한다. 뒤의 0x5314b914 호출과 대체 WB 분기가 결과를 바꿀 수 있으므로 앞의 >>5 결과를 모든 분기의 최종 gain으로 부르지 않았다. 네 채널을 R/Gr/Gb/B로 명명할 근거도 아직 부족하다.

Develop 공통 준비 0x52e608d8은 ImageConfig의 +0x82e0에 common 포인터를 기록하고 보정값 4개를 +0x82ce..+0x82d4에 복사한다. WB 초기화도 같은 보정 레코드를 사용한다. 초기 수동 WB 값을 담는 common+0x30c78은 선택 결과와 별도다. 선택 결과 common+0x30c10에서 B2b나 하드웨어 gain 필드로 읽어 가는 소비 경로는 이번에 연결하지 못했다. 따라서 WB가 디모자이킹이나 모드 행렬보다 먼저 적용된다고 단정하지 않는다. WB·보정 데이터 흐름 근거

클리핑은 대상별로 구분해야 한다

위치 확인한 제한 해석 범위
모드 행렬 준비 계수를 −2048~2047로 제한한 뒤 12비트 필드에 저장 계수 포화다. 픽셀 RGB를 이 범위로 제한한다는 뜻이 아니다.
일반 감마 준비 정규화 결과의 상한 16384 테이블 생성 과정의 제한이다. 모든 ISP 중간 픽셀의 상한으로 일반화하지 않는다.
Gold/Cross 곡선 보간 입력 16320 이상에서 마지막 항목 선택 곡선 주소 계산의 경계 처리다. 뒤에서 런타임 설정이 결과를 바꿀 수 있다.
색공간별 감마 변환 출력 샘플 상한 1023, 인접 차이 인덱스 0~240 하드웨어에 보낼 테이블과 레코드의 생성 규칙이다. 픽셀 클리핑 순서는 확정하지 않았다.
JPEG 양자화 표 항목을 1~255로 제한 양자화 표의 제한이다. 출력 RGB나 YCbCr 값의 범위를 뜻하지 않는다.
ISP 픽셀 경로 내부 포화·음수·하이라이트 처리 미확정 하드웨어 출력 또는 레지스터 규격과의 대조가 필요하다.

앞의 세 항목은 이전의 원본 ARM 수치 시험에서 확인했고 색공간별 감마와 JPEG 항목은 이번에 별도로 시험했다. 모드 행렬, 감마 곡선, WB를 옮길 때 이 제한들을 하나의 최종 RGB clamp로 합치면 원래 동작과 달라질 수 있다. 행렬 검증 · 감마·톤 검증 · 색공간·WB 검증 · JPEG 검증

Lightroom으로 옮기기 위한 조건

펌웨어의 컬러모드 행렬과 곡선을 DCP에 그대로 넣는 방식은 아직 성립하지 않는다. 입력 색좌표, 화이트밸런스 적용 상태, 고정소수점 배율과 클리핑 위치가 일치해야 같은 연산이 된다. 현재 복원한 자료는 모드별 변환을 재현할 때 사용할 연산 모델과 피연산자 목록이다. 카메라 JPEG와의 색 일치를 검증한 Lightroom 프로파일은 아직 만들지 않았다.

DNG의 ColorMatrix는 XYZ에서 기준 카메라 색공간으로, ForwardMatrix는 화이트밸런스를 적용한 카메라 색에서 XYZ D50으로 변환한다. 펌웨어에서 발견한 3×3 행렬에는 ColorMatrix라는 이름이 붙어 있다. 이 이름만으로 두 행렬을 같은 것으로 볼 수 없다. Adobe의 LookTable 역시 정해진 색공간과 적용 순서를 사용한다. 변환 방향과 좌표계를 먼저 맞춰야 한다. Adobe DNG 규격 1.7.1.0, pp.33, 52–53, 57, 63–64

제안하는 구현은 카메라 보정용 DCP와 모드별 look을 분리한다. DCP가 센서 색과 화이트밸런스 해석을 담당하고 look은 확인된 모드별 변환을 Adobe가 기대하는 입력 좌표계에서 표현한다. Enhanced XMP의 RGB LUT는 더 자유로운 색 변환을 담지만 적용 위치가 다르다. 2018년 Profile SDK는 RGB LUT의 최대 크기를 32×32×32로 설명한다. 이 수치는 해당 SDK의 규격이며 모든 후속 버전의 한계로 일반화하지 않는다. Adobe Profile SDK

RAW·JPEG 예제가 제공된 뒤의 검증

같은 RAW에서 모드별 카메라 JPEG를 만들고 가능한 설정을 고정한다. 촬영 때의 WB와 노출, 렌즈, 카메라 펌웨어, 출력 색공간, JPEG 품질, 노이즈 감소, 샤프닝과 자동 톤 설정을 함께 기록한다. 비교에 쓰는 모드가 해당 렌즈와 촬영 조건에서 실제로 선택되는지도 확인한다.

색상표만으로 평가를 끝내지 않는다. 회색 계조, 피부색, 잎과 강한 원색, 하이라이트가 포함된 장면을 준비하고 특성이 알려진 조명 조건을 나누어 비교한다. 프로파일을 맞출 때 사용하지 않은 이미지로 다시 검사한다. 평가 항목은 패치별 색차와 중성축 오차, 계조의 단조성, 노출 변화에 따른 오차, 채널별 클리핑 비율이다. 허용 오차는 사용 목적에 맞춰 정하고 측정 결과와 함께 공개한다.

JPEG 압축과 크로마 처리 때문에 파일 바이트의 완전한 일치를 색 재현의 합격 조건으로 삼기는 어렵다. 디코딩한 이미지에서 동일한 색관리와 출력 크기를 적용하고 패치 내부의 색과 경계 부근의 공간 오차를 구분해 평가한다. 현재 단계에서는 실제 RAW·JPEG 쌍, 카메라 하드웨어 출력, Lightroom 적용 결과를 시험하지 않았다.

검증과 보관

이번 보고서의 주소·분기·vtable 및 설정 필드는 원본 ARM 목록과 대조했다. 공개한 deep-evidence.json과 검증기는 해당 기록의 바이트 일치와 연결 조건을 검사한다. 바이트 검증이 모든 함수 의미나 실제 카메라 실행을 입증하는 것은 아니다.

추가 angr 의사코드와 전체 조사 구간의 ARM 목록, 원본 계수·테이블은 로컬 .private/jpeg-lowlevel/, .private/isp-pixel-path/, .private/wb-colorspace/에 보관한다. 공개 저장소에는 분석 문서, 주소·해시·조건부 연결과 재현용 검증 코드를 담는다. 디컴파일된 C는 원래 소스코드가 아니며, 타입·부동소수점·간접 호출 해석에서 ARM 목록과 차이가 날 수 있다.

검증 재현 명령

python verify_deep_analysis.py path/to/decoded.bin
python verify_jpeg_quantization.py path/to/decoded.bin --output jpeg-checks.json
python verify_isp_configuration.py path/to/decoded.bin --output isp-checks.json
python verify_colorspace_wb.py path/to/decoded.bin --output colorspace-wb-checks.json
python decompile_sample.py path/to/decoded.bin 0x5320ac78

첫 명령은 Python 표준 라이브러리를 사용한다. JPEG·ISP 수치 검증은 Unicorn 2.1.4, 개별 함수 디컴파일은 angr 10.0.5를 사용했다. 입력 펌웨어의 준비 방법은 저장소 안내에 있다.

근거 색인과 문서 검토

주소·분기·vtable 바이트 근거와 필드·MMIO·테이블 복사·미해결 연결을 함께 공개했다. 현재 통합 목록은 분석 구간 608개, 분기 위치 5,262곳, 데이터 워드 180개와 조건부 간접 연결 37개다. 이전 기록을 모두 보존했으며 새 수치 검증기 세 개도 원본 명령으로 다시 실행했다.

문장 검토 기록

humanize-korean light 경로, 변경률 0.1%, 언어 검토 등급 B, 자체검증 6/6. 결정적 검사는 수치·인용·서법의 소실 없이 통과했다. 긴 관형절 2→0, 연결어미 뒤 쉼표 7→0으로 정리했다. 예를 들어 “보관하고, 4항씩”을 “보관하고 4항씩”으로 바꿨다. 낮은 변경률은 원문을 대부분 보존한 결과다. 이 등급은 펌웨어 분석의 신뢰도 점수가 아니다.
