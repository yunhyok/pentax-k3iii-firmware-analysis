K-3 III DNG의 Adobe SDK Stage 3

Adobe DNG SDK 1.7.1 Build 2768이 고정 DNG의 CFA를 카메라 R·G·B 세 평면으로 보간했습니다. 가장자리를 포함한 채널 값 77,675,520개가 별도로 계산한 Bayer 보간과 모두 일치했습니다.

센서 자리와 보간 성분

고정 DNG의 uint16 샘플과 채널 값
범위행×열×평면최솟값–최댓값값 0값 65,535
Stage 2 CFA4160×6224×169–65,53508,530
Stage 3 카메라 채널4160×6224×369–65,535018,299
Stage 3 기본 크롭 부분집합4128×6192×369–65,535018,299

Stage 3에서 값 65,535는 R 4,426개, G 9,552개, B 4,321개입니다. 센서 자리에서 유지된 성분 8,530개와 보간된 성분 9,769개를 더한 수입니다. 센서 위치와 같은 색의 25,891,840개 값은 Stage 2와 모두 같습니다. 배열은 행 우선 little-endian uint16이며 각 위치에서 R·G·B 순으로 저장했습니다. 앞선 정규화 실행 · 채널별 통계와 배열 SHA-256

원본 보간과 경계 처리

SDK 기본 host에서 미리보기와 크기 요청을 끈 채 BuildStage3Image(host, -1)를 호출했습니다. SDK는 단일 CFA 평면에서 소스 평면 0을 사용합니다. 이 입력은 레이아웃 1의 RGGB이고, 다운스케일과 raw-to-full 배율은 모두 (1,1)입니다. dng_validate.cpp:61–69,104–113,276–292, dng_negative.cpp:5672–5727,5753–5803, dng_mosaic_info.cpp:1494–1521,1688–1695,2071–2116에서 호출과 분기를 확인할 수 있습니다. Adobe DNG SDK

센서 자리에서는 한 값, 가로·세로 보간에서는 두 값, 십자·대각선 보간에서는 네 값을 씁니다. 가장자리에서는 2×2 CFA 주기를 유지한 채 경계 값을 반복합니다. 원본 uint16 루프는 Q8 가중치 누산에 128을 더하고 8비트 오른쪽으로 시프트합니다. 독립 대조는 네 CFA 위상과 세 평면의 12개 조합을 별도로 계산했습니다. 근거는 dng_mosaic_info.cpp:596–669,724–735,1058–1067,1979–1989, dng_reference.cpp:1293–1333, 덤프 배치는 dng_pixel_buffer.cpp:486–493입니다. 전체 보간 대조 · 하네스

Stage 3 직후 블랙은 0, 게인은 1이며 OpcodeList3는 비어 있습니다. 기본 크롭 [24,28,4152,6220)은 활성 영역 기준 메타데이터입니다. 이 실행은 SDK 렌더를 호출하기 전에 끝났습니다. 값은 디모자이크한 카메라 채널이며 렌더의 화이트밸런스·프로파일·톤·출력 색공간을 적용하기 전입니다. Lightroom과 Adobe Converter 내부 경로는 실행하지 않았습니다. 고정 SDK 소스 및 최초 빌드 기록

같은 입력으로 재현하기

Windows x64에서 Python 3.12와 NumPy 1.26.4를 사용했습니다. 고정 첫 변환 DNG, Adobe SDK ZIP, Zig 0.15.2 전체 배포판의 zig.exe는 직접 지정합니다. Stage 2와 같은 XMP·baseline libjpeg·SDK AVX 비활성 빌드입니다. DNG IFD0에는 XMP가 있습니다. 기본 재현은 기존 Stage 2 도구의 컴파일 및 실행을 호출한 뒤 새 Stage 3 하네스 하나만 컴파일하고 나머지 오브젝트 275개를 다시 사용합니다. 고정 파일과 도구 준비 · SDK 라이선스

python -B tools/check_lightroom_sdk_stage3.py --sdk dng-sdk.zip --dng K3IIIhSLI0000100NR0.dng --zig C:\path\to\zig.exe --work C:\sdk-s3
python -B -m unittest discover -s tests -p test_lightroom_sdk_stage3.py

작업 디렉터리는 기존 부모 아래에 새로 만듭니다. 실행하는 동안 다른 프로세스에서 이 작업 디렉터리의 파일을 바꾸지 마십시오. Windows 경로 길이를 고려해 짧은 경로를 지정합니다. SDK 소스와 내부 DNG 사본, 배열 덤프, 빌드 캐시는 지정한 작업 폴더에 남습니다. 이미 보존한 최초 Stage 2 작업 폴더의 영수증과 275개 오브젝트 해시가 모두 맞으면 --stage2-work로 그 파일들을 재사용할 수 있습니다. 새로 빌드한 Stage 2 오브젝트는 기본 경로에서 생성한 뒤 같은 실행 안에서 재사용합니다. 최초 및 새 실행의 EXE 해시는 별도로 기록하며 결과 비교에는 배열, 통계, SDK 로그와 전체 보간 대조를 사용합니다. 빌드·검증 도구 · 입력 보호와 보간 테스트 · 공개 도구의 실행 기록
