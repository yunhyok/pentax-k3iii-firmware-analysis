K-3 III · 타이머 callback 연결

보드 등록에서 지연 callback까지

보드 descriptor의 RAM 생산자와 타이머 handler 등록을 연결했다. 기한 큐에서 CPU별 지연 실행 큐로 넘어가는 선택 경로도 원본 ARM으로 재현했다. 실제 IRQ와 CPU 간 전달은 검증 범위 밖이다.

설정 생산자등록 경로기한 비교callback 수명검증 범위

CPU 0 분기에서 descriptor가 만들어진다

  1. CPU 0 초기화
    0x525d9e94
  2. 보드 descriptor
    0x54c40e70
  3. handler 등록
    0x525d7c90
  4. 타이머 처리 함수
    0x525b807c

0x525d9e30의 MPIDR 검사에서 CPU index가 0이면 0x525d9e94로 이동한다. 이 경로는 0x54c40e70의 0x30바이트를 초기화한 뒤 그 주소를 보드 binder 0x525b5b4c에 전달한다. descriptor+0에는 초기화 함수 0x525b5bf0, +4·+8·+12에는 후속 callback 주소가 기록된다. 생산자·등록·원본 명령 근거

타이머 초기화는 0x54c40e70의 첫 포인터가 비제로이면 간접 호출한다. 앞의 생산자가 실행되고 이후 덮어쓰기가 없다는 조건에서 대상은 0x525b5bf0이다. 이어서 0x54c40ea0의 index로 handler 표 0x54c3f504에 0x525d7c90을 기록한다. 이 wrapper는 0x525b807c를 호출한다.

CPU 시험은 privileged 초기화 분기 이후부터 시작해 descriptor 생산과 alias 복사를 재현했다. 전체 startup·실제 handler 등록·IRQ 진입·SVC 7 복귀는 실행하지 않았다. 등록 경로가 연결됐다는 정적 근거와 실제 인터럽트가 전달됐다는 검증은 구분해야 한다.

signed 64비트 차이로 기한을 비교

선택한 큐 처리 경로는 delta = (deadline − NOW) mod 2⁶⁴를 구한다. 이를 signed 64비트로 보아 1 이상이면 head에서 처리를 멈추고 0 이하이면 노드를 분리한다. CMP·SBCS 이후 BGE의 N==V 조건을 직접 검사했다. 단순히 차이에서 1을 뺀 순환 결과의 부호만 보는 식으로 바꾸면 극단 경계의 의미가 달라진다.

합성 조건관측 결과
현재값과 같거나 이전인 head노드를 먼저 분리하고 callback 호출
미래인 head 뒤에 과거 노드가 있음head에서 멈추고 뒤 노드는 처리하지 않음
callback 포인터가 0노드 분리 후 다음 head 확인
callback 대체 함수가 NOW를 변경다음 비교에서 NOW를 다시 읽음

callback은 node+0x10, 인수는 node+0x14에서 읽는다. 시험은 정상적으로 연결한 합성 목록과 signed 최소·최대값, 64비트 순환 경계를 포함한다. callback의 NOW 변경은 시험이 만든 동작이며 실제 생산자의 발견은 아니다. 원본 삽입 함수의 별도 검증에서도 임의 기한의 전순서나 상위 호출자의 유효 범위를 보장하지는 않는다.

기한 큐에서 CPU별 지연 실행 큐로

alarm 메타데이터의 callback 0x525cdfa0는 객체+0x10의 노드를 CPU별 큐에 연결한다. 객체+4의 bit 0x20000이 설정된 경로는 객체+0x34의 mask로 index를 고른다. 해당 bit가 꺼진 경로는 MPIDR의 하위 2비트를 사용한다. 수치 시험은 전자의 mask 0·1·4·8만 실행했다. 임의 mask에 대해 index가 4 미만임을 보장하는 검사는 이 함수에서 확인하지 못했다.

선택된 큐는 0x54c405e8 + 12×index에 있다. 노드의 새 callback은 0x525cde48, 인수는 alarm 객체다. 등록은 큐 flag의 bit 0을 설정한다. 별도 mark 함수 0x525ce7bc는 하위 두 bit가 1인 슬롯에 bit 1을 설정하고 반환 CPU mask에 포함하며 모든 슬롯의 bit 0을 지운다.

지연 실행 함수 0x525ce80c도 노드를 분리한 뒤 callback을 호출한다. 0x525cde48은 객체+0x0c의 bit 0을 지우고 bit 1을 설정한 뒤 lock·IRQ helper를 거쳐 object+8(object+0)을 호출한다. 복귀 후에는 비교 필드 +0x38이 호출 전 값과 같을 때만 bit 1을 지운다. 이 필드의 실제 갱신 생산자와 동시 실행 안전성은 이번 결과로 확정하지 않는다.

기한 큐 처리 → alarm route → mark → 선택 CPU의 지연 실행 → application callback 경계는 시험이 순서대로 호출했다. application callback과 lock·IRQ helper는 대체 함수다. CPU 간 신호와 실제 scheduler의 전달을 재현한 것은 아니다. 상위 callback의 UI 연결은 기존 타이머 서비스 보고서에 별도로 기록했다.

20사례의 범위

descriptor 생산 1사례, 큐 초기화 1사례, 기한 처리 12사례, alarm 전달 4사례, flag 변환 1사례와 빈 지연 큐 1사례가 RTOS·decoded에서 동일하게 통과했다. 20사례 결과

디컴파일 C 7개, 지원 범위 7개와 ARM 582 words를 로컬에 보존했다. 디컴파일 C가 정확하게 복원하지 못한 포인터·CPU 상태는 원본 ARM으로 판단했다. 기존 TTimPeriod 20사례와 하위 산술 6,754회 실행은 이 20사례에 합산하지 않는다.

재현 명령
python verify_update_timer_irq.py rtos.bin --output timer-irq.json

재현 도구는 decoded 입력도 지원한다. 원본 C·ASM·바이너리·내장 표는 로컬에만 보존한다.

실제 시간 단위·주파수, 비제로 bank 생산자, 리소스 레코드 +4 기록자, 인증·재시작과 카메라에서의 동작은 미확정이다. 카메라 I/O·펌웨어 빌드·플래시는 수행하지 않았다.

정적 연결과 선택한 합성 실행을 구분했다. 실제 IRQ 전달은 미검증이며 보고서는 320·390·1280px에서 렌더링했다.
