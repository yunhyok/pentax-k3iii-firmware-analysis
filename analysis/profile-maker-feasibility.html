색 프로파일 · 검토

프로파일 생성 프로그램 타당성 검토

카메라의 색 계산을 PC에서 그대로 따라 해 Lightroom용 프로파일을 만들어 주는 프로그램을 만들 수 있는지 검토했습니다. 필요한 재료를 어디까지 확보했는지, 프로파일 형식으로 담지 못하는 것이 무엇인지, 쓰기 편한 프로그램이 되려면 무엇이 더 필요한지 정리합니다.

핵심 요약

  • 만들 수 있습니다. 계산 엔진과 명령줄 프로그램은 이미 저장소에 있고 펌웨어 없이 돕니다. 필요한 것은 공개한 색 표 파일과 Python, numpy뿐입니다.
  • 엔진은 카메라의 원본 코드와 같은 값을 냅니다. 원본 코드를 에뮬레이터에서 실행한 결과와 10,087가지 경우를 비교했고 다른 값이 하나도 없었습니다.
  • 지금 만들 수 있는 프로파일은 세 가지입니다. Custom Image 16종에 설정 여섯 개를 넣은 프로파일, RAW 파일에 기록된 설정을 읽어 그 사진에 맞춘 프로파일, 모드 행렬을 직접 만든 것으로 바꾼 프로파일입니다.
  • 프로파일 형식 때문에 담지 못하는 것이 있습니다. 조색, Cross Processing, Gold, Auto Select가 그렇습니다. 그림자 보정이나 샤프니스처럼 색 프로파일 밖에 있는 처리도 빠집니다.
  • 가장 큰 공백은 Lightroom에서 확인하지 못했다는 점입니다. 카메라 JPEG과 비교한 모드도 Natural과 Bright 둘뿐입니다. 프로그램을 만드는 일보다 이 확인이 먼저입니다.

확인 실행하거나 계산해 확인

  • 계산 엔진의 색 행렬, YC 행렬, 조색 오프셋, 감마 곡선이 원본 코드의 결과와 10,087가지 경우에서 일치
  • 엔진으로 만든 프로파일 16개와 펌웨어를 직접 실행해 만든 16개가 바이트 단위로 같음
  • RAW 두 장에서 Custom Image와 설정을 읽어 프로파일을 만드는 경로

정적 분석 코드를 읽어 판단

  • 설정 기록(메이커노트 태그 0x0247)의 값 순서. 설정을 색 계산 입력으로 옮기는 코드에서 읽음
  • 출고 설정 표의 구조

모델 연구자가 정한 것

  • 출고 설정 표의 각 줄을 Custom Image에 대응시킨 것(간접 근거 셋)
  • 프로파일의 LookTable을 계산하는 방법

미확인 하지 않은 것

  • Lightroom·Camera Raw에서의 실제 결과
  • JPEG과 비교하지 않은 14개 모드, 설정을 바꾼 사진
  • 웹 페이지나 앱 형태의 프로그램, 3D LUT를 담는 확장 프로파일

무엇을 검토했는가

프로그램은 두 부분으로 나뉩니다. 카메라의 색 계산을 따라 하는 부분과 그 결과를 프로파일로 옮기는 부분입니다.

카메라는 Custom Image와 설정값을 받아 색 행렬, 감마 곡선, YC 변환 행렬 같은 숫자를 계산하고 이 숫자를 영상 처리 회로에 넣습니다. 이 계산을 PC에서 똑같이 할 수 있으면 카메라가 어떤 설정에서 어떤 색을 내는지 알 수 있습니다. 그다음에는 그 색을 Lightroom의 카메라 프로파일(DCP)이 가진 태그로 옮겨야 합니다.

필요한 것과 확보한 것

계산에 필요한 재료는 모두 확보했습니다. 없는 것은 Lightroom에서의 확인입니다.

엔진이 원본 코드와 같은가

같습니다. 비교한 10,087가지 경우에서 값이 하나도 다르지 않았습니다.

엔진은 펌웨어를 실행하지 않습니다. 색 표를 읽어 같은 정수 계산을 Python으로 다시 합니다. 그래서 원본과 같은 값을 내는지를 따로 확인해야 합니다. check_color_engine.py는 같은 설정을 엔진과 펌웨어 에뮬레이터에 넣고 결과를 값 하나하나 비교합니다.

엔진과 원본 코드의 대조
비교한 범위경우의 수다른 값
Custom Image 18종 × 설정 조합 × 색공간 2개3,5260
Natural의 톤 설정 네 개의 모든 조합(94)6,5610

설정 조합은 모드마다 98가지입니다(출고 설정 기록이 없는 Cross Processing은 97가지). 모든 설정이 0인 경우, 출고 설정, 설정 여섯 개를 하나씩 −4에서 +4까지 바꾼 48가지, 조색 여덟 색, 무작위 조합 40가지입니다. 한 경우마다 색 행렬 9개, YC 행렬 9개, 조색 오프셋 2개, 감마 곡선 256점을 비교했습니다. Cross Processing과 Gold는 감마 곡선을 뺀 나머지만 비교했습니다. 두 모드는 채널마다 다른 곡선을 쓰고 엔진은 그 곡선을 계산하지 않습니다.

Auto Select는 비교에서 뺐습니다. 장면을 분석해 다른 Custom Image의 행렬을 고르므로 고정된 답이 없습니다.

프로파일 파일로도 확인했습니다. 엔진으로 만든 프로파일 16개와 build_firmware_dcp.py가 펌웨어를 실행해 만든 16개가 바이트 단위로 같았습니다.

AdobeRGB 프로파일의 작은 차이

카메라를 AdobeRGB로 설정하면 펌웨어는 감마 표를 다시 부호화합니다. 엔진은 이 변환을 식(sRGB 복호 뒤 감마 2.2 부호화)으로 계산하고 펌웨어 경로는 회로에 들어가는 10비트 표를 그대로 씁니다. 두 값은 표의 한 단계 안에서 같지만 정확히 같지는 않습니다. 그래서 AdobeRGB 프로파일은 두 경로의 파일이 바이트 단위로는 다릅니다.

지금 만들 수 있는 프로파일

명령 한 줄로 프로파일 하나를 만듭니다. 계산은 1초 안에 끝납니다.

python tools/make_k3iii_profile.py --mode bright --output Bright.dcp
python tools/make_k3iii_profile.py --mode portrait --saturation 1 --key 1 --output portrait-soft.dcp
python tools/make_k3iii_profile.py --from-raw IMGP0001.PEF --output IMGP0001.dcp
python tools/make_k3iii_profile.py --mode natural --look-matrix my-look.json --name "My look" --output my-look.dcp
python tools/make_k3iii_profile.py --all --color-space adobergb --output-dir adobe-rgb
프로그램의 기능
기능설명
Custom Image와 설정16종 가운데 하나를 고르고 채도, 색상, 키, 대비, 대비(하이라이트), 대비(섀도)를 −4에서 +4로 줍니다. 주지 않은 설정은 그 모드의 출고값을 따릅니다. --neutral을 붙이면 0으로 둡니다.
RAW에서 읽기--from-raw는 PEF나 DNG에서 Custom Image, 설정, 색공간을 읽어 그 사진을 찍을 때의 설정으로 프로파일을 만듭니다.
나만의 모드 행렬--look-matrix는 3×3 행렬을 모드 행렬 자리에 넣습니다. 각 행의 합이 1이어야 회색이 회색으로 남습니다. 카메라의 것으로 오해하지 않도록 --name이 필요합니다.
색공간--color-space adobergb는 카메라를 AdobeRGB로 설정했을 때의 처리를 따릅니다.
내 카메라의 색 행렬--color-matrix-from은 자기 카메라로 찍은 DNG에서 ColorMatrix를 복사합니다. 화이트밸런스 계산에 쓰이는 값입니다.

감마 곡선을 직접 만든 것으로 바꾸는 기능은 엔진의 함수(Engine.camera(curve=...))에만 있고 명령줄에는 없습니다.

프로파일에 담지 못하는 것

카메라 프로파일은 색 행렬 하나, 톤 곡선 하나, 색조·채도 표로 이루어집니다. 이 틀을 벗어나는 처리는 담지 못합니다.

담지 못하는 처리와 까닭
처리까닭다른 길
조색 (Muted, Bleach Bypass, HARUBENI)Cb와 Cr에 상수를 더해 회색까지 물들입니다. 색조·채도 표는 채도에 배율을 곱하므로 채도가 0인 회색을 바꾸지 못합니다.Lightroom의 색 보정 패널에서 따로 넣거나 3D LUT를 담는 확장 프로파일을 쓰는 방법이 있습니다. 둘 다 시험하지 않았습니다.
Cross Processing, GoldR, G, B 채널마다 다른 감마 곡선을 씁니다. 프로파일의 톤 곡선은 하나입니다.확장 프로파일. 시험하지 않았습니다.
Auto Select카메라가 장면을 분석해 열 가지 설정 가운데 하나를 고릅니다.카메라가 무엇을 골랐는지 RAW에 남는지 확인하지 않았습니다.
Monochrome의 필터 효과와 조색엔진에 넣지 않았습니다. 조색은 색차를 고정값으로 두는 방식이라 회색을 물들이는 문제가 같습니다.필터 효과는 색 행렬만 바뀌므로 넣을 수 있을 것으로 보이지만 확인하지 않았습니다.
그림자 보정, 하이라이트 보정, 명료도, 샤프니스, 노이즈 감소, 디지털 필터, 렌즈 보정색 프로파일이 다루는 범위 밖의 처리입니다.Lightroom의 해당 기능으로 따로 조정합니다.

확장 프로파일은 Adobe의 XMP 형식 프로파일이고 3D LUT를 담을 수 있습니다. 이 형식에 대해 조사한 내용은 컬러모드 자원과 Lightroom에 있습니다. 이 연구에서 만들어 보지는 않았습니다.

쓰기 편한 프로그램으로 만들려면

계산 부분은 끝났고 남은 것은 화면입니다. 설치가 필요 없는 웹 페이지 형태가 가장 알맞습니다.

프로그램의 형태별 비교
형태쓰는 사람이 할 일더 필요한 작업평가
명령줄 (지금)Python과 numpy를 설치하고 명령을 입력없음이미 동작합니다. 명령줄에 익숙하지 않으면 쓰기 어렵습니다.
웹 페이지브라우저에서 모드와 설정을 고르고 파일을 내려받음엔진과 프로파일 조립을 JavaScript로 옮기고 Python 결과와 바이트 단위로 대조권장합니다. 설치가 없고 이 문서 사이트에 올릴 수 있습니다.
데스크톱 앱설치하고 RAW를 끌어다 놓음포장과 배포, RAW 미리보기사진으로 결과를 미리 보는 기능이 필요할 때만 값어치가 있습니다.

웹 페이지로 옮길 때의 기술적 걸림돌은 크지 않습니다. 엔진은 정수 덧셈, 곱셈, 자리 이동만 쓰고 프로파일 조립은 81,000개 격자점의 색을 계산하는 일입니다. Python으로 프로파일 16개와 문서 17쪽을 만드는 데 4초가 걸렸습니다. 파일을 서버로 보낼 필요도 없습니다. 지켜야 할 것은 하나입니다. 옮긴 프로그램이 Python 판과 같은 파일을 내는지 자동으로 대조하는 시험을 함께 두어야 합니다.

미리보기는 별개의 일입니다. RAW를 화면에 그리려면 디모자이크와 화이트밸런스가 필요합니다. compare_camera_jpeg.py가 비교용으로 절반 크기 영상을 만들고 있어 재료는 있습니다. 다만 프로파일을 만드는 데는 필요하지 않습니다.

위험과 한계

  • Lightroom에서 확인하지 않았습니다. 프로파일의 결과는 Adobe DNG SDK의 기준 처리 순서로 계산했습니다. Lightroom의 실제 처리가 이와 다르면 결과도 달라집니다. 프로그램을 더 만들기 전에 이것부터 확인해야 합니다.
  • 카메라 JPEG과 비교한 모드는 둘입니다. Natural과 Bright에서 평탄 영역의 평균 ΔE00이 0.9 안팎이었습니다. 나머지 14개 모드는 같은 계산 경로를 쓰지만 결과를 따로 재지 않았습니다.
  • 출고 설정의 대응은 간접 근거에 기댑니다. 설정 표의 각 줄이 어느 Custom Image인지는 줄 번호의 순서, 표본 한 장, 리코의 설명으로 맞췄습니다.
  • 펌웨어 2.20의 표입니다. 다른 버전의 카메라가 같은 표를 쓰는지는 확인하지 않았습니다. 비교한 표본 두 장은 1.01과 1.10으로 찍혔고 결과가 맞았습니다.
  • 센서의 개체차. 프로파일의 ColorMatrix 행 배율은 표본 한 대에서 얻었습니다. 자기 카메라의 DNG에서 복사하는 선택지를 두었습니다.

권고와 다음 단계

  1. Lightroom에서 확인합니다. 프로파일을 넣고 RAW를 현상한 결과를 같은 사진의 카메라 JPEG과 비교합니다. Lightroom이 있는 PC에서만 할 수 있습니다. 비교 절차는 ColorChecker 비교 절차에 있습니다.
  2. 비교하지 않은 모드의 표본을 구합니다. 같은 장면을 RAW+JPEG로 Custom Image마다 한 장씩 찍으면 compare_camera_jpeg.py로 바로 비교할 수 있습니다. 카메라만 있으면 됩니다.
  3. 웹 페이지 판을 만듭니다. 앞의 두 확인에서 큰 차이가 없을 때 진행합니다.
  4. 확장 프로파일을 검토합니다. 조색, Cross Processing, Gold를 담으려면 필요합니다.

재현 방법

펌웨어 없이 할 수 있는 확인입니다. 엔진의 결과가 공개한 기록의 해시와 같은지, 프로파일과 문서가 색 표에서 그대로 다시 만들어지는지 봅니다.

python tools/check_color_engine.py --compare analysis/k3iii-color-engine-checks.json
python tools/build_profile_pages.py --check
python -m unittest tests.test_color_engine

펌웨어가 있으면 엔진과 원본 코드를 직접 대조할 수 있습니다. --full은 톤 설정 6,561가지를 모두 넣습니다. 프로세서 네 개로 15분쯤 걸립니다.

python tools/check_color_engine.py --decoded .private/my-decode/decoded.bin --full --compare analysis/k3iii-color-engine-checks.json
python tools/export_color_tables.py .private/my-decode/decoded.bin --compare analysis/k3iii-color-tables.json
