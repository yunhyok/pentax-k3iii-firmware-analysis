합성 톤 DCP의 Lightroom 출력 검증

한 차트에서 정한 톤을 DCP에 옮겨 같은 차트와 별도 장면에서 내보냈습니다. 두 장면 모두 오프라인 예측에 가까워졌고, 차트의 주황 패치는 미리 정한 최대 허용값을 넘었습니다.

이미 렌더된 톤을 프로파일 곡선으로 옮기는 조건

기존 실험은 행렬 DCP로 내보낸 #1376 TIFF에서 무채색 여섯 패치의 밝기를 기준으로 단조 PCHIP 곡선 G를 정했습니다. 이 실험은 그 곡선을 그대로 사용합니다. 톤 잔차 실험

Adobe 참조 SDK에서는 유효한 프로파일 곡선이 장면 기준 기본 곡선 B를 대체합니다. 같은 선형 ProPhoto RGB에서 높은 채널과 낮은 채널에 곡선을 적용하고, 중간 채널은 두 채널 사이의 상대 위치를 유지합니다. B가 엄격히 증가하면 이 RGB 연산을 B와 G에 차례로 적용한 결과는 G∘B를 한 번 적용한 결과와 같습니다. 같은 전단 상태를 사용하고, 두 연산 사이에 채널 혼합이나 클리핑이 없을 때 성립합니다. SDK는 노출 보정 함수와 프로파일 곡선을 합성하므로 후보를 만들 때 노출 보정을 역변환하지 않았습니다. Adobe DNG 규격 51쪽

기본 곡선의 대리값으로 DNG SDK 1.7.1 Build 2768의 ACR3 순방향 표를 사용했습니다. 후보는 각 ACR3 출력값에 G를 적용한 1,025개의 FLOAT 점을 넣습니다. 끝점은 (0,0), (1,1)이고 SDK의 자연 3차 스플라인 모델에서 모든 구간의 도함수 최솟값이 양수였습니다. Lightroom의 실제 내부 기본 곡선과 처리 순서는 이 실험에서 분리해 확인할 수 없습니다. 기존 항등·Lift·ACR3 대조 · SDK 소스 범위와 레시피 해시

고정 오프라인 목표에 얼마나 가까워졌나

Lightroom Classic 16.0, Camera Raw 19.0, Process Version 15.4의 6,016×4,000 무압축 ProPhoto RGB 16비트 TIFF를 사용했습니다. 두 장면에서 비교한 CRS 속성은 각각 115개이며, 그중 프로파일 이름과 지문만 달랐습니다. 중첩 설정 6개는 모두 일치했습니다. As Shot 수치는 #1376에서 5200 K/+2, #1363에서 4650 K/+28이었고, 노출은 두 장면 모두 EV 0.00이었습니다.

TIFF 쌍의 최대 정합 이동은 각각 0.0974px와 0.0154px로, 모두 사전에 정한 1px 미만 조건을 충족했습니다. 새 TIFF를 읽기 전에 #1376의 고정 정합 지점을 기존 homography로 TIFF 좌표에 옮기는 수정을 기록했습니다. 평가 영역과 허용값은 그대로였고, 후보의 미세 이동은 보정하지 않았습니다. 정합 지점과 현상값 대조

상대 기준 충족, 차트 최대 허용값 초과

두 장면 모두 후보 오차가 기준의 절반 미만이었습니다. 별도 차트 지표인 패치별 Lab 중앙값의 ΔE00는 평균 0.1554로 기준 0.25 이했습니다. 최대값은 7번 주황 패치의 0.8918로 기준 0.75를 넘었습니다. 같은 패치의 중앙 100×100에서도 0.8917이었습니다. 따라서 사전 기준을 모두 충족하지는 못했습니다.

차트의 같은 지표에서 무채색 6개 평균은 0.0102, 유채색 18개 평균은 0.2038이었습니다. 허용값은 두 장면을 평가하기 위한 실험 기준입니다. 관측된 차이만으로 주황 패치 잔차의 원인을 정할 수 없습니다.

프로파일 생성과 측정 재현

실험 프로파일 이름은 PENTAX K-3 II 1376 Composed Tone Offline v1입니다. 기존 #1376 DCP의 모델·행렬 두 개·광원 두 개는 동일합니다. 생성되는 8,500바이트 파일의 SHA-256은 5eaf0636e72197f0c94d79df12c2a20fa5d77a4f7641e9319d3ca7d858e212d2이고, 실제 TIFF의 프로파일 지문은 830CCADC7EB96FB2A9A81857DA6E1544였습니다.

실험 DCP 다운로드 · 파생 곡선의 출처와 Adobe 고지 · Adobe SDK 라이선스

같은 DCP를 재생성하려면 사용자가 확보한 Adobe DNG SDK 1.7.1 Build 2768 ZIP이 필요합니다. Adobe 페이지의 배포 빌드는 바뀔 수 있으므로 ZIP SHA-256으로 확인합니다. 다운로드 파일은 위 SHA-256과 일치하는 실험판입니다. Adobe SDK 소스와 원본 ACR3 표는 별도 ZIP에 있습니다. Adobe SDK 배포처 · RAW 출처와 CC0 기록

python tools/check_lightroom_composed_tone.py build --sdk dng-sdk-2768.zip --output candidate.dcp

Lightroom에 가져오기 전에 두 RAW를 각각 pentax-k3ii-1376.dng와 pentax-k3ii-1363.dng로 저장합니다. 검증기는 TIFF의 XMP에서 이 원본 이름을 확인합니다. 두 DNG에서 SubIFD1:PreviewImage를 추출해 비교용 JPEG로 사용합니다. #1376 RAW와 내장 JPEG · #1363 RAW와 현상·내보내기 설정

exiftool -b -SubIFD1:PreviewImage -w %d%f-preview.jpg pentax-k3ii-1376.dng pentax-k3ii-1363.dng

TIFF 여섯 장은 다음 프로파일로 내보냅니다. --matrix-1376과 --matrix-1363에는 PENTAX RAW matrix test 1376을, --candidate-1376과 --candidate-1363에는 PENTAX K-3 II 1376 Composed Tone Offline v1을 적용합니다. #1363의 --natural-1363과 --standard-1363에는 각각 Camera Natural과 Adobe Standard를 적용합니다.

아래 명령에 직접 내보낸 TIFF를 전달하면 같은 실험 조건에서 새 결과를 계산합니다. 기록 당시 TIFF로 기준 결과를 검증하려면 --fresh-exports를 빼고 실행합니다. #1363의 기존 Camera Natural·Adobe Standard TIFF는 마스크 복원에만 씁니다. Python의 NumPy·SciPy·OpenCV·Pillow·tifffile·scikit-image, ExifTool과 LittleCMS tificc가 필요합니다.

python tools/check_lightroom_composed_tone.py replay --fresh-exports \
  --dcp candidate.dcp --raw-1376 pentax-k3ii-1376.dng --preview-1376 pentax-k3ii-1376-preview.jpg \
  --matrix-1376 chart-matrix.tif --candidate-1376 chart-candidate.tif \
  --raw-1363 pentax-k3ii-1363.dng --preview-1363 pentax-k3ii-1363-preview.jpg \
  --matrix-1363 scene-matrix.tif --candidate-1363 scene-candidate.tif \
  --natural-1363 scene-natural.tif --standard-1363 scene-standard.tif \
  --scratch work --output fresh-result.json

입력 경로를 실제 파일로 바꾸고 work는 기존 디렉터리로 지정합니다. --exiftool과 --tificc로 실행 파일 경로를 줄 수 있습니다. 새 TIFF에서도 RAW·DCP·ICC 해시, 기록된 현상값과 중첩 설정 전체, TIFF 간 정합을 확인합니다. 고정 차트 좌표를 유지하기 위해 #1376의 기준 행렬 TIFF는 파일 컨테이너가 달라도 디코딩한 RGB 픽셀이 기록 당시와 같아야 합니다. #1363의 두 마스크는 선택된 픽셀까지 기존과 같아야 합니다. 픽셀이 달라지면 같은 마스크로 바꿔 끼우지 않고 오류를 반환합니다. 새 결과에는 실제 파일·픽셀·ICC·XMP 해시와 별도 실험 판정을 기록합니다.
