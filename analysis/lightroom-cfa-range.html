K-3 III DNG의 CFA 범위와 기본 크롭

첫 변환 DNG의 기본 크롭에 WhiteLevel 16,315를 넘는 CFA 샘플이 8,529개 남았습니다. 공개 Adobe SDK의 기본 정규화 수식에서는 경계값과 같은 한 개까지 8,530개가 65,535에 이릅니다.

이 문서에서

  1. 기본 크롭에 남은 샘플
  2. 공개 SDK의 기본 uint16 정규화
  3. PEF에서 기록한 값과 비교할 때
  4. 고정 DNG와 SDK로 다시 계산하기

기본 크롭에 남은 샘플

이 파일의 ActiveArea는 RAW 배열의 위·왼쪽·아래·오른쪽을 뜻합니다. 아래와 오른쪽 경계는 포함하지 않습니다. DefaultCropOrigin은 ActiveArea 안에서 가로 28, 세로 24만큼 이동한 점입니다. 크롭을 저장 배열 좌표로 옮기면 행 58, 열 54에서 시작합니다. 가로·세로 DefaultScale은 모두 1이고 이 표는 저장 방향의 RAW 좌표입니다. 태그와 영역 좌표

BlackLevel 64 이하의 샘플은 모두 ActiveArea 바깥에 있었습니다. WhiteLevel을 넘은 샘플은 기본 크롭의 약 0.0334%입니다. CFA 위치는 ActiveArea의 RGGB 순서를 유지하고 크롭의 시작점에서 다시 매기지 않았습니다. WhiteLevel과 정확히 같은 샘플은 R과 같은 행의 G 한 개였습니다.

공개 SDK의 기본 uint16 정규화

이 RAW SubIFD의 BitsPerSample은 16이고 SampleFormat(태그 339)은 없습니다. SDK 1.7.1 Build 2768은 이 태그의 기본값을 부호 없는 정수로 두고, 16비트 정수를 ttShort로 분류합니다. 기본 Stage 1은 RAW IFD의 이 픽셀 형식으로 할당되며, 기본 Stage 2도 ttShort를 사용하고 목적지 블랙은 0입니다. dng_ifd.cpp:223,5366–5384와 dng_negative.cpp:5074–5085,5314–5338에서 이 연결을 확인했습니다. 태그와 SDK 멤버 해시

2×2 BlackLevel은 모두 64이고 WhiteLevel은 16,315입니다. 선형화 LUT, 가로·세로 블랙 보정값, opcode list는 없습니다. 반복 열이 둘이므로 SDK는 블랙값이 같아도 2차원 보정표를 만듭니다. 세로 보정값이 없고 2차원 보정표가 있으므로 1차원 보정항은 0입니다. 이 조건에서 LUT에는 스케일만 담고, 블랙은 별도로 뺍니다. 스케일과 두 정수 보정항을 계산할 때는 real64를 씁니다. 근거는 dng_linearization_info.cpp:217–277,288–305,393–394,455–496입니다. Adobe DNG SDK

정규화 스케일은 1/(16315−64) = 1/16251입니다. SDK 소스의 정수 경로는 원시 샘플과 블랙 항을 8비트 추가 정밀도로 각각 반올림합니다. 두 항을 뺀 뒤 128을 더하고 8비트 우측 시프트한 값을 0…65,535로 제한합니다. 관측 최댓값 16,382는 제한 전 선형 비율로 약 1.004123이며, 정수 경로에서는 65,805입니다.

PEF에서 기록한 값과 비교할 때

PEF MakerNote의 WhiteLevel은 16,378이고 LibRaw가 PEF에서 보고한 maximum은 16,383입니다. 같은 배열의 기본 크롭에서 16,378보다 큰 코드는 8,479개이며 16,383 이상은 없었습니다. 따라서 50개는 16,315보다 크고 16,378 이하입니다. 이 구간은 기록된 두 숫자의 차이를 보여 줍니다. Adobe의 PEF 처리에서 16,378을 정규화 입력으로 사용한다는 근거는 없습니다. 원본 PEF와 첫 DNG의 CFA 및 메타데이터 대조

저장 CFA를 디코딩해 직접 센 값과 공개 SDK 소스를 Python으로 계산한 값을 구분했습니다. 보존한 한 파일에서 얻은 결과이며, Converter 18.7과 Lightroom의 내부 실행, 디모자이크 및 최종 렌더는 확인하지 않았습니다. 변환기 버전과 첫 DNG의 출처

고정 DNG와 SDK로 다시 계산하기

첫 변환 K3IIIhSLI0000100NR0.dng, 원본 K3IIIhSLI0000100NR0.PEF, Adobe DNG SDK 1.7.1 Build 2768 ZIP을 각각 지정합니다. PEF는 해시만 확인합니다. 세 입력의 정확한 크기와 SHA-256, ZIP 멤버 6개의 해시를 검사한 뒤 DNG의 RAW SubIFD 한 장을 디코딩합니다. 새 변환에서 파일 해시가 달라지면 이 정본 재현은 거부됩니다. 전체 결과가 고정 SHA-256과 일치할 때만 새 파일로 저장합니다. 입력 해시와 전체 결과

재현 환경은 Python 3.12.3, NumPy 1.26.4, tifffile 2023.4.12, imagecodecs 2023.1.23입니다.

python -B tools/check_lightroom_cfa_range.py --self-test
python -B tools/check_lightroom_cfa_range.py --dng K3IIIhSLI0000100NR0.dng --pef K3IIIhSLI0000100NR0.PEF --sdk dng-sdk.zip --output cfa-range-new.json
python -B -m unittest discover -s tests -p test_lightroom_cfa_range.py

검사 코드는 센서 샘플을 파일로 쓰지 않습니다. 정본 JSON의 SHA-256은 bdd372448cc6e9634d81aaf16748d634cac5b24abb4155a5318f7272c049211e입니다. 재현 도구 · 합성 좌표·경계 및 파일 보호 검사
