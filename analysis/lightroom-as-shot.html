Lightroom 색 프로파일 · Q7 As Shot 계산

같은 As Shot 중립값에서 온도·틴트가 달라지는 이유

Lightroom에서 프로파일만 바꿨는데 화이트밸런스 표기가 달라졌습니다. 공개된 Adobe DNG SDK의 계산식을 따라가 그 까닭을 확인했습니다.

이 문서에서

  1. 배경: As Shot은 센서 값이고 온도·틴트는 그 이름표입니다
  2. Lightroom 16.0에서 관측한 변화
  3. Adobe SDK가 중립값을 백색점으로 바꾸는 순서
  4. Q7의 같은 중립값을 두 프로파일로 계산했습니다
  5. K-3 III와 실제 채널 이득을 확인하려면
  6. 한계와 남은 과제
  7. 고정 입력으로 재현
  8. 근거 파일과 참고 자료

핵심 요약

  • PC의 Lightroom Classic 16.0에서 프로파일만 바꾸자 As Shot 표기가 움직였습니다. Q7은 5100 K/−17에서 4900 K/−7로, K-3 III는 5400 K/−7에서 5350 K/−6으로 바뀌었습니다. 화이트밸런스는 손대지 않았습니다.
  • 공개 Adobe DNG SDK 1.7.1 Build 2768의 수식을 Python으로 재현해 Q7 DNG의 같은 중립값을 두 프로파일에 넣었습니다. 결과는 5120.790 K/−16.980과 4921.133 K/−6.884입니다. 그 차이 −199.657 K/+10.096은 Lightroom 표기 변화(−200 K/+10)와 가깝습니다.
  • 센서 쪽 중립값은 그대로입니다. 프로파일마다 ColorMatrix가 달라서 같은 중립값이 다른 백색점 좌표, 곧 다른 온도·틴트 숫자로 표시됩니다. 카메라→D50 변환 행렬도 함께 달라집니다.
  • 한계: SDK를 직접 실행하지 않았고 Lightroom 내부도 들여다보지 않았습니다. 계산한 절대 온도는 표기보다 약 21 K 높았습니다. Q7 장면 하나(촬영 펌웨어 1.00)의 결과이며 K-3 III는 별도 문서에서 다룹니다.

확인 파일과 화면에서 읽은 값

  • Lightroom 16.0의 UI와 TIFF XMP에 기록된 As Shot 표기
  • Q7 DNG의 AsShotNeutral과 AnalogBalance, 두 DCP의 행렬(해시 고정)
  • K-3 III PEF의 MakerNote WhitePoint와 표준 태그 부재

모델 Python 수식 재현

  • SDK Build 2768 소스의 백색점·온도 계산을 Python으로 옮긴 결과
  • CameraWhite와 녹색 기준 역수 비율은 이 모델에서 계산한 값

미확인 이 계산으로 알 수 없는 것

  • Lightroom이 SDK와 같은 코드를 실행하는지, 실제 채널 이득
  • 약 21 K의 절대 온도 차이가 생기는 까닭
  • 촬영 조명의 스펙트럼과 물리적 색온도

배경: As Shot은 센서 값이고 온도·틴트는 그 이름표입니다

카메라는 촬영 때 회색이 센서에서 어떤 R:G:B 비율로 찍히는지를 RAW에 적어 둡니다. DNG에서는 이 값을 AsShotNeutral(촬영 시 중립값)이라고 부릅니다. Lightroom의 화이트밸런스 "As Shot"은 이 값을 그대로 씁니다.

화면에 보이는 "5100 K / −17" 같은 온도·틴트는 센서 값을 사람이 읽는 좌표로 옮긴 이름표입니다. 이 변환에 프로파일(DCP)의 ColorMatrix가 쓰입니다. 그래서 센서 값이 같아도 프로파일을 바꾸면 이름표가 달라질 수 있습니다.

쉽게 말하면

ColorMatrix는 "센서 색 → 표준 색" 사전입니다. 같은 센서 회색을 사전 두 권으로 번역하면 서로 조금 다른 백색점이 나옵니다. ForwardMatrix는 그 뒤 실제 그림을 그릴 때 쓰는 다른 사전으로, 이름표를 정하는 단계에는 쓰이지 않습니다.

Lightroom 16.0에서 관측한 변화

같은 RAW의 가상 사본에서 프로파일만 바꿨더니 세 출력 모두 As Shot 표기가 달라졌습니다.

As Shot을 유지했고 화이트밸런스를 수동으로 조정하지 않았습니다. 아래 값은 Lightroom UI와 내보낸 TIFF의 XMP에 남은 표기입니다. 이 출력들의 색차 비교는 Lightroom 참조 프로파일 비교에 있습니다. 거기서는 프로파일과 As Shot 해석이 함께 바뀐 조건으로 다룹니다.

Adobe SDK가 중립값을 백색점으로 바꾸는 순서

SDK는 고정된 카메라 중립값을 선택한 프로파일의 ColorMatrix로 풀어 백색점을 정합니다. ForwardMatrix는 그 다음 렌더링 변환에만 쓰입니다.

  1. RAW 중립값 정리 DNG 중립 벡터의 최대 채널을 1로 맞추고 소수 여섯 자리로 반올림합니다. Q7의 AsShotNeutral은 (256/411, 1, 256/445)입니다.
  2. 프로파일별 역변환 렌더러에 명시적 백색점 지정이 없고 카메라 중립값이 있으면, 선택된 프로파일의 ColorMatrix로 백색점 xy를 반복 계산해 풉니다. 두 조명 행렬 사이의 보간 가중치는 역색온도로 정합니다.
  3. 온도와 틴트 xy를 등온선 표와 보간해 SDK의 온도·틴트 좌표로 나타냅니다.
  4. 렌더링 변환 xy를 다시 카메라 공간으로 보내 CameraWhite를 구합니다. 이어서 ForwardMatrix 또는 Bradford 경로로 D50 PCS에 옮깁니다. 프로파일에 ForwardMatrix가 있으면 그 행렬을 씁니다.

입력의 AnalogBalance와, 시그니처가 맞는 CameraCalibration도 유효 행렬에 들어갈 수 있습니다. Q7 입력의 AnalogBalance는 (1, 1, 1)이고 보정 행렬과 시그니처는 없습니다. Q7 매트릭스 DCP에는 ForwardMatrix가 없어 Bradford 경로를 탔고 Adobe Standard는 자기 ForwardMatrix를 썼습니다. 공개 SDK의 참조 커널은 CameraWhite를 채널별 상한으로 쓴 다음 변환 행렬을 적용합니다.

SDK 소스 파일과 행 번호

계산에 쓴 SDK 1.7.1 Build 2768 ZIP의 SHA-256은 c1d3a545ed45b150e59af2e6aa0695c1551f0e2bed34ad87436898a05194d2b1입니다. 주요 근거는 dng_color_spec.cpp(역변환 NeutralToXY는 최대 30회, CameraWhite와 카메라→PCS 변환), dng_temperature.cpp(등온선 표와 온도·틴트), dng_negative.cpp(중립값 정규화와 반올림), dng_render.cpp(백색점 선택 순서)입니다. 파일별 해시와 행 번호는 SDK Build 2768 파일·행 번호의 sdk.source에 있습니다. SDK 배포처는 Adobe DNG SDK입니다.

Q7의 같은 중립값을 두 프로파일로 계산했습니다

계산한 변화량(−199.657 K/+10.096)은 Lightroom 표기 변화(−200 K/+10)와 가까웠습니다. 절대값은 계산 쪽이 약 21 K 높았습니다.

두 계산 모두 6회 반복에서 수렴했습니다. 모델에서 정규화한 CameraWhite는 두 프로파일 사이 최대 성분 차이가 1.61×10−8입니다. 녹색을 1로 둔 역수 비율의 최대 차이는 4.14×10−8입니다. 반면 카메라→D50 변환 행렬은 최대 성분 차이가 0.541446입니다. 같은 센서 중립값이 다른 백색점 좌표로 표시되고 렌더링 변환도 함께 달라집니다. 계산값과 자체 검사는 lightroom-as-shot.json에, 계산 코드는 check_lightroom_as_shot.py에 있습니다.

표기 변화는 가까웠지만 Lightroom이 SDK의 같은 코드를 실행하는지는 확인하지 못했습니다. 별도의 채널 이득을 무엇으로 적용하는지도 모릅니다. 역수 비율은 모델에서 계산한 값이며 촬영 조명의 스펙트럼이나 물리적 색온도를 잰 자료는 없습니다. 이 실험의 촬영 펌웨어는 Q7 1.00과 K-3 III 1.10입니다.

K-3 III와 실제 채널 이득을 확인하려면

K-3 III PEF에는 표준 DNG 중립값이 없어 이 문서에서는 계산하지 않았습니다. Lightroom의 실제 채널 이득은 최종 TIFF만으로는 구할 수 없습니다.

K-3 III PEF의 Pentax MakerNote에는 WhitePoint 18976/8192/8192/13088이 있습니다(ExifTool Pentax 태그 정의). 원본 PEF의 IFD0에는 표준 DNG AsShotNeutral과 AsShotWhiteXY가 없습니다. 이 Q7 계산에서는 K-3 III의 센서 중립값을 추정하지 않았습니다. 표시 Kelvin에서 거꾸로 구한 벡터도 독립 검증에 쓸 수 없습니다. 고정 버전 Adobe DNG Converter가 기록한 표준 중립값은 K-3 III PEF 변환과 수식 대조에서 따로 확인했습니다.

DNG 변환은 그 변환기의 중립값 해석을 보여 줄 뿐입니다. Lightroom 렌더러의 채널 이득이 같은지 보려면 같은 RAW의 두 프로파일 조건에서 백색점 해석 직후(색 행렬·LUT 적용 전)의 채널 이득과 적용 단계를 알아야 합니다.

참고

이득 D와 뒤따르는 행렬 M의 곱만 알면 임의의 가역 대각행렬 A에 대해 (M A⁻¹)(A D)도 같은 변환을 만듭니다. 그래서 최종 TIFF만으로는 두 인자를 따로 구할 수 없습니다.

촬영 조명 아래 물리적 중립의 센서 응답을 확인하려면 분광 반사율을 아는 무채색 표적을 함께 찍어야 합니다. 포화되지 않은 선형 CFA 채널값에서 블랙 레벨을 뺀 비율을 재고 광원의 물리적 색도는 따로 측색합니다.

한계와 남은 과제

  • 컴파일한 SDK를 실행하지 않았고 Lightroom 내부도 계측하지 않았습니다. 고정 입력에 대한 수식 재현입니다.
  • Q7 절대 온도는 계산과 표기가 약 21 K 다릅니다. 표시 정밀도, 내부 이득, 알고리즘이 같은지는 확인하지 못했습니다.
  • MakerNote 값은 해석기가 읽은 필드 값일 뿐이며 Adobe의 PEF 해석 방식과 연결되지 않았습니다.
  • 촬영 한 장이 RAW와 중립값을 정합니다. 실제 조명의 스펙트럼이나 물리적 색온도는 재지 않았습니다.

고정 입력으로 재현

Adobe DNG SDK 1.7.1 Build 2768 ZIP, Q7 DNG, K-3 III PEF, 매트릭스 1760 DCP, 설치된 Q7 Adobe Standard DCP를 각각 지정합니다. 파일 크기와 SHA-256은 입력 핀과 전체 결과에 고정했습니다. 계산기는 ZIP에서 온도 표를 읽습니다. 그다음 직접 확인한 RAW의 중립값과 프로파일 행렬을 Python 수식에 넣어 원래 결과와 대조합니다. Adobe가 지금 다른 빌드를 배포하면 입력 해시가 맞지 않을 수 있습니다. 원본 출처는 스튜디오 RAW 출처, SDK 사용 조건은 Adobe SDK 라이선스를 보십시오.

python -B tools/check_lightroom_as_shot.py \
  --sdk dng-sdk.zip --raw Q7hSLI00100NR1.DNG \
  --pef K3IIIhSLI0000100NR0.PEF --matrix pentax-q7-1760-matrix-test.dcp \
  --adobe-standard "PENTAX Q7 Adobe Standard.dcp" --output as-shot-replay.json

매트릭스 1760 DCP가 없으면 스튜디오 기준 JSON의 profile_recipes.q7.spec 객체를 별도 JSON 파일로 저장합니다. 그 뒤 python tools/profile_bridge.py q7-spec.json pentax-q7-1760-matrix-test.dcp로 만듭니다.

결과 비교 방식과 실행 환경

검증기는 고정 기준 JSON과 그 안의 원래 계산 결과를 각각 SHA-256으로 확인합니다. 새 계산은 키, 배열 길이, 자료형과 실수 이외의 값이 모두 같아야 합니다. 유한 실수의 허용 오차는 항목마다 절대 차이 1e-10입니다. 계산값을 그대로 저장하고 실제 출력의 SHA-256을 표시합니다. 기준과 바이트까지 같으면 exact, 수치 비교만 통과하면 numeric입니다.

Python 3.12.3, NumPy 1.26.4, tifffile 2023.4.12에서 기본 OpenBLAS 경로는 바이트까지 일치했습니다. 같은 환경에서 Nehalem 커널을 고른 대조는 실수 25개에 최대 6.66×10⁻¹⁶ 차이가 있었고 수치 비교를 통과했습니다. 두 실행 환경에서의 관측입니다. 입력 RAW·DCP·SDK와 원본 온도 표는 따로 준비해야 합니다. 계산에는 SDK 네이티브 실행이나 Lightroom 렌더링이 들어 있지 않습니다.
