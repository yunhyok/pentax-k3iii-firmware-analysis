업데이트 파일 시스템과 버퍼 수명

실제 FileSystem 객체부터 FAT·exFAT 분기까지 연결하고 압축 입력과 decoded 출력이 함께 존재하는 구간 및 실패 후 정리 조건을 확인했다.

resourceManager+0x38은 factory singleton 0x54787088의 +0x14에 저장된 FileSystem primary 객체다. factory 초기화 함수에서 0x30바이트 객체를 생성하고 그 생성자가 vptr 0x53901308을 설치한다. open/close/read/stat은 이 객체의 실제 함수로 연결되며 경로에서 구한 volume index에 따라 FatFileSystem, ExFatFileSystem 또는 VirtualFileSystem의 secondary interface로 전달된다.

handle·크기·오류 전달

open이 lower callback 성공을 받으면 52f50498에서 8바이트 wrapper를 할당하고 52f504d4에 raw lower handle, 52f504e0에 volume index를 기록한다. 52f504e4는 그 wrapper pointer를 caller의 output에 저장한다. read와 close는 wrapper+4로 backend를 선택하고 wrapper+0을 lower handle로 전달한다. 성공 시 카운터 증가와 close 성공 시 감소도 이 층에 있다. open의 wrapper 할당 실패 처리는 합성 검사에서 실행하지 않았다.

read는 buffer/size를 lower+10으로 그대로 전달하고 lower 반환값과 error word를 반환한다. null handle, 음수 index, null backend에서는 lower 호출 없이 반환0과 error12가 나온다. stat은 경로 index와 lower+48을 사용하며 invalid path는 반환0과 error2다. 합성 stat callback이 쓴 FileInfo+18은 caller가 읽을 크기 필드로 유지된다. close는 lower 실패에서도 wrapper 해제 helper를 호출한다. 반환값은 lower가 0이면 0, 비제로이면 1로 정규화한다. open도 wrapper 할당 성공 시 같은 방식으로 정규화하며 read·stat은 lower의 32비트 반환값을 유지한다. 이 차이는 합성 반환값 0·1·2·0xffffffff로 확인했다. 실제 lower close 동작은 실행하지 않았다.

이 facade의 read/stat은 내부 mutex acquire 반환값을 분기 조건으로 쓰지 않는다. 합성 lock 반환0에서도 lower callback과 unlock이 호출됐다. 상위 loader의 mutex gate는 별도이며 이 관찰을 실제 동시성 오류나 잠금 정책 부재로 확대하지 않는다.

재현과 검증 범위

파일 인터페이스 재현 도구는 pinned RTOS 또는 decoded.bin SHA를 검증한다. 원본 ARM 49사례는 factory fragment/실제 ctor alias4, 첫문자 index10, backend 분기8, open 반환값4 및 invalid1, read7 및 invalid3, stat7 및 invalid1, close4다. factory의 vptr와 네 alias 필드는 예상값과 다른 값으로 채운 뒤 실제 저장 결과를 확인했다. factory fragment는 52f51644..16d8이며 합성 r4와 frame을 주입했다. factory의 전체 시작 경로나 mount 전체를 실행한 검사는 아니다.

명시적 stub은 lower FS callbacks, factory/handle 할당, mutex, assertion, handle bookkeeping/free, strlen, FileSystem initialize 경계다. 문자열 길이는 합성 NUL 문자열에서만 계산한다. 요청된 수천만 바이트를 실제로 할당하거나 읽지 않는다. CPU 모델은 Unicorn Cortex-A15이며 카메라 재현 정확도를 주장하지 않는다. genuine angr C8개는 그대로 보존하되 ARM을 조건·주소의 기준으로 사용한다.

압축 입력과 decoded 출력의 공존

종류 2의 검증 진입점 52fefb84는 state+48의 입력 포인터와 +44의 길이를 packageContext+1c/+20으로 전달한다. 52ff2e04 → 52ff4b0c → 52ff5168을 거쳐 validator+8/+c에 같은 입력을 연결한다. 원본 함수는 헤더·종류·외부 합계를 검사한 뒤 52ff4f88이 별도의 출력 버퍼를 할당하고 기존 입력의 +80 주소를 디코더에 넘긴다. 이 구간에는 입력 해제 호출이 없다. 공개 연결 검사의 외부 합계 필드는 0xffffffff sentinel이므로 실제 합계 비교를 건너뛴다. 별도 비공개 검토에서 실제 외부 합계의 일치·불일치 2사례를 검사했다. 연결 주소·해시·공존 근거

앞선 메모리 할당 조사에서 구한 입력·출력의 OS 요청 합계는 원본 113,790,848바이트, 선택 블록만 바꾼 후보 113,820,928바이트, 전체 stored 후보 157,374,848바이트다. 이제 이 합계를 두 요청이 공존하는 시점과 연결할 수 있다. 이는 전체 업데이트의 최고 메모리 사용량이 아니다. 디코더 작업 공간, 다른 할당, OS 내부 오버헤드, 현재 가용 연속 공간은 포함하지 않았다.

입력 정리와 pool 해제의 반환값

52feec18(state, flag)에서 입력이 없으면 해제 요청을 생략한다. 입력이 있고 flag가 0이면 포인터를 지우되 pool에 반환하지 않는다. flag가 0이 아니면 52ff622c에 해제를 요청하고 반환값이 0일 때는 포인터와 종류·경로·길이의 초기화 전에 종료한다. 비제로 반환을 받으면 먼저 state+48을 0으로 지우고 각 component의 입력 setter를 호출한다. 그 뒤 종류=8, 경로·길이=0을 기록한다. flag=0인 실제 호출 위치 533164c0도 존재한다. flag의 소유권 의미를 다른 진입 경로 전체로 확장하지 않았다. 정리 함수·호출자

52ff622c는 resourceManager+30 pool의 slot+18로 주소 소속을 확인하고 아니면 +34 pool을 검사한다. 일치한 pool의 slot+c를 호출한 뒤 반환하는 값은 저장해 둔 mutex 획득 결과다. pool 해제 함수의 성공 여부는 이 반환값에 반영하지 않는다. 어느 pool에도 속하지 않으면 false assertion에 도달한다. 두 실패 사례에서는 assertion이 반환한다고 가정해 이후 흐름을 확인했지만 실제 카메라의 실패 처리 정책은 재현하지 않았다.

IMAGE1의 slot+18 대상 530efb60은 unsigned base ≤ pointer < base+size를 검사한다. 확인된 필드 base=6e500000, size=31affff0를 대입하면 끝 경계는 9ffffff0이며 그 주소 자체는 제외된다. 앞서 초기 설정 영역의 끝을 a0000000으로 기록한 것과 구분해야 한다. 마지막 16바이트는 이 소프트웨어 소속 검사 범위 밖이다. 이는 물리 DRAM 매핑이나 실제 가용 공간을 입증하지 않는다.

slot+c의 실제 대상 530efee8은 aligned 포인터 −8의 debug 포인터를 읽고 그 소속을 확인한 후 backpointer를 0으로 지운다. debug 포인터에서 0x18을 빼 raw 주소를 복원하고 525b75e0(handle, raw)에 전달한다. OS 반환값이 0이면 pool 함수는 1을 반환한다. 이 검사는 OS 호출을 합성 함수로 대체했으므로 실제 메모리 반환을 증명하지 않는다. 버퍼 수명 재현 도구

현재 확인한 setter와 정리 구간은 validator의 decoded 필드와 상위 context의 decoded 필드를 지우지 않는다. 다만 component 5의 reset 함수 52ff31c4는 호출 인자만 확인하는 경계로 남겼다. 이후 리소스 슬롯 조회와 전체 업데이트 종료 과정까지 따라가야 최종 출력 회수 시점을 확정할 수 있다.
