# K-3 Mark III v2.20 RTOS 명령과 호출 관계

명령표의 957개 항목을 17개 기능군으로 분류하고 각 진입점에서 C 형태의 의사코드를 생성했다. 촬영·AF·영상처리에서는 명령 처리기 11개와 하위 함수 25개, **서로 다른 함수 36개**를 골라 기계어와 대조했다. 가장 구체적으로 복원한 연산은 두 디포커스 결과를 합치는 조건과 영상 진단 코드의 256항 톤 변환표다.

## 957개 명령의 분류

각 명령에는 주 기능 하나를 지정했다. 예를 들어 AF 측거점 선택 스위치는 사용자 입력, AF 모드 설정은 AF, 화이트밸런스는 영상처리로 세었다. 명령 이름과 소속 계열을 기준으로 나누고 약칭이 모호한 곳은 처리기가 참조하는 도움말과 인수도 대조했다. 예를 들어 ID 717·718의 도움말은 스위치 **입력 에뮬레이션**을 명시한다. 이 표에서 UI에 분류된 명령이 실제 스위치를 폴링한다고 단정할 수는 없다.

## AF

**명령과 결과 조회.** ID 39 `camctl_control_auto_focus`도 촬영과 같은 제출 함수 `0x52c1e4a8`을 호출한다. 요청 ID 3은 같지만 첫 슬롯이 **2**다. 뒤에는 `cam/area`, `start/stop`, 숫자 인수 두 개가 따른다. 마지막 두 숫자는 도움말의 폭·높이 표기와 진단 메시지의 x·y 표기가 달라 해석을 보류했다. 반면 ID 242의 뷰파인더 AF 모드 설정은 요청 ID 0, 설정 항목 `0x57`에 single=1 또는 continuous=2를 넣는다. ID 336의 PAF 플래그 설정은 유효한 하위 객체의 `+0x89` 바이트에 0 또는 1을 직접 기록한다.

**디포커스 값이 만들어지는 단계와 읽히는 단계.** ID 335 `GetDefocus`는 저장 레코드의 유효 바이트를 검사한다. 무효이면 `0x7fffffff`를 반환하고 유효하면 마지막 분기 `0x52553fd4 → 0x52caa160`에서 부호 있는 기존 디포커스 값을 읽는다.

별도 함수 `0x52cd1d20`에서는 유효성 조건을 통과한 두 측거 결과를 실제로 계산에 사용한다. `0x52cd1f4c`와 `0x52cd1f64`에서 슬롯 0과 1의 값을 읽고, 두 값의 차이 크기가 **60을 초과하면 결합을 건너뛴다**. 통과하면 두 값의 합을 2로 나눠 0 방향으로 절삭한 뒤 `0x52cd1fdc`에서 슬롯 2에 쓴다. 이 설명은 32비트 덧셈·뺄셈이 넘치지 않는 입력 범위에서 성립한다. 60의 광학 단위는 미확인이다. 이 함수는 측거점별 모드를 사용하고 `GetDefocus`는 집계 모드를 사용하므로, 두 함수가 같은 슬롯 번호를 쓴다는 사실만으로 직접 생산·소비 관계를 연결하지 않았다. 센서의 원시 위상차로부터 첫 두 값을 얻는 계산도 이번 경로 밖에 있다.

## 영상처리

**톤 변환표.** ID 698 `IQ_tone`은 진단 파일을 처리하는 명령이다. `0x5258efd4`와 `0x5258effc`에서 작업 공간 조회와 처리에 같은 하위 함수 `0x530b6810`을 호출한다. 이 함수는 16비트 항목 256개를 만들고 동일 테이블 포인터를 세 설정 필드에 넣는다. 중간 구간의 연산을 ARM/VFP 명령과 리터럴 상수에서 복원했다. 아래 식은 코드가 사용하는 유효한 입력 순서 `lo < mid < hi`의 진단 예를 설명한다.

- `left = mid - lo`, `right = hi - mid`, `q = min(left, right) / (hi - lo)`.
- `p = 2.5q² + 0.55q + 0.1`. `left ≤ right`이면 지수는 `p`, 반대면 `1/p`다.
- 입력 `i ≤ lo`에는 0, `i ≥ hi`에는 255를 기록한다. 그 사이는 `trunc(0.5 + 255 × ((i-lo)/(hi-lo))^지수)`다. 정규화와 지수 계산은 단정밀도 반올림을 거치고, `pow` 계열 호출 결과의 배율·가산은 배정밀도 명령에서 확인했다.

진단 기본값 `lo=15, hi=240, mid=128`에서는 지수가 **1.0068115**다. 호스트에서 반올림을 재현하면 입력 `15, 64, 128, 200, 240`은 각각 `0, 55, 127, 209, 255`가 된다. 카메라의 일반 JPEG 촬영에 적용되는 기본 톤 곡선인지는 확인하지 않았다. 디컴파일러의 C 출력에는 부동소수점 반환값을 놓친 표현이 있어 수식 검증에는 역어셈블 명령을 사용했다.

**노이즈 감소.** ID 692 `IQ_nr`는 `0x5258e1b4 → 0x530bc14c`에서 다중 스케일 작업 버퍼를 배치하고 용량을 확인하는 경로에 들어간다. 네 개의 하위 경로와 톤 경로가 완료 처리 함수 `0x530be7dc`를 공유한다. 이 함수는 `0x530be7f8 → 0x530bcb74`에서 상태를 기다리며 IIP, CNR0, CNR1, DSP 오류를 구분한다. 공통으로 확인된 부분은 완료·오류 처리까지다. 픽셀별 노이즈 필터나 가상 호출 뒤 ISP/DSP 내부의 산술은 미확인이다.

## 호출표를 읽는 방법

일괄 분석에서 찾은 **직접 호출 위치 17,346곳, 대상 미확정 레지스터 호출 350곳, 분석 창 밖으로 향하는 분기 15곳**을 기록했다. 한 함수가 여러 곳에서 같은 대상을 호출하면 각 호출 위치를 센다. 상세 추적에서 추가한 위치까지 합친 표는 17,914행이다. 각 행에서 호출자 주소, 명령 위치, 종류, 목적지를 읽을 수 있다. `call-thumb`는 Thumb 상태로 전환하는 직접 호출, `call-reg`의 `-`는 미확정 목적지다. `branch`는 일반 분기이며 호출 수에서 제외했다. `evidence`는 일괄 CFG, 상세 추적 또는 양쪽에서 얻은 행인지 구분한다. [호출·분기 표](transfers.tsv)

상세 대조 범위는 **경계 주소가 서로 다른 디컴파일 함수 36개와 추가 역어셈블 구간 6개**다. 구간 일부만 조사한 경우 호출표의 `caller`는 조사 구간의 시작을 뜻한다. 각 구간에는 시작·끝 주소와 원본 바이트의 SHA-256을 붙였다. 하위 함수의 영문 설명 이름은 분석용이다. [검증 구간과 해시](priority-functions.tsv)

957개 일괄 분석은 각 명령 진입점에서 제어흐름 그래프(CFG)를 만들고, 다음 진입점 주소를 탐색 상한으로 사용했다. 마지막 명령의 상한은 다음 별도 프롤로그 `0x525b2cd8`이다. 탐색 창에는 리터럴과 다른 코드도 있을 수 있어 `cfg_bytes / window_bytes`를 소스 복원율로 사용하면 안 된다. 간접 호출은 반환할 수 있다고 모델링했고 스택 보호 실패 함수 `0x532fb9c8`은 종료점으로 취급했다. 생성한 C에는 타입·호출 규약 오인과 분기 누락이 있다. 예를 들어 상세 추적에서 요청 전송 함수는 484바이트 중 432바이트, 셔터 드라이버 호출 구간은 180바이트 중 60바이트만 해당 디컴파일 CFG에 나타났다. 나머지 동작 설명은 전체 ARM 목록과 직접 대조했다.

`c_sha256`은 이번 일괄 실행으로 저장한 C 텍스트의 해시다. 같은 버전의 angr로 촬영 명령을 다시 분석해도 지역 구조체와 포인터 표현이 달라지는 경우를 확인했다. 재현 시에는 입력 바이트·명령 주소·호출 목적지를 우선 대조한다.

## 재현

먼저 [기본 분석 절차](../README.md#재현)로 이 버전의 `decoded.bin`을 만든다. 다음 두 명령은 Python 표준 라이브러리만 사용한다.

```console
python rtos_catalog.py .private/my-decode/decoded.bin --output .private/my-commands.tsv
python verify_command_analysis.py .private/my-decode/decoded.bin
```

첫 명령은 원래 이름·주소·분류를 결합한 957행 TSV를 만든다. 공개 표에는 명령 ID별 분석 결과를 담고, 원본 명령표 전문과 생성한 C는 작업 폴더에 보관한다. 두 번째 명령은 분류, 상세 구간 해시 및 17,914개 위치의 ARM 명령 유형과 직접 분기 목적지를 바이너리에서 독립적으로 확인한다. 이 검증은 기계어와 기록의 일치를 검사하며, 모든 함수의 의미를 판정하는 검사는 아니다.

개별 명령은 `angr==10.0.5`를 설치한 Python 환경에서 ID로 재현한다. 상세 조사한 함수는 주소로도 지정할 수 있다. 출력은 C 형태의 의사코드다.

```console
python decompile_sample.py .private/my-decode/decoded.bin 39
python decompile_sample.py .private/my-decode/decoded.bin 0x530b6810
```

REA의 원시 RTOS 이미지 열기 결과는 `unsupported binary format`이었다. 이 분석에서는 확인된 적재 주소 `0x52500000`에서 angr와 Capstone으로 ARM 코드를 읽고, 공개 검증기는 분기 인코딩을 별도로 해석했다. 카메라 실행이나 플래싱은 수행하지 않았다. [분기 검증 코드](../verify_command_analysis.py) · [angr 디컴파일러](https://docs.angr.io/en/latest/analyses/decompiler.html)
