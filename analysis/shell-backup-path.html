RTOS 명령과 셸 · SD 셸 입력과 백업

SD 카드 스크립트가 셸 명령을 실행하는 경로

SD 카드에 둔 스크립트가 카메라 내부 셸 명령을 실행하는 코드가 있습니다. 또한 보정 데이터 백업 명령은 조건에 따라 내부 저장장치에도 쓰기 때문에, 단순한 읽기 전용 백업으로 볼 수 없습니다.

핵심 요약

  • SD 카드의 TTL 스크립트가 sendln을 거쳐 RTOS 셸 명령을 실행하는 경로를 원본 명령에서 확인했습니다. 이 경로는 카메라 초기화가 진행된 뒤에 쓰입니다.
  • USB로 같은 셸에 들어가는 경로는 확인하지 못했습니다. 바이너리에 관련 이름은 있지만, 조사한 범위에서 USB 입력이 RTOS 셸에 도달한다는 근거는 없었습니다.
  • 보정 데이터 백업 명령(inf_adj backup)은 조건에 따라 내부 eMMC에도 씁니다. 따라서 이 버전의 백업 명령을 내부에 흔적을 남기지 않는 백업으로 쓸 수 없습니다.

배경: SD 스크립트와 내부 셸

카메라 내부에는 점검·개발용 셸이 있습니다. 평소에는 바깥에서 쓸 일이 없지만, 특정 파일이 SD 카드에 있으면 그 내용이 셸 명령으로 실행될 수 있습니다. 이 파일은 TTL 스크립트 형식입니다.

쉽게 말하면

TTL은 터미널 프로그램 Tera Term이 쓰는 매크로 언어입니다. sendln은 “이 문자열을 한 줄 보내라”는 명령으로, 사람이 키보드로 명령을 입력하는 것을 대신합니다. 카메라는 SD의 스크립트에서 이 줄을 받아 내부 셸 명령으로 실행합니다. Tera Term 매뉴얼의 sendln

저장장치 용어도 구분이 필요합니다. SD 카드는 꺼낼 수 있는 외장 저장장치이고, eMMC는 본체에 붙박인 내장 저장장치입니다. eMMC는 부트 영역과 일반 영역이 하드웨어로 나뉘어 있어, 부트 영역을 골랐다가 일반 영역으로 되돌아오는 동작을 코드에서 구분할 수 있습니다. eMMC 규격(JEDEC JESD84)

SD 파일에서 셸 명령 실행까지

초기화 중 보낸 시스템 메시지가 C:\script\의 TTL 파일을 확인하고, 스크립트의 sendln 줄을 콜백에 넘겨 셸 명령 처리기를 부릅니다.

초기화 경로가 시스템 처리기 0x53318764에 인수 0으로 메시지를 보냅니다. 처리기는 dbgparam.ttl의 크기를 검사해 내용이 있으면 실행을 요청하고, 이어 startup.ttl에도 같은 검사를 합니다. 인수가 0이 아닌 쪽은 shutdown.ttl을 확인합니다. 세 파일은 모두 C:\script\ 아래에 있고, C:는 SD 드라이버로 연결됩니다. 스크립트 처리기는 sendln을 토큰 0x4e로 바꿔 문자열을 콜백에 넘기고, 셸은 명령 이름을 찾아 간접 호출로 해당 함수를 실행합니다. 콘솔 초기화 쪽은 리소스 슬롯 4를 읽어 명령을 등록하며, 초기 레코드 이름은 ShellCmdList입니다.

읽기 계열 명령 중 emmc_fread는 일반 영역을 읽어 지정한 파일에 쓰고, sys_fwdump는 정해진 범위를 읽어 C:\fwdump.bin으로 내보냅니다. 이 두 처리 함수에서 eMMC에 데이터를 기록하는 호출은 찾지 못했습니다. 반면 emmc_freadb는 eMMC 부트 파티션을 골랐다가 일반 영역으로 되돌아오므로, 같은 범주의 읽기 시험에서 분리합니다.

주의

출력 파일이 SD에 생겨도, 정상 초기화 도중 내부 로그나 설정을 함께 기록하는지는 별도로 확인해야 합니다. 이 스크립트는 RTOS가 실행된 뒤에 읽습니다. 부팅이 멈춘 바디의 Boot ROM 복구 기능은 아직 확인되지 않았습니다.

USB의 셸 진입 경로는 미확인

바이너리에 Linux 셸 명령 처리기 이름이 있지만, 조사한 범위에서 USB 입력이 RTOS 셸에 도달한다는 근거는 찾지 못했습니다.

Ricoh가 공개한 USB 기능은 MTP·CD-ROM 데이터 전송과 테더 촬영입니다. 바이너리에는 UsbServer와 HostInterfaceCommand::DeviceCommandProcessor::ExecuteLinuxShellCommand라는 이름이 있지만, 조사한 초기화와 호출 범위에서는 USB 요청이 RTOS 셸 0x530ff66c에 도달한다는 근거가 없었습니다. 이름만으로 USB 입력이나 SHELLCMD 실행을 입증할 수 없습니다. 외부 연구에서도 방향은 같지만, 그 보고만으로 이 버전의 전체 실행 조건이 확인되지는 않습니다. Ricoh USB 기능 안내

보정 백업이 쓰는 세 경로

보정 백업은 조건에 따라 SD 파일뿐 아니라 내부 eMMC에도 씁니다. 세 경로가 항상 함께 실행되는 것은 아니며, 내부 쓰기는 데이터 검사 결과에 따라 갈립니다.

inf_adj의 backup 분기(0x52564f1c)는 수집 함수 0x52eacfc0을 부릅니다. 이 함수는 BOOT·CPTR·IMAG·MDBL 네 그룹을 모읍니다. 버퍼 구성에 성공하면 생성자가 준비한 파일명 C:\KB%ld.ADJ로 SD에 씁니다.

수집 중 그룹 작업 데이터 검사가 실패하면 재구성 경로에 들어갑니다. 여기서는 상태에 따라 이전 레코드를 먼저 무효화할 수 있고, 새 본문을 내부 eMMC에 쓴 뒤 성공하면 파티션 표를 다시 기록합니다. 이는 최종 SD 파일 쓰기 전에 일어나는 내부 기록입니다. MDBL을 재구성할 때는 보존 함수도 거칩니다. 무선 LAN 조정 객체는 일반 경로 E:\WifiInfo.bin과 별도로 보존 경로 B:\WifiInfo.bin을 두며, B:는 내부 eMMC와 같은 제공자에 연결됩니다.

주의

이 버전의 inf_adj backup은 내부에 흔적을 남기지 않는 백업으로 쓸 수 없습니다. 조정 데이터가 유효하면 SD 파일만 쓰지만, 재구성 분기에 들어가면 내부 eMMC에도 쓰기를 요청합니다.

한계와 남은 과제

  • USB에서 RTOS 셸로 들어가는 경로는 확인하지 못했습니다. Linux 셸 명령 처리기 이름만으로는 입증되지 않습니다.
  • SD 출력 파일이 실제로 올라오는 시점과, 초기화 중 함께 일어나는 다른 기록은 확인 범위 밖입니다.
  • 부팅이 멈춘 바디의 Boot ROM 복구 기능은 아직 확인되지 않았습니다.
