SD 카드에서 셸 명령을 받는 경로

SD의 TTL 스크립트가 sendln을 거쳐 RTOS 셸 명령을 실행하는 코드가 있다. 이 경로는 카메라의 시스템 초기화가 진행돼야 사용할 수 있다. USB에서 같은 셸로 들어가는 경로는 확인하지 못했다. 보정 데이터 백업 명령은 조건에 따라 내부 eMMC에 쓰므로 읽기 전용 백업으로 분류할 수 없다.

SD 파일에서 eMMC 읽기 명령까지

초기화 경로의 0x532fe8d0이 0x533012b8을 호출한다. 이 함수는 메시지 0xA2C08101과 인수 0을 보낸다. 시스템 처리기 0x53318764는 인수가 0이면 dbgparam.ttl의 크기를 검사해 내용이 있을 때 실행을 요청하고, 이어 startup.ttl에도 같은 검사를 한다. 인수가 0이 아닌 쪽은 shutdown.ttl을 확인한다. 세 파일은 모두 C:\script\ 아래에 있으며 C:는 SD 드라이버로 연결된다. C 볼륨과 SD 드라이버

스크립트 처리기는 sendln을 토큰 0x4e로 바꾼다. 분기표의 0x533a27f0은 0x533a2b2c를 가리키고, 그곳에서 호출한 0x533a180c가 문자열을 콜백에 넘긴다. 초기 복사 영역의 포인터 0x53d0de3c → 0x530ffa40과 스크립트 실행기가 넘기는 RAM 주소 0x545260fc가 이 콜백을 특정한다. 셸은 0x530ff66c에서 명령 이름을 찾고 0x530ff840의 간접 호출로 해당 함수를 실행한다. 콘솔 초기화 쪽은 리소스 슬롯 4를 읽어 명령을 등록하며 초기 레코드의 이름은 ShellCmdList다. SHELLCMD 명령 색인 · 명령표 재현 도구

emmc_fread는 일반 영역을 읽어 지정한 파일에 쓴다. sys_fwdump는 정해진 범위를 읽어 C:\fwdump.bin으로 내보낸다. 추적한 두 처리 함수에서 eMMC 데이터 기록 호출은 발견하지 않았다. 출력 파일을 SD로 지정하는 조건에서 두 함수가 후보가 된다. emmc_freadb는 eMMC 부트 파티션을 선택했다가 일반 영역으로 돌아오므로 같은 범주의 읽기 시험에서 분리한다. eMMC 파티션 선택과 복귀

출력 파일이 SD에 생겨도 정상 초기화 도중 내부 로그나 설정을 기록하는지는 별도로 확인해야 한다. 이 스크립트는 RTOS가 실행된 뒤에 읽는다. 부팅이 멈춘 바디의 Boot ROM 복구 기능은 아직 확인되지 않았다.

USB의 셸 진입 경로는 미확인

Ricoh가 공개한 USB 기능은 MTP·CD-ROM 데이터 전송과 테더 촬영이다. 바이너리에는 UsbServer와 HostInterfaceCommand::DeviceCommandProcessor::ExecuteLinuxShellCommand가 있지만, 조사한 초기화와 호출 범위에서는 USB 요청이 RTOS 셸 0x530ff66c에 도달한다는 근거를 찾지 못했다. Linux 명령 처리기의 이름만으로 USB 입력이나 SHELLCMD 실행을 입증할 수 없다. Ricoh USB 기능 안내

PentaxForums에는 K-3 Mark III에서 sendln을 사용한 연구 기록과 디버그 메뉴의 조정 데이터 SD 내보내기에 관한 보고가 있다. 펌웨어 내부 단서와 방향이 일치하지만, 그 보고만으로 무기록 백업이나 이 버전의 전체 실행 조건까지 확인되지는 않는다. 연구자 게시물

보정 백업이 쓰는 세 경로

inf_adj의 backup 분기(0x52564f1c)는 0x52eacfc0을 호출한다. 이 함수가 모으는 그룹은 BOOT, CPTR, IMAG, MDBL이다. 버퍼 구성에 성공하면 0x52ead08c에서 파일 쓰기 함수를 호출한다. 이때 파일명은 생성자가 준비한 C:\KB%ld.ADJ다.

수집 중 그룹 작업 데이터의 검사가 실패하면 0x52eace24가 재구성 경로 0x52eac814에 들어간다. 여기서는 상태에 따라 이전 레코드의 무효화가 먼저 일어날 수 있다. 새 본문은 0x52eac328 → 0x52ff586c → 0x52ff5708을 통해 내부 eMMC에 쓰고, 성공하면 0x52ff5818에서 파티션 표를 다시 기록한다. 최종 SD 파일 쓰기 전에 일어나는 내부 기록이다. 조정 그룹의 쓰기 대상과 인덱스 · 저장 함수의 기존 합성 검증

MDBL을 재구성할 때는 먼저 보존 함수 0x52eaccdc도 거친다. 이 함수는 레코드의 유효 표식과 대응 객체를 확인하고, 경로 조회가 0을 반환하면 파일 쓰기를 요청한다. 무선 LAN 조정 객체의 생성자 0x52ec99a4는 일반 경로 E:\WifiInfo.bin과 별도로 보존 경로 B:\WifiInfo.bin을 둔다. 보존 함수가 사용하는 가상 메서드 0x52eaaf30은 그 보존 경로를 돌려준다. B:는 내부 eMMC와 같은 제공자에 연결된다. 다른 보존 레코드의 경로는 각 객체가 결정한다. B와 R의 볼륨 등록 · 내부 eMMC 제공자

이 버전의 inf_adj backup은 내부 무기록 백업에 사용할 수 없다. 조정 데이터가 유효하면 SD 파일만 쓰는 경로를 따르지만, 재구성 분기에 들어가면 내부 eMMC에도 쓰기를 요청한다.
