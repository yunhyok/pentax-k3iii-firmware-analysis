PENTAX K-3 MARK III · FIRMWARE STATIC ANALYSIS · 2026-11-08

R 파티션의 sector 주소와 하위 I/O

R 볼륨의 두 상수를 FAT와 Emmc의 실제 인수 흐름으로 연결했다. record+0x0c는 시작 sector 오프셋, record+0x10은 총 sector 수다. 선택한 Emmc 경로의 단위는 512바이트이며 실제 매체 배치와 mount 상태는 확인하지 않았다.

두 필드의 의미를 소비자에서 확인

앞선 생성자 분석에서 별도 EmmcPartition 객체의 R 항목은 0x348000과 0x38c000을 volume record에 전달했다. 이번에는 두 값을 사용하는 FAT callback과 Emmc 메서드를 따라갔다. 이 volume record는 FwPartition의 bank record와 다르며 여기서 확인한 값이 RTOS bank 선택을 설명하지는 않는다. 생산자 근거 · 소비자 근거

factory+4의 volume manager는 초기화 pack을 거쳐 FatFileSystem의 0x52f495b0에서 전역 0x54787078에 저장된다. adapter는 이 alias로 R의 record를 조회한다. callback 등록의 실제 저장은 원본 ARM으로 검사했지만 library가 이를 호출하는 시점과 실제 mount 성공은 실행하지 않았다. geometry output helper의 100바이트 복사도 합성 구현이다.

소프트웨어 설정 범위는 sector 기준 [0x348000, 0x6d4000)이고 길이는 0x38c000이다. 현재 장치가 이 범위를 제공하는지, 어떤 파일시스템이 선택되는지, 실제 저장 매체의 물리 주소와 어떻게 대응하는지는 이 결과만으로 판단할 수 없다.

읽기와 쓰기의 정렬 조건은 다르다

Emmc vslot+0x30은 read 0x53297938, +0x2c는 write 0x53297a84에 연결된다. 각 경로의 중간 버퍼 복사량은 chunk sector 수에 기본 block size 512를 곱한다. 반면 sector 주소는 chunk 수만큼 증가한다. 이 두 연산과 하위 진단 문자열의 sector 표기가 512바이트 단위 해석의 근거다. 재정의된 block-size getter는 실행하지 않았다. vtable·곱셈·하위 인수 근거

하위 경계의 인수는 start sector, sector count, buffer다. 하위 반환값 0은 성공으로 바뀌고 비제로는 최대 세 차례의 시도로 이어진다. OS mutex가 0을 반환하거나 this+0x30의 준비 byte가 0인 검사에서는 하위 I/O에 도달하지 않았다. 성공·실패 값은 시험에서 주입했으며 실제 driver나 저장소를 실행하지 않았다.

검사한 경로의 경계 조건

선택한 callback→Emmc 경로는 record+0x10을 읽어 요청 끝과 비교하지 않았다. 마지막 상대 sector 0x38bfff에서 count 2를 요청한 합성 사례는 0x6d3fff, count 2로 하위 stub에 전달됐다. 이는 해당 경로의 관찰이다. 상위 FAT library와 하위 driver의 제약을 조사하지 않았으므로 전체 시스템의 범위 검사 부재나 장치 수용을 뜻하지 않는다. 원본 ARM 25사례

count 0이나 handle 조회 실패는 callback에서 0을 반환한다. 알 수 없는 경로에서 시작 오프셋 getter는 0xffffffff를, geometry getter는 manager+0x1c의 fallback 포인터를 반환했다. 따라서 경로 조회 실패의 총량을 항상 0이라고 일반화할 수 없다. Emmc descriptor+0x18의 후속 비제로 생산자와 Virtual·ExFat의 소비 경로는 아직 미확정이다.

검증과 남은 범위

공개 도구의 원본 ARM 25사례는 RTOS 직접 입력과 통합 decoded 입력에서 동일하게 통과했다. 별도의 로컬 검토 3사례는 32바이트 정렬에서 read와 write의 분기가 다른지, sector 덧셈이 32비트로 순환하는지를 확인했다. 이 3사례는 공개 도구의 25사례에 포함하지 않았다. genuine C 출력 10개와 ARM 957 words의 해시를 로컬에 보존했다.

시험은 작성한 R record, 기본 Emmc vptr, byte+0x14=3, byte+0x44=0을 사용한다. 매체 I/O·OS lock·cache·library lookup·등록 준비·메모리 복사는 명시적 stub이다. read는 합성 바이트를 공급하고 write는 buffer 해시만 기록한다. 초기화·mount·실제 파일 접근·카메라·펌웨어 빌드·플래시는 수행하지 않았다.
