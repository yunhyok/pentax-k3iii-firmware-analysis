K-3 III 색공간 sRGB 글자의 래스터와 픽셀 전송

펌웨어 2.20의 원본 ARM 코드가 색공간 첫 행의 sRGB 글자를 76×40 비트맵으로 만들고, 256×144 합성 RAM 표면에 픽셀 705개를 썼습니다. 각 쓰기의 위치·값·순서와 최종 표면 전체가 독립 계산과 일치했습니다.

원본 실행 순서와 공급한 상태

하네스는 현재 선택 0, 언어 0, 프로필 바이트 0, 부모 사각형 [10,12,180,60]과 타입 5 표면을 공급했습니다. 표면은 한 줄이 256워드인 256×144 합성 RAM입니다. 아이콘과 체크 표시는 앞선 원본 실행으로 1,532개 픽셀을 썼으며, 글자 전송은 이 표면을 이어 씁니다. 두 Latin 글꼴은 원본 decoded에서 읽어 파일 모델이 요청된 버퍼에 전달했습니다. 문자열은 원본 descriptor 0x536f0224과 UTF-16 0x536e6608에서 왔습니다. 선행 행·글꼴·측정 검증

원본 좌표 계산은 텍스트 영역 [110,22,76,40]과 뷰 클립 [110,22,80,40]을 만들었습니다. 교차 영역은 76×40 비트맵 전체를 덮습니다. 측정 뒤 StringView 설정의 63바이트 해시와 그리기 함수가 0x52bedba8..0x52bedbc4에서 스택에 복사한 64바이트 해시는 별도로 확인했습니다. 주소·클립·설정 해시

팔레트가 멈춘 곳과 캐시가 채워진 경로

원본 생성자 0x52a618bc가 옵저버 관리자를 만든 뒤 하네스가 준비 플래그 0x545a1980을 설정합니다. 원본 0x52a6c900은 관리자를 통해 팔레트를 등록하고, 0x52a6c700에서 프로필 0의 ROM과 일치하는 RGB 항목과 32비트 색상 항목 42개를 채웁니다. 확장 팔레트에 필요한 현재 UserData는 확보하지 못했습니다. 그리기 호출에는 준비 플래그 0x545a6c28을 공급했고, 아직 반환하지 않은 팔레트 생성 구간에서 만들어진 값 중 인덱스 26·28만 읽도록 검사했습니다. 두 항목은 프로필 0 생성자의 후속 로컬 쓰기 대상에 포함되지 않습니다. 후속 알림과 생성자 반환은 실행 범위 밖입니다.

원본 0x528c12f8 → 0x528c1f74는 할당된 1,448바이트를 0으로 채웁니다. 그리기 중 0x528c2384는 클립 좌상단의 기존 표면 워드 0x31425364와 팔레트 인덱스 26의 0xffffffff를 받아 빈 캐시에서 새 항목을 만듭니다. 원본 0x528c21f8은 ROM의 float32 가중치를 사용하고, 항목을 복사한 뒤 삽입 인덱스를 0에서 1로 올립니다. 인덱스 28의 0xff000000도 읽지만 실제 비트맵에 이를 직접 쓰는 0xff 샘플은 없었습니다. 팔레트·캐시 관측값

픽셀 전송을 독립 계산으로 대조

원본 글리프 임시 버퍼에서 관찰한 바이트를 Python으로 OR 합성해 3,040바이트 비트맵을 대조했습니다. 전송 계산은 이 비트맵, 원본 가중치, 두 팔레트 워드와 기존 시험 표면에서 시작합니다. 네 바이트 채널별로 float32 곱셈·덧셈 뒤 정수로 잘라 16워드 캐시를 재구성했습니다. 0인 샘플은 기존 픽셀을 보존하고 부분 커버리지는 계산된 캐시 워드를 고릅니다. 이 대조는 원본 글꼴 윤곽선을 별도로 해석하는 실험과 구분됩니다.

원본 전송에서 관찰한 항목결과
0인 샘플2,335개 · 표면 쓰기 없음
부분 커버리지705개 · 0x528c26c8에서 순서대로 쓴 705워드가 전부 일치
0xff 샘플0개 · 이 분기의 원본 직접 쓰기는 실행 범위 밖
최종 147,456바이트표면 전체와 경계 가드가 예상값과 일치

최종 표면 SHA-256은 9567ae794794bf3c9b287bab7a6ff3101a3dd65a965b532e79d4beac8bc31f98입니다. A5·5A 대조에서는 팔레트와 할당 영역의 초기 채움값을 바꿨습니다. 전송 구간의 성공 단언 한 건을 모델로 처리한 두 결과는 채움값만 정규화하면 일치했습니다. 별도의 A5 재생에서는 0x530fdfc4의 성공 경로도 원본으로 실행했습니다. 이때 22,550개 원본 명령이 전송 재개부터 복귀까지 실행됐고, 이 구간에서 모델 호출은 0건이었습니다. 기존 A5 결과와 픽셀 쓰기, 캐시, 팔레트 읽기, 최종 표면이 같았습니다. 세 실행의 원본·모델 기록과 해시

재현 조건과 검증 범위

기록 정정: 최초 공개 JSON의 사례별 표면 높이에 글자 비트맵 높이 40이 잘못 기록됐습니다. 하네스의 변수를 분리해 256×144로 고쳤습니다. 정정 전 전체 관측 기록에서 이 높이만 바꾼 해시와 원본 코드 재실행 결과를 대조했습니다. 원본 명령·메모리 쓰기·최종 표면 해시는 변하지 않았습니다.

Python 3.12와 Unicorn 2.1.4에서 K-3 III 2.20의 78,683,892바이트 decoded 파일을 읽었습니다. 검증기는 도우미 소스를 전부 캡처해 SHA-256을 확인한 뒤 실행하고, 같은 decoded 바이트에서 RTOS·ICONBIN과 글꼴 범위를 읽습니다. 전체 관측 기록의 정규 JSON 해시 세 개를 검증한 다음 공개 JSON을 씁니다. 파일·메모리 할당·앞 단계의 성공 단언 모델은 단계별로 기록돼 있습니다.

python -B tools/verify_colorspace_text.py decoded.bin --output colorspace-text-replay.json
python -B -m unittest discover -s tests -p test_verify_colorspace_text.py

이 재현은 준비된 첫 행의 글자와 합성 RAM 전송을 검증합니다. 실제 LCD의 픽셀 해석, 시작 시 팔레트 초기화, 메뉴 이벤트와 설정 저장, 다른 기종의 UI 이식은 별도 검증이 필요합니다. 재현 CLI · 텍스트 실행과 독립 계산 · 입력·출력 보호 검사 · 세 기종 이식 검증 조건
