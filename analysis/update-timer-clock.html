TTimPeriod에서 64비트 카운터까지

예약 시각 계산에 쓰이던 전역 값의 생산자를 내장 설정과 연결했다. 내장 기본값 1과 파싱된 32비트 값의 허용 범위 1~50은 확인했으며 실제 시간 단위와 타이머 주파수는 미확정이다.

상위 시각 계산설정 생산자레지스터 기록검증 범위

같은 전역 값이 예약 보정과 카운터 증가에 쓰인다

  1. 내장 설정
    0x533e3138
  2. TTimPeriod 읽기
    0x525d91fc
  3. 전역 값 기록
    0x54c40580
  4. 64비트 카운터 증가
    0x54c40e50

설정 초기화의 0x525d6efc는 내장 테이블 포인터 0x533e3138을 0x54c405a4에 저장한다. 이 테이블의 0x533e3244에서 TTimPeriod 값 1을 확인했다. CPU 시험에서는 이 전역 포인터를 직접 설정한 뒤 원본 파서로 값을 읽었다. 초기화 함수의 실제 startup 호출과 이후 설정 교체 여부는 검증하지 않았다. 생산자·테이블·명령 근거

타이머 초기화 0x525b7e64는 용량 1인 출력 0x54c40580으로 값을 읽는다. 읽기 결과가 0 이하이거나 u32(period − 1) > 49이면 0xfffb0000을 반환한다. 따라서 이 검사에서 허용하는 값은 1~50이다. 허용 경로는 두 64비트 값과 타이머 목록을 초기화한다. 시험은 다음 호출 직전인 0x525b7ec8에서 멈췄으므로 전체 초기화 성공을 뜻하지 않는다.

Wrapper·숫자 reader·키 검색·token·숫자 변환과 strlen·memcmp helper를 원본 ARM으로 실행했다. 파서 대체 함수는 사용하지 않았다. 없는 키와 빈 키는 0xffd60000, 값 없는 키는 0을 반환했다. 합성 입력에 값 두 개를 주고 출력 용량을 1로 제한하면, 첫 값만 저장하면서 반환 개수는 2가 된다. 선택한 입력만 검증했으며 전체 파서 문법과 모든 오류 입력을 검증한 것은 아니다.

0x525b810c..0x525b8140의 명령은 NOW64 = (NOW64 + u32(period)) mod 2⁶⁴를 수행한다. 상위 예약 시각·남은 시간 계산에 쓰이는 주소와 같다. carry와 64비트 순환을 합성 입력으로 확인했으며 이 명령을 실행하는 실제 IRQ 진입·주기·전달 경로는 이번 시험에 포함하지 않았다.

보드 함수 0x525b5b4c는 descriptor에 초기화 0x525b5bf0와 후속 callback 주소를 저장한다. 주소 저장은 정적으로 확인했지만 전체 startup에서 해당 descriptor가 선택되는 과정은 실행하지 않았다. 아래 순서는 초기화 함수를 별도로 호출해 MMIO 주소를 일반 에뮬레이터 RAM으로 매핑한 결과다.

Ricoh 공개 소스의 milbeaut-timer.c는 제어·카운터·reload 레지스터를 상대 오프셋 0·4·8·12로 정의한다. 이 배열은 관측 주소를 해석할 보조 근거다. 다만 Linux DTS가 사용하는 채널은 0x1e000050/60이고 rclk도 분주 설정을 거친다. 이 자료만으로 RTOS의 0x1e0000d0 채널 주파수나 시간 단위를 확정할 수 없다. Ricoh 공식 소스 배포본 · 파일 해시와 대조 범위

20사례와 남은 연결

초기화 입력 9사례, 빈 키·내장 값·출력 용량 각 1사례, 64비트 덧셈 6사례, 합성 레지스터 기록 2사례가 RTOS·decoded 입력에서 동일하게 통과했다. period = 0xffffffff인 덧셈 시험은 초기화 검사가 거부하는 값을 직접 넣은 경계 시험이며 실제 생산자의 증거가 아니다. 20사례 결과

genuine C 8개와 지원 범위 5개, ARM 414 words를 로컬에 저장했다. 디컴파일 C의 잘못 복원된 변수·분기는 수정하지 않고 원본 ARM과 실행 결과로 판단했다. 기존 UI 타이머 39사례와 커널 ABI 17사례는 그대로 유지한다.
