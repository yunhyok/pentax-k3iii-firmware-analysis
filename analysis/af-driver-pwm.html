AF 드라이버와 PWM 연결

K-3 III 펌웨어 2.20에서 PafMotor의 리셋 요청은 AfMotorDriver를 거쳐 두 PWM 객체로 전달됩니다. 원본 코드에서 객체 등록을 추적하고, 드라이버가 이벤트를 받아 플래그를 쓰거나 다시 전달하는 동작을 따로 재생했습니다.

리셋 요청과 이벤트의 객체 경로

  • 0x5317757c는 가드 0x547bc23c를 확인하고 AfDeviceFactory 0x547bc240을 반환합니다. factory vtable +8의 원본 대상 0x531777a4는 별도 AfMotorDriver singleton 0x547bc258을 가져와 0x531777f8에서 factory +4에 둡니다. 0x52f0b3f4와 0x52f07b68은 그 포인터를 각각 PafMotor +8과 Joint +0xd4에 저장합니다.
  • PwmFactory는 0x5326ce64와 0x5326cedc에서 0x38바이트 객체를 각각 할당합니다. 공통 생성자 0x5326c03c는 레지스트리 등록 경로와 이벤트 번호를 설정합니다. 레지스트리 키는 0xe0/0xe1, 이벤트는 0x12f/0x130입니다. PWM의 런타임 번호 +0x24는 별도 전역 카운터에서 가져옵니다.
  • AfMotorDriver vtable +8의 0x531779b0 경로는 두 레지스트리 키를 조회하고 원본 RTTI의 Pwm 형으로 변환합니다. 반환 포인터는 0x53177b9c와 0x53177bd0에서 드라이버 +0x2c/+0x30에 저장됩니다. 조회 결과가 0이면 해당 슬롯에 0을 기록합니다. 객체 이름과 vtable은 원본 RTTI와 ROM 구간으로 확인했습니다.

원본 주소·구간 해시와 실행 기록

같은 PafMotor를 가리키는 별칭

AfMotorFactory의 +0xc는 PafMotor를, +0x10은 별도 PafPulse를 가리킵니다. factory의 첫 확인 호출은 각 객체의 vtable +8을, 별도 바인더 호출은 vtable +0xc를 읽습니다. PafMotor 포인터는 Joint +0xdc, Debug +0x1c, LensInfo +0x18, PafMovableObject +0x14, Pulse +0x10에서도 확인됩니다.

원본 ARM에서 Motor의 vtable +8 호출은 r0=1로 돌아왔습니다. 별도 바인더 호출은 같은 객체를 r6에 두고 0x52f0b394 서비스 호출 직전에 멈췄습니다. Joint의 주소 계산과 +0xdc 저장을 별도 구간에서 재생한 뒤, 그 포인터로 Motor +0x44를 Joint +0x90에 복사하고 Motor +0x3c == 3의 결과를 Joint +0x94에 기록하는 두 대조를 확인했습니다. factory 슬롯과 상태값은 시험에서 준비했고, 두 경우 모두 Motor 0xec바이트가 그대로였습니다.

Motor 코드 0x52f0b354–0x52f0ddb4의 10,848바이트에서 STR·STRB·STRH 328개를 폭과 변위로 검사했습니다. +0x56/+0x68의 반워드와 겹친 고정 변위 저장 두 개는 생성자의 0 초기화입니다. 인덱스를 사용하는 두 저장은 Pulse +0xa6a를, 주소를 함께 갱신하는 한 저장은 스택을 가리킵니다. 이 검색은 외부 호출, 간접 포인터 쓰기와 Thumb까지 닫는 전수 분석이 아닙니다. 두 필드에 0이 아닌 값을 넣는 경로는 미확인입니다.

리셋이 PWM에 넘기는 레코드

Joint의 리셋 호출 0x52f08214는 PafMotor를 거쳐 0x52f0b9a4에서 r1=0으로 드라이버 0x5317817c에 진입합니다. 드라이버는 12바이트 입력을 만들고 바이트 +8에 0을 지정한 뒤 두 PWM 객체에 전달합니다. 0x5326ca24는 각 PWM 객체 +0x2c의 12바이트 레코드를 복사하고, 입력에서 유지값으로 지정한 필드를 제외한 값을 병합합니다. 두 반워드는 0, 대부분의 바이트는 0xff에서 기존 값을 유지합니다.

0x5326c7c4는 이 12바이트 병합값에서 별도의 16바이트 스택 레코드를 구성합니다. 0x5326c7f8부터 네 워드를 지우고 변환한 필드와 테이블 워드를 기록한 다음, 0x5326c8f4에서 PWM 번호와 스택 레코드 포인터를 하위 함수에 넘깁니다. 하위 코드는 RAM을 갱신한 뒤 0x53349644에서 0x1e000000 기반 주소를 읽습니다. 드라이버에 r1≠0으로 들어오면 앞선 정지 경로의 첫 레지스터 읽기는 0x53349b9c입니다. 두 레지스터 접근은 정적으로 확인했습니다.

드라이버의 두 적용 호출 사이에는 반환값으로 분기하는 코드가 없습니다. 적용 내부의 하위 호출은 0x5326c8f8와 0x5326c96c에서 각각 반환값을 검사합니다. 여기서는 주변장치의 응답이나 리셋 성공을 재생하지 않았습니다.

드라이버 콜백 재생 7건

드라이버는 PWM 리스너에 AfMotorDriver+4를 이벤트 0x12f/0x130의 수신자로 등록합니다. 콜백 0x53177928은 수신자 주소에서 4를 빼 원래 드라이버를 찾습니다. Joint는 같은 드라이버의 리스너에 자기 +0xc0을 별도 ID 네 개로 등록합니다. 이 전달 경로의 원본 Joint 콜백은 0x52f07de4에서 0xc0을 빼며, 그중 0x3d의 일부 분기는 Joint +0xdc를 통해 PafMotor에 접근합니다.

원본 드라이버 생성자의 후반부에서 두 vptr과 플래그를 초기화한 뒤, ROM 슬롯이 가리키는 콜백을 개별 호출했습니다. 일곱 이벤트 값은 하네스가 직접 공급했습니다. 플래그는 각 사례 직전에 0으로 두었고, 반환은 하네스가 둔 0x20000000에서 확인했습니다. 실제 리스너 목록과 등록 성공 상태는 공급하지 않았습니다.

이벤트원본 명령관측한 결과
0x12f21드라이버 +0x44에 1을 기록하고 반환
0x13024드라이버 +0x45에 1을 기록하고 반환
0x13124드라이버 쓰기 없이 반환
0x3d/0x58/0x5f/0x6712/14/16/18객체 쓰기 없이 0x5317791c의 리스너 가상 호출 직전에 정지

Cortex-A7 기본 조건, Cortex-A7과 A15에서 초기 일반 레지스터·NZCV를 바꾼 조건에서 일곱 사례씩, 총 21건의 로컬 실행 결과가 일치했습니다. 서비스 반환과 MMIO를 대체하는 훅은 사용하지 않았습니다. 실제 초기화 순서, PWM 인터럽트의 생성, 전달 이후의 리스너 실행, 두 채널의 물리적 역할은 검증 범위 밖입니다.

원본 재현

저장소 루트에서 Python, Unicorn 2.1.4와 Capstone 5.0.7로 실행합니다. 원본 decoded 또는 RTOS 파일을 지정하고 출력은 새 경로에 둡니다. 입력 길이와 SHA-256, 보조 코드 두 개의 SHA-256을 검사합니다. 두 전체 관측 기록의 SHA-256을 확인한 뒤 공개 JSON을 만들며, 이 JSON에는 원본 바이트나 전체 디스어셈블리 대신 주소·범위 해시와 재생 결과를 남깁니다.

python -B verify_af_driver_pwm.py decoded.bin --output af-driver-decoded.json --compare analysis/af-driver-pwm-checks.json
python -B verify_af_driver_pwm.py rtos.bin --output af-driver-rtos.json --compare analysis/af-driver-pwm-checks.json
python -B -m unittest discover -s tests -p test_af_driver_pwm.py
