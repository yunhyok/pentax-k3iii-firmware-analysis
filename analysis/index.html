셸 명령 957개의 분류와 호출 관계

카메라 본체 운영체제는 셸 명령 957개를 가지고 있습니다. 이 명령들이 무엇을 담당하는지 분류하고, 촬영·AF·영상처리 명령이 실제로 어떤 함수를 부르는지 원본 기계어로 따라갔습니다.

핵심 요약

  • 셸 명령 957개를 주 기능 기준으로 17개 군으로 나눴습니다. 영상처리 189개, 촬영 130개가 가장 많고 우선 조사 분야인 촬영·AF·영상처리를 주 기능으로 가진 명령은 364개입니다.
  • 각 명령 진입점에서 C 형태의 의사코드를 자동 생성하고 촬영·AF·영상처리에서 함수 36개를 골라 원본 기계어와 대조했습니다. 가장 구체적으로 복원한 것은 두 측거 결과를 합치는 조건과 영상 진단용 톤 변환표입니다.
  • 호출·분기 위치 17,914곳을 원본 바이트에서 독립 확인했습니다. 자동 디컴파일 결과는 타입·이름을 완전히 복원하지 못하므로, 판단은 기계어 대조를 우선합니다. 카메라에서 실행한 것은 없습니다.

확인 바이트 대조로 확인

  • 호출·분기 위치 17,914곳의 명령 유형·직접 목적지
  • 상세 대조한 함수 36개와 보조 구간 6개의 구간 해시
  • 957개 분류의 재현(원본 명령표 기준)

  • 디포커스 결합 조건, 톤 변환표 수식

모델 시험 조건으로 정한 것

  • 탐색 창 상한은 다음 명령 진입점 주소
  • 간접 호출은 복귀 가능으로 모델링

미확인 확인하지 않은 것

배경: RTOS 셸 명령이란

이 카메라는 RTOS와 Linux가 함께 돕니다. RTOS에는 내부 점검·개발용으로 쓰이는 셸 명령 목록이 들어 있습니다. 펌웨어의 SHELLCMD 레코드에 957개 항목이 있고 각 항목은 명령 이름과 처리 함수 주소를 가집니다.

957개 명령에 주 기능을 하나씩 지정해 분류하고 촬영·AF·영상처리 명령의 처리 함수를 원본 기계어와 대조해 어떤 동작을 하는지 복원했습니다.

참고

분류는 명령 이름과 계열, 처리기가 참조하는 도움말과 인수를 근거로 했습니다. 예를 들어 ID 717·718의 도움말은 스위치 입력 에뮬레이션을 명시합니다. 그래서 이 표에서 조작계로 분류한 명령이 실제로 물리 스위치를 읽는다고 단정할 수는 없습니다.

957개 명령의 분류

영상처리와 촬영이 전체의 3분의 1을 차지합니다. 우선 조사 분야인 촬영·AF·영상처리를 주 기능으로 가진 명령은 364개입니다.

보조 기능까지 포함해 세면 촬영 142개, AF 61개, 영상처리 215개로 모두 418개입니다. 나머지 539개도 자동 디컴파일했습니다. 분류 결과와 근거는 표로 공개합니다.

촬영과 AF는 같은 제출 함수를 지난다

촬영(ID 30)과 AF(ID 39)는 같은 공통 제출 함수를 불러, 같은 메시지 번호로 디스패처에 요청을 넘깁니다. 첫 인수 값만 1(촬영)과 2(AF)로 다릅니다.

촬영 제어의 대표 명령 셋을 짚어 봅니다. ID 30은 캡처·릴리스 요청입니다. ID 391 AE_Capture는 상태에 따라 프레임 수를 정해 버퍼를 요청하는 측광 프레임 덤프입니다. ID 710 shtrctrl_bulb는 별도 벌브 진단 경로입니다.

AF 명령과 디포커스 결합 조건

AF 모드·영역 설정 명령과, 두 측거 결과를 하나로 합치는 함수의 조건을 복원했습니다. 차이가 60을 넘으면 결합을 건너뜁니다.

AF 명령에서는 AF 모드 설정(ID 242는 요청 ID 0, 설정 항목 0x57에 single=1·continuous=2 기록), 위상차 AF 플래그 설정(ID 336은 유효 객체의 +0x89에 0 또는 1 기록), 디포커스 조회(ID 335 GetDefocus)를 확인했습니다. GetDefocus는 저장 레코드가 유효하지 않으면 0x7fffffff를 반환하고 유효하면 기존 디포커스 값을 읽습니다.

이 설명은 32비트 덧셈·뺄셈이 넘치지 않는 입력 범위에서 성립합니다. 60의 광학 단위와, 이 함수가 GetDefocus와 직접 생산·소비 관계인지는 확인하지 않았습니다. 두 함수가 같은 슬롯 번호를 쓴다는 사실만으로 연결하지 않았습니다.

영상처리: 톤 변환표와 노이즈 감소

영상 진단 명령의 톤 변환표 생성 수식을 디스어셈블에서 복원했습니다. 입력과 출력이 뚜렷해 호스트에서 결과를 재현할 수 있습니다.

ID 698 IQ_tone은 진단 파일을 처리하는 명령으로, 하위 함수 0x530b6810에서 16비트 항목 256개짜리 변환표를 만듭니다. 중간 구간의 연산을 ARM·VFP 명령과 리터럴 상수에서 복원했습니다. 유효한 입력 순서 lo < mid < hi에서 다음과 같이 계산합니다.

  • left = mid - lo, right = hi - mid, q = min(left, right) / (hi - lo)
  • p = 2.5q² + 0.55q + 0.1. left ≤ right이면 지수는 p, 반대면 1/p
  • 입력 i ≤ lo에는 0, i ≥ hi에는 255를 기록하고 그 사이는 trunc(0.5 + 255 × ((i-lo)/(hi-lo))^지수)

진단 기본값 lo=15, hi=240, mid=128에서는 지수가 1.0068115입니다. 호스트에서 반올림을 재현하면 입력 15, 64, 128, 200, 240은 각각 0, 55, 127, 209, 255가 됩니다. 이것이 일반 JPEG 촬영의 기본 톤 곡선인지는 확인하지 않았습니다.

ID 692 IQ_nr(노이즈 감소)는 다중 스케일 작업 버퍼를 배치하고 네 하위 경로와 톤 경로가 완료 처리 함수 0x530be7dc를 공유합니다. 공통으로 확인한 범위는 완료·오류 처리까지입니다. 픽셀별 노이즈 필터와 ISP/DSP 내부 산술은 미확인입니다.

호출표를 읽는 방법

함수가 어디서 무엇을 부르는지 정리한 호출표는 17,914행입니다. 각 행에서 호출자, 명령 위치, 종류, 목적지를 읽을 수 있습니다.

일괄 분석에서 찾은 호출·분기를 기준으로, 상세 추적에서 추가한 위치까지 합친 표입니다. 같은 함수가 여러 곳에서 같은 대상을 부르면 각 위치를 따로 셉니다.

일괄 분석이 찾은 전달 위치
종류개수뜻
직접 호출17,346목적지가 정해진 호출(Thumb 전환 포함)
레지스터 호출350목적지가 레지스터로 정해지는 미확정 호출
창 밖 분기15분석 창 밖으로 향하는 분기

상세 대조 범위는 경계 주소가 서로 다른 디컴파일 함수 36개와 추가 역어셈블 구간 6개입니다. 각 구간에는 시작·끝 주소와 원본 바이트의 SHA-256을 붙였습니다. 957개 일괄 분석은 각 명령 진입점에서 제어흐름 그래프를 만들고 다음 진입점 주소를 탐색 상한으로 썼습니다. 마지막 명령의 상한은 다음 별도 프롤로그 0x525b2cd8이고 스택 보호 실패 함수 0x532fb9c8은 종료점으로 취급했습니다.

탐색 창에는 리터럴이나 다른 코드가 섞일 수 있으므로 창 안의 코드 비율을 소스 복원율로 쓰면 안 됩니다. 예를 들어 요청 전송 함수는 484바이트 중 432바이트, 셔터 드라이버 구간은 180바이트 중 60바이트만 해당 그래프에 나타났습니다. 나머지는 전체 ARM 목록과 직접 대조했습니다. 자동 생성한 C에는 타입·호출 규약 오인과 분기 누락이 있습니다. 그래서 재현할 때는 입력 바이트·명령 주소·호출 목적지를 먼저 대조합니다. TSV의 cfg_bytes·window_bytes는 그래프와 창의 크기, c_sha256은 저장한 C 텍스트의 해시입니다.

재현 방법

먼저 기본 분석 절차로 이 버전의 decoded.bin을 만듭니다. 다음 두 명령은 Python 표준 라이브러리만 씁니다.

python rtos_catalog.py .private/my-decode/decoded.bin --output .private/my-commands.tsv
python verify_command_analysis.py .private/my-decode/decoded.bin

첫 명령은 이름·주소·분류를 결합한 957행 TSV를 만듭니다. 두 번째 명령은 분류, 상세 구간 해시, 17,914개 위치의 ARM 명령 유형과 직접 분기 목적지를 바이너리에서 독립 확인합니다. 이 검증은 기계어와 기록의 일치를 보며 모든 함수의 의미를 판정하지는 않습니다.

개별 명령의 의사코드는 angr==10.0.5 환경에서 ID 또는 주소로 다시 생성합니다. 출력은 C 형태의 의사코드입니다.

python decompile_sample.py .private/my-decode/decoded.bin 39
python decompile_sample.py .private/my-decode/decoded.bin 0x530b6810

상용 디스어셈블러로 원시 RTOS 이미지를 여는 시도는 unsupported binary format으로 실패했습니다. 그래서 확인한 적재 주소 0x52500000에서 angr와 Capstone으로 읽었습니다. 카메라 실행이나 플래싱은 하지 않았습니다.
