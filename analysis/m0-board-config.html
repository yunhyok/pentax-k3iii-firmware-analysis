각 본체는 Thumb 명령 384개로 구성된다. 32비트 store 125회가 고유 주소 123곳에 기록하며 20,000에서 0까지 감소하는 반복문 2개가 있다. 여섯 본체의 store 주소 순서는 같고 일부 기록값이 다르다. 이 구간의 load는 모두 원본 literal을 읽으며 외부 호출이나 MMIO 값에 따른 분기는 없다. 20,000회는 명령상의 횟수이며 실제 대기 시간은 측정하지 않았다.

여기서 검사한 것은 여섯 본체의 코드 범위다. 실제 카메라의 보드 선택값, 해당 레지스터의 writable bit·readback·side effect는 확인하지 않았다. 본체가 기록하는 주소와 값 전체는 로컬 분석 자료에 보존하고 공개 결과에는 범위·해시·필요한 비교값만 기록했다.

앞선 OR 기록과 뒤의 상수 기록을 구분한다

초기 setup은 0x3ffe0838 뒤에 보드 선택기를 호출한다. 따라서 앞의 OR 연산만 보고 최종 기록값이 다른 bit를 유지한다고 설명할 수 없다. 뒤의 보드 본체는 0x4dffb208에 상수 0x20을 쓴다. 실제 레지스터가 모든 bit를 저장하는 일반 RAM처럼 동작하는지는 별도 문제다. 명령 순서 근거.

같은 보드 본체는 0x4d021090에 0x3f를 쓴다. 기존에 추적한 적재 helper는 0x3fffa800의 entry가 비제로일 때 벡터 0x20000000, 진입 주소 0x20000020, 모드 0x2000fffc를 준비하고 DSB 뒤에 0xf3f를 쓴다. 두 기록값의 차이는 0xf00이다. 이를 특정 코어의 해제 비트나 remap 비트라고 명명할 근거는 아직 없다. 이 순서는 조건부 코드 연결이며 전체 reset·작업 스케줄링·진입점 실행을 재현한 결과가 아니다. 기존 적재·모드 경로.

공식 소스의 CLK_CRRRS와 비교할 수 있다

Ricoh가 배포한 Linux 소스의 arch/arm/mach-milbeaut/snapshot.c는 46행에서 CLK_CRRRS_OFFSET=0x90을 정의하고 2602행에서 base 0x1d021000을 매핑한다. 2630행과 2733행은 그 위치를 읽고 복원한다. 따라서 해당 소스가 사용하는 주소는 0x1d021090이다. archive member·SHA-256·행 번호.

M0의 0x4d021090과는 0x30000000 차이다. 이 비교는 주변장치 주소 대응의 단서이며 동일한 물리 레지스터임을 실측한 결과는 아니다. 특히 SRAM 후보 주소의 차이는 0x1f000000이므로 이 주변장치 차이를 SRAM에 그대로 적용하지 않는다. 공식 소스의 이름도 각 bit의 기능이나 선행 ROM의 인증 정책을 설명하지는 않는다. SRAM 주소 연결의 기존 근거와 한계.

0x4dffb208에는 pin 제어 후보가 있다. 같은 배포본의 sc2000.dtsi는 주석 처리된 디버그용 CM0 pinctrl 노드에 base 0x1dffb000을 적는다. 대응 드라이버 pinctrl-mlb01-cm0.c는 EPCR=0x200, 레지스터당 pin 16개를 정의하며 GPIO 선택 시 해당 bit를 지우고 그 밖에는 설정한다. 이 주변장치 주소 대응이 성립한다면 +0x208의 bit 5는 드라이버의 pin index 37에 해당한다. 이 해석은 조건부 소스 비교이며 활성 DT 노드, 실제 패키지 pin 번호 또는 선택된 주변장치 기능을 확인한 결과가 아니다.
