RTOS 명령과 셸 · 셔터와 AF 연산

공통 요청에서 셔터 GPIO와 AF 연산까지

촬영과 AF 요청은 같은 통로로 디스패처에 전달됩니다. 그 뒤 셔터 제어가 전기 신호를 내보내는 지점과, AF가 초점을 계산하는 실제 연산까지 따라갔습니다.

핵심 요약

  • 촬영·AF 요청이 공통 메시지로 수신기에 도달한 뒤 촬영 이벤트와 AF 이벤트로 갈라지는 분기를 확인했습니다. 다만 이벤트에서 실제 셔터·AF 동작으로 이어지는 중간 상태 전이는 아직 연결하지 못했습니다.
  • 셔터 제어 코드가 특정 조건에서 GPIO 레지스터에 값을 쓰는 지점을 특정했습니다. 각 핀이 선막·후막·플래시 중 무엇인지는 회로도나 실측이 있어야 합니다.
  • AF의 상관 연산에 쓰이는 SAD·SSD 함수를 에뮬레이터에서 실제로 실행해 기준식과 일치시켰습니다. 광학 단위, 렌즈 보정, 최종 렌즈 구동은 미확인입니다.

확인 원본 코드 실행·바이트 대조로 확인

  • SAD·SSD 함수를 합성 입력 72개에서 기준식과 대조
  • 구간 1,232개·호출 7,389개·상수 492개·간접 연결 104개 재계산

정적 분석 디스어셈블을 읽어 판단

  • 수신 분기, 이벤트 번호, 셔터 작업 스레드 경로
  • AF 팩토리 객체와 상관·디포커스 호출 순서
  • GPIO 쓰기 값(초기화된 레지스터·마스크로 계산)

모델 시험 조건으로 정한 것

  • SAD·SSD 입력은 합성 배열, CPU는 Unicorn Cortex-A7
  • 간접 호출 대상은 문서화된 생성자 조건에 의존

미확인 확인하지 않은 것

  • 이벤트에서 셔터·AF로 가는 런타임 상태 전이
  • 물리 핀 대응, 실제 기계적 셔터·합초 결과

배경: 요청이 디스패처로 가는 구조

촬영 버튼이나 AF 요청 같은 사용자 동작은 셸 명령으로 들어와, 하나의 공통 제출 함수를 거쳐 디스패처로 전달됩니다. 이 공통 통로는 명령 전체 지도에서 다뤘습니다. 이 문서는 요청이 디스패처에 도달한 다음을 추적합니다.

요청은 공통 메시지로 수신기에 도달해 촬영·AF 이벤트로 갈라지고 이벤트 큐를 거쳐 현재 제어 객체의 가상 함수로 넘어갑니다.

공통 메시지에서 촬영·AF 이벤트로

공통 제출 경로는 메시지 0x46020102를 만들어 보냅니다. 수신기는 이 메시지를 받아 요청 ID 3을 고르고 첫 인수 값에 따라 촬영(1)과 AF(2)로 갈라집니다. 촬영 시작은 이벤트 0x49, AF 시작은 이벤트 0x11을 큐에 넣습니다.

이벤트 큐는 하나의 공용 객체를 씁니다. 소비 함수는 현재 제어 객체를 얻어 가상 함수 슬롯 +0x24를 부릅니다. 기본 제어 객체의 이 슬롯 값은 확인했지만 실행 시 선택되는 파생 객체와 그다음 동작은 상태에 따라 달라집니다. 촬영·AF 이벤트에서 아래의 셔터·상관 연산으로 이어지는 전체 연결에는 이 상태 전이 구간이 남아 있습니다.

셔터 제어 객체에서 GPIO 쓰기까지

벌브 시작 함수가 작업 스레드를 깨우면, 스레드가 GPIO 드라이버의 가상 함수를 거쳐 특정 레지스터 주소에 값을 씁니다. 쓰기 뒤에는 ARM의 메모리 동기화 명령(DSB)이 옵니다.

조사한 보드 매핑 7개 중 6개는 논리 번호 0x62를 드라이버 등록 키 0x8d로, 0x0e를 키 0x36으로 연결합니다. 이 초기화가 선택된 조건에서 아래 쓰기가 일어납니다. 값은 초기화된 레지스터 주소와 마스크로 계산한 정적 결과입니다.

주의

이 분석으로 셔터 제어 코드가 도달하는 전기적 인터페이스를 특정했습니다. 다만 각 핀이 선막·후막·솔레노이드·상태 접점 중 무엇인지, 벌브 진단 경로가 일반 촬영에서도 실행되는지는 회로도나 실측으로 확인해야 합니다. 플래시 신호명 EXT_STRB_FT를 셔터 액추에이터에 직접 연결하는 근거로 쓰지 않았습니다.

AF 객체 생성과 실제 수치 연산

AF 팩토리가 만든 세 객체 중 Predictor가 상관 결과를 받아 보정하고 그 값을 디포커스로 변환해 저장합니다. 상관 단계의 핵심 함수(SAD·SSD)는 에뮬레이터에서 실제로 실행해 확인했습니다.

예측기는 상관 결과 후보를 꺼내 16비트로 보정하고 디포커스 변환을 부릅니다. 변환은 설정·렌즈 값으로 곱셈과 스케일 조정을 한 뒤, 크기 값을 0xffff로 제한해 객체 +0x0e에 16비트로, 부호 있는 결과를 +0x10에 32비트로 저장합니다. 광학 단위, 렌즈 보정 계수 전체, 최종 렌즈 구동 명령은 추가 분석 대상입니다.

SAD·SSD 상관 함수

상관에 쓰이는 0x52c73190 함수는 부호 없는 16비트 배열 두 개에 대해 SAD와 SSD를 계산합니다. NEON 명령으로 여러 값을 한 번에 처리하므로, 마지막 벡터를 읽을 때 배열 끝을 조금 넘겨 읽을 수 있어 패딩 메모리가 필요합니다.

쉽게 말하면

위상차 AF는 센서가 받은 두 상(像)을 조금씩 밀어 가며 가장 잘 겹치는 위치를 찾습니다. 두 상의 차이를 재는 것이 SAD·SSD이고 차이가 가장 작은 밀림량이 초점이 얼마나 어긋났는지를 알려 줍니다.

원본 커널 바이트를 Unicorn의 Cortex-A7 모델에서 독립 실행했습니다. 양수 길이 1~129 중 18가지에 같은 값·최대 차이·교대 값·난수를 조합한 72개 사례에서 기준식과 일치했습니다. 8개 단위 경계의 앞뒤, 0이 아닌 패딩, 32비트 넘침을 포함합니다. 0·음수 길이의 의미는 이 범위에서 검증하지 않았습니다.

참고

이 함수를 C로 다시 만들어 원본과 더 넓게 대조한 결과는 수치 함수 C 재구현에 있습니다. angr의 VEX 실행은 특정 NEON 명령(Iop_PwAddL16Ux8)을 지원하지 않아 실패해, 수치 검증에는 Unicorn을 사용했습니다.

검증 범위

정적 근거는 원본 RTOS 바이트에서 전부 다시 계산해 확인했습니다. 다만 실기에서 이 경로가 실제로 실행됐다는 뜻은 아닙니다.

현재 근거 파일에는 함수·데이터 구간 1,232개, 호출·분기 위치 7,389개, 상수·포인터 단어 492개, 생성자 근거를 붙인 조건부 간접 연결 104개가 들어 있습니다. 검증기는 RTOS의 SHA-256을 먼저 대조한 뒤 이 전부를 원본 바이트에서 다시 계산해 일치를 확인합니다. 각 간접 연결은 현재 객체가 해당 생성 경로에서 만들어졌다는 조건을 유지합니다.

주의

구간 해시·명령 목적지·함수 포인터 단어를 검사하는 것은 저장한 근거의 재현성을 확인합니다. 현재 제어 객체와 보드 선택, 비동기 콜백이 특정 촬영에서 실제 실행됐다는 의미는 별도의 실기 추적으로 확인해야 합니다. 카메라·렌즈를 구동하거나 펌웨어를 변경하지 않았습니다.

재현 방법

기존 추출기로 만든 decoded.bin을 입력합니다. 첫 검증기는 Python 표준 라이브러리만, 둘째는 unicorn==2.1.4를 씁니다.

python verify_deep_analysis.py .private/my-decode/decoded.bin
python verify_numeric_kernels.py .private/my-decode/decoded.bin

추가 진입점의 의사코드는 angr==10.0.5 환경에서 주소로 다시 생성할 수 있습니다. 텍스트 구조는 도구 상태에 따라 달라질 수 있으므로 바이트·호출 위치를 우선 비교합니다.

python decompile_sample.py .private/my-decode/decoded.bin 0x52cde650 > .private/paf-predictor.c
python decompile_sample.py .private/my-decode/decoded.bin 0x5312cd40 > .private/color-matrix.c
