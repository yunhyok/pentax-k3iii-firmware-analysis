PafPulse 기준값의 쓰기 경로

K-3 III 펌웨어 2.20에서 AF 위치 계산이 PafPulse+0xa88을 갱신합니다. 네 쓰기 지점 중 두 경로를 원본 ARM으로 실행했고, 별도로 시작한 요청 3의 계산이 같은 객체의 새 값을 읽었습니다.

이 문서에서

  1. 생산자와 소비자가 공유하는 객체
  2. 기준값을 갱신하는 네 명령
  3. 두 쓰기 경로와 별도 요청 3 계산을 네 번 재생했습니다
  4. PafMotor의 두 halfword는 비영값 출처가 남아 있습니다
  5. 재현 조건과 실기 검증 범위

생산자와 소비자가 공유하는 객체

AfMotorFactory 초기화의 원본 0x52f08c74부터 PafMotor 0xec바이트가 factory +0xc에, PafPulse 0xab4바이트가 +0x10에 배치됩니다. 두 객체의 ROM vtable +0xc는 각각 0x52f0b380, 0x52f0dde0을 가리킵니다. 이번 재생에서는 원본 생성자와 두 바인더를 실행했고 전체 cold 초기화 대신 필요한 factory 슬롯을 준비했습니다.

원본 0x52f0b46c가 PafMotor +0x14에 Pulse를, 0x52f0dea4가 Pulse +0x10에 PafMotor를 기록합니다. PafControl의 0x52cad944도 같은 factory 슬롯에서 Pulse를 읽어 자기 +0x34에 기록합니다. 실행 기록과 원본 구간 해시

기준값을 갱신하는 네 명령

아래에서 M은 PafMovableObject, P는 PafPulse입니다. d는 원본 0x52cbeba4가 만든 보정값입니다. M +0x148의 signed word 절댓값에 M +0x3c의 부호를 적용하고, PafControl +0x74의 값이 1이면 부호를 다시 뒤집습니다. 아래 쓰기에서 기준값은 32비트, 변화량은 하위 16비트입니다.

원본 쓰기값과 대상확인 방식
0x52cb2c64PafControl +0x34의 P에 M[+0x4c] + d를 씁니다. P+0x5a에는 새 값에서 이전 기준값을 뺀 결과를 씁니다.별도 0x52cb2c24부터 원본 실행. 앞선 0x52cb9908의 비영 반환을 요구하는 분기는 정적으로 확인.
0x52cb2e28같은 P에 M[+0x4c] + d − P[+0xe8]를 씁니다. P+0x5a에는 같은 방식으로 변화량을 씁니다.0x52cb2ba8부터 원본 실행. P+0x21이 비영인 분기.
0x52cb9e10PafDrive +0x28의 P에 씁니다. 한 경로는 M +0x44에서 값을 읽고, 다른 경로는 보정값과 기존 기준값을 사용합니다.원본 분기와 0x52cb8500의 객체 연결을 정적으로 확인.
0x52cbeb8cM +0x1c의 P에 스택에 준비한 값을 씁니다. 앞선 명령이 P +0x36과 기존 기준값의 하위 16비트 중 하나를 선택합니다.원본 선택, 스택 저장, 0x52cbe5ec의 객체 연결을 정적으로 확인.

M +0x148을 쓰는 원본 0x52cbea90도 확인했습니다. M +0x20이 가리키는 설정 객체의 +0xf4 word와 Pulse +0x56을 곱한 뒤, 부호 있는 값의 256 나눗셈과 앞선 호출 결과에 따른 부호 처리를 거칩니다. 재생에서는 이미 계산된 M의 값을 시험 조건으로 공급했습니다. M +0x4c의 비영값 출처와 설정 word의 원래 저장소는 미확인입니다.

별도 진입한 원본은 s16(P[+0x2e] − u16(P[+0xa88] − r0))를 계산합니다. 0x52f0ca18에서 P +0xf8에 signed 잔여값을 쓰고, 이번 조건에서 양수이면 그 값을 인자로 요청 3 진입 직전까지 진행합니다. 앞선 보고서에서 요청 3의 첫 장치 읽기와 별도 수치 계산도 각각 확인했습니다. 요청 3의 피드백 계산 · 네 재생의 입력과 관측값

PafMotor의 두 halfword는 비영값 출처가 남아 있습니다

PafMotor 생성자의 0x52f0b57c와 0x52f0b5a0이 +0x56/+0x68을 0으로 초기화합니다. 네 재생에서 이후 두 필드의 쓰기는 없었습니다. PafMotor 인접 코드 0x52f0b354–0x52f0ddb4의 정렬 A32 직접 오프셋 검사에서도 이 두 쓰기를 찾았습니다. 다른 모듈의 별칭, 블록 복사, 계산한 주소나 Thumb의 쓰기는 이 검사에 포함하지 않았습니다.

0x52f0e3f4의 +0x56 쓰기는 PafPulse를 대상으로 하며 렌즈 관련 조건에 따라 값이 달라질 수 있습니다. PafMotor의 동명 필드에는 이 결과를 적용할 수 없습니다. 별도의 PafMotor 소비자 0x52f0cdd0은 +0x68이 비영이면 +0x5c에 ROM 기본값을 쓰고, +0x68의 값을 +0x5a에 씁니다. 인수 r1이 비영이면 200을 더한 하위 16비트를 씁니다. 이 분기는 정적으로 확인했습니다.

재현 조건과 실기 검증 범위

Unicorn 2.1.4의 Cortex-A7 기본 재생, Cortex-A7과 A15의 호출자 저장 레지스터·NZCV 변경 대조가 일치했습니다. 두 입력에서 결과 JSON이 바이트 단위로 같았습니다. 각 재생은 실행 범위, 쓰기 주소·폭·값, 인접 필드의 카나리, RX 원본 영역의 전체 SHA-256을 확인합니다. 메모리·서비스 설정의 일부는 모형으로 공급했습니다.

python -B verify_af_feedback_producers.py rtos.bin --output af-producers-rtos.json
python -B verify_af_feedback_producers.py decoded.bin --output af-producers-decoded.json
python -B -m unittest discover -s tests -p test_af_feedback_producers.py

원본 RTOS나 RTOS를 포함한 decoded 파일 중 하나가 필요합니다. -O를 사용하지 않고 아직 없는 출력 경로를 지정합니다. 원본 ARM 재현기 · 입출력·의존 소스 검사 · 입력 SHA-256과 전체 결과

이 결과는 소프트웨어의 기준값 생산·사용 경로를 보여 줍니다. 렌즈별 저장 보정 레코드, 실제 거리·각도·시간 단위, 모터의 물리적 종류나 연속 AF 동작은 확인하지 않았습니다.

PafMotor와 PafPulse의 입력값 경로에서 생성자, 디버그 요청과 별도 LensInfo 계산의 원본 재생을 확인할 수 있습니다.
