목표와 현재 단계

최종 목표는 일부 정보를 추가하거나 바꾼 펌웨어를 빌드해 K-3 Mark III에서 정상 동작시키는 것이다. 부가 목표는 K-3 Mark III의 UI를 K-3 II 또는 Q7에 이식하는 것이다. 여기서는 사용자가 부른 K-3mk2를 K-3 II로 해석했다. 현재는 두 목표의 선행 분석 단계다. 빌드·패치·플래시와 다른 기종 이식은 아직 시작하지 않았다.

현재 확보한 의사코드는 원래 소스 프로젝트와 다르다. 타입·이름·링커 배치·라이브러리·자원 생성 도구를 복원하지 않은 상태이므로 의사코드를 컴파일하면 원본과 동등한 펌웨어가 만들어진다고 볼 수 없다. 전체 소스 재구축, 특정 모듈의 재구현, 기존 이미지의 제한적 변경은 필요한 근거와 검증 범위가 서로 다르다. 어느 경로를 선택할지는 아래 분석 결과로 판단한다. 현재 분석 범위

이번에 조사한 UI 리소스 접근

패키지의 ICONBIN payload는 26,219,192바이트다. 별도의 RES 레코드에는 폰트 경로가 있다. 크기와 레코드 이름만으로 자원 포맷이나 호환성을 판단하지 않았다. 패키지 레코드·해시

아이콘 그리기 경로 0x528c4780은 0x52ff8ed0(5)로 리소스 슬롯 5의 준비 상태를 확인하고 0x52ff8de4(5)로 기준 주소를 얻는다. RAM 테이블 0x54525578의 16바이트 레코드 중 슬롯 5는 초기화 원본 0x53d0d308에 대응하며 이름 포인터는 IconBinaryData를 가리킨다. ROM→RAM 초기화 매핑과 두 접근 함수의 원본 명령으로 이 연결을 확인했다. UI·업데이트 근거

준비 확인 함수는 레코드 +0xc의 포인터가 가리키는 값을 읽어 0xa55a5aa5인지 검사한다. 이는 관찰한 리소스 준비 표식이다. 업데이트 패키지의 암호학적 서명 검증으로 해석하지 않는다. 그리기 함수는 별도 설명자 조회 0x528c3f08의 결과에서 +8을 읽고 기준 주소+(값<<2)로 데이터 주소를 만든다. 설명자 조회에는 ID 재매핑과 0x681 상한 검사도 있다. 범위 해시·호출 근거

이 구조에서는 ICONBIN만 옮겨 UI가 작동한다고 가정할 수 없다. 자원 적재, 설명자 표, 그리기 코드, 메뉴 상태, 입력 이벤트의 인터페이스를 함께 비교해야 한다. 이번에는 관련 함수 5개의 의사코드와 ARM 목록을 로컬에 추가했다.

업데이트와 공개 소스의 경계

파일명 생성자 0x52ff32ac는 런타임 값을 받아 C:와 R: 드라이브의 FWDC%ldB.BIN 경로를 만든다. 해당 숫자는 0x5310b748이 읽는 객체의 +0x18에서 온다. 파일명 생산자를 확인한 결과이며 실제 업데이트 허용·버전·무결성·서명 검사에 연결한 결과는 아니다. 함수 범위와 전이

공식 OSS 패키지의 Stubby 1.60.1도 확인했다. README 109~117행은 MLB01 보드의 RTOS-main 이미지 조합을 설명하며 MILB_SDK.bin을 별도 입력으로 요구한다. config-sc2000-rtos.h의 RTOS 주소는 0x60000000으로 이번 RTOS 분석 주소 0x52500000과 다르다. 공개 보드 설정을 카메라의 실제 빌드 설정으로 취급하지 않는다. Ricoh 공식 OSS · 배포 패키지 · 파일 해시·행 근거

이 설정 파일의 RSA 서명 옵션은 주석 처리돼 있다. 해당 옵션의 존재·상태만으로 카메라가 수정된 업데이트를 허용한다고 결론낼 수 없다. 입력 패키지의 32비트 합계가 0이라는 기존 관찰도 검증 규칙 전체를 설명하지 않는다. RTOS 업데이트 수신부, 패키지 검증기, 실제 부트로더를 각각 연결해야 한다.

분석 단계의 종료는 모든 함수를 해석하는 시점으로 잡지 않는다. 첫 변경 대상의 의존 범위, 이미지 재구성 규칙, 부팅·복구 조건, 검증 방법을 설명할 수 있는 시점을 구현 착수 판단 기준으로 삼는다. 실제 정상 동작의 판정에는 부팅뿐 아니라 메뉴 입력, 촬영·저장·재생, AF·노출, 전원 전환과 원본 복구 확인이 필요하다. 이는 후속 단계의 검증 기준이며 이번에 수행한 시험은 아니다.

K-3 II·Q7 이식 비교의 출발점

공식 사양에서 K-3 Mark III는 3.2형 약 162만 도트와 정전식 터치, K-3 II는 3.2형 약 103.7만 도트, Q7은 3.0형 약 46만 도트다. 이 수치는 표시 자원·레이아웃·입력 매핑을 따로 검토해야 하는 근거다. 도트 수를 framebuffer 해상도나 메모리 포맷으로 환산하지 않았다. K-3 Mark III · K-3 II · Q7

다른 기종의 ISA·RTOS·GUI ABI가 일치하는지는 아직 조사하지 않았다. 이 조건들이 다르면 UI 바이너리의 직접 이식보다 화면 구성과 동작을 대상 기종의 인터페이스에 맞게 재구현하는 방향을 검토해야 한다. 화면 재현, 메뉴 동작 이식, 전체 UI 런타임 이식은 구분해 평가하며 현재 어느 방식의 성공도 보장하지 않는다.

현 단계는 분석이다. 수정 이미지의 빌드·플래시·카메라 실행과 타 기종 이식은 수행하지 않았다.
