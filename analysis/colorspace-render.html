K-3 III 색공간 행의 아이콘과 글자 측정

펌웨어 2.20의 원본 ARM 코드가 색공간 행의 아이콘과 체크 표시를 시험 표면에 복사했습니다. 같은 행에서 불러온 sRGB 문자열의 배치 크기는 76×40이었습니다. 이 수치는 글자 배치에 쓰이며, 글자가 표면에 찍힌 범위는 이번 실행에서 측정하지 않았습니다.

이 문서에서

  1. 행이 선택한 아이콘과 문자열
  2. 원본 Latin 글꼴을 읽어 캐시를 준비하는 구간
  3. sRGB의 네 글자가 76×40 배치 크기로 이어졌습니다
  4. 재현 입력과 실행 경계

행이 선택한 아이콘과 문자열

타입 19 행의 생성자 0x52c10660은 체크용 IconView를 +0x17c, 행 아이콘을 +0x180, StringView를 +0x18c에 둡니다. 원본 목록 채우기 0x5278e05c가 메뉴 디스크립터 72를 읽고 행에 아이콘과 문자열 ID를 전달합니다. 체크 표시를 켤지는 설정 레코드의 현재값을 비교해 결정합니다. 화면에서 아직 확정하지 않은 포커스는 방향 입력·포커스 재현에서 다룹니다.

마지막 대조에서 하네스가 행의 원본 +0x6c 콜백을 별도로 호출하자 0x52c10d14가 체크 ID 0x231을 기록했습니다. 각 아이콘을 별도로 그린 뒤 전체 256×144 시험 표면과 순서가 있는 쓰기 목록을 독립 바이트 계산과 대조했습니다. 호스트가 사각형, ICONBIN 슬롯과 초기화 상태를 공급했고 카메라 LCD의 채널 해석은 시험하지 않았습니다. ICONBIN 형식과 복사 규칙

두 행에 붙은 StringView는 언어 바이트 0을 받아 원본 테이블의 슬롯 1을 선택했습니다. ID 0x1f6은 sRGB, ID 0x1f7은 AdobeRGB의 NUL 종료 UTF-16LE 리소스를 가리켰습니다. 원본 테이블 21개 슬롯에서 두 이름을 정적으로 대조했고, 동적 재생은 언어 바이트 0으로 한정했습니다. 색공간 값과 메뉴 리소스의 연결

원본 Latin 글꼴을 읽어 캐시를 준비하는 구간

글꼴 대조는 모두 sRGB 행의 원본 StringView 진입점 0x52beeae4를 사용합니다. 언어 슬롯 1이 글꼴 선택자 0을 고릅니다. 성공 재생에서는 파일 이름·크기·복사 주소를 검사하는 호출 모형이 decoded의 RT_Latin.bin 53,880바이트와 LE_Latin.bin 20,784바이트를 복사합니다. 실제 파일시스템, 잠금, 할당기와 실패 후 재시도는 실행하지 않았습니다.

시험 조건정지 지점원본에서 관찰한 동작
렌더러와 IMAGE1 레지스트리 슬롯이 비어 있음0x528c30e0렌더러를 초기화한 뒤 ID 14 조회가 null을 돌려줍니다. 그 포인터를 참조하기 전에 멈춥니다.
최소 버퍼를 갖춘 기존 캐시에 빈 태그를 공급0x528c3b48캐시 미스 분기에서 선택자 0의 RT 파일을 요청합니다. 모형 파일 호출에 진입하기 전에 멈춥니다.
IMAGE1과 두 파일 읽기의 성공 조건을 공급0x528c3438원본 코드가 두 렌더러를 만들고 글꼴 바이트를 받은 뒤 LE 작업 공간을 준비합니다. 선택된 LE 작업 공간은 36×36, 1,388,072바이트입니다.
같은 성공 조건에서 RT 준비까지 실행0x528c37440x5339af58이 원본 RT를 읽고 0을 반환합니다. 호출자가 이 상태를 검사하기 전에 멈춥니다.

두 글꼴의 payload는 decoded의 0x04a13c70과 0x046784e0에서 시작합니다. 결과 JSON은 12개 레코드의 이름, 범위, SHA-256과 실행 조건을 담습니다. 원본 payload는 입력에서 읽어 에뮬레이터 메모리에 전달합니다.

sRGB의 네 글자가 76×40 배치 크기로 이어졌습니다

원본 코드관측값
0x528c38a4 · 작업 공간 할당원본 sizing 경로가 5,960바이트를 요청합니다. 준비 함수는 NUL을 포함한 UTF-16 단위 다섯 개를 받습니다.
0x5338aa64 · LE 준비s,R,G,B,NUL을 읽고 LE 매핑 레코드 다섯 개를 만듭니다. 이 레코드에서 RT 글리프 ID는 확인하지 않았습니다.
0x5338da60 · 문자 측정내부 metric 호출 네 번이 순서대로 s,R,G,B를 받아 각각 0을 반환합니다. 요청 경계의 네 halfword는 [0, 2, 75, 37]입니다.
0x528c3930 · 크기 계산20바이트 결과는 [0, 76, 40, 15000, 15000]입니다. 너비는 Xmax+1, 높이는 별도의 줄 높이 계산에서 나왔습니다. 마지막 두 값의 의미는 확인하지 않았습니다.
0x52beec08 · StringView 복사임시 그리기 설정 63바이트가 StringView+0x188에 그대로 복사됩니다. 너비·높이는 각각 +0x194, +0x198에서 읽었습니다.

RT 준비까지만 실행한 두 대조에서 12개 IMAGE1 할당을 A5와 5A로 채웠습니다. 원본 실행 추적과 파일 호출·읽기 기록은 0으로 시작한 글꼴 대조와 일치했습니다. 전체 측정의 세 대조에서는 같은 12개와 추가 작업 공간 한 개를 각각 00, A5, 5A로 채웠습니다. 결과에서 조건 이름과 채움값 13개, 총 14개 필드만 정규화하자 세 실행의 전체 관측값이 일치했습니다. 기존 문맥 등 나머지 메모리는 하네스의 초기 상태를 유지했습니다.

세 측정 모두 같은 63바이트를 복사했고, 앞 단계의 아이콘·체크 표시 1,532개 쓰기와 표면 SHA-256도 같았습니다. 새로 매핑한 LE 임시 레코드 0x547cd248에서 허용한 쓰기는 세 번이며 최종 4바이트는 00 00 00 01입니다. 이 페이지에 선행 쓰기 검사 훅을 두었고 게스트 읽기는 관찰되지 않았습니다. 이 결과가 전체 힙의 초기값 독립성이나 모든 라이브러리 읽기의 초기화 순서를 입증하지는 않습니다.

재현 입력과 실행 경계

Unicorn 2.1.4에서 Cortex-A15를 사용했습니다. 실행한 A32 명령어를 입력과 비교하고, 메모리 쓰기 범위와 표면 경계, 입력과 재배치 영역의 불변성을 검사합니다. 새 출력 경로와 78,683,892바이트의 K-3 III 2.20 decoded 파일을 사용합니다. CLI는 입력과 도우미 소스의 SHA-256을 확인합니다.

python -B tools/verify_colorspace_render.py decoded.bin --output colorspace-render-replay.json
python -B -m unittest discover -s tests -p test_verify_colorspace_render.py

후속 sRGB 글자의 래스터와 픽셀 전송에서는 같은 원본 글꼴의 705개 부분 커버리지 표본을 합성 표면에 쓰는 별도 구간까지 검증했습니다. 이 문서의 측정 시험과 후속 전송 시험은 각각의 실행 경계를 유지합니다.

공개 기록과 같은 환경에서는 새 JSON의 SHA-256을 전체 재현 결과와 비교할 수 있습니다. 기록에는 사례별 실행 주소와 코드 구간의 SHA-256도 들어 있습니다. 재현 CLI · 의존 소스와 입출력 검사

이 측정 시험은 시험 표면의 아이콘·체크 표시와 언어 바이트 0에서의 sRGB 배치 계산까지 다룹니다. 같은 StringView의 별도 그리기 슬롯 0x52bedb40에서 시작하는 글자 래스터와 전송은 후속 보고서에 기록했습니다. 전체 화면의 입력·표시·설정 저장과 K-3 II·Q7 이식 동작은 아직 검증하지 않았습니다. 세 기종 UI 이식 검증 조건
