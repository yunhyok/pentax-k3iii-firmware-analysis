부트 헤더를 읽는 +4 저장 후보의 실제 대상

기록자 후보 0x53323ce4의 직접 호출자를 확인했다. 이 호출의 출력은 전역 0x54c40f3c이며 슬롯 2 파티션 표와 다르다. 함수의 output+4 저장을 리소스 record+4의 bank 기록으로 해석할 근거는 없다.

연구 개요 · 기존 bank 후보 · 입출력 주소 · 검증 범위

헤더는 입력이고 별도 전역 버퍼가 출력이다

앞선 조사에서는 0x53323d24가 0x50b70028을 읽는다는 사실과 인수 r2로의 저장만 확인했다. 이번에 찾은 직접 호출 0x525e019c는 r0·r1을 0x54c40ee0과 +4에서 읽고 r2에 0x54c40f3c를 지정한다. 호출자 0x525e012c 내부의 진단 문자열에 mwnf_get_device_information()이 나온다. 실제 장치 식별값이나 실행 성공을 확인한 결과는 아니다. 호출 인수·진단 문자열 근거

직접 호출 직전에는 0x1910080c의 상위 두 bit가 0x40000000이면 전역 정보 구조+8에 0을, 다른 값이면 1을 저장한다. 이 주소는 시험에서 RAM으로 대체했다. 원본 builder까지 실행한 후 복귀 주소 0x525e01a0에서 중단했으므로 이후 컨트롤러 처리와 초기화 결과는 검증하지 않았다.

이미지 전체의 정렬된 ARM 직접 분기 후보 검색에서는 위 호출 하나가 나왔고 함수 주소의 word·인접 MOVW/MOVT 후보 검색에서는 추가 참조가 나오지 않았다. 계산된 간접 호출·다른 CPU·별도 적재 코드까지 배제하는 검색은 아니다. 이번 결론은 확인한 호출과 정상 출력 주소에 한정한다. 비제로 FwPartition bank 생산자와 슬롯 2 record+4의 실제 값 생산자는 여전히 미확정이다.

9개 원본 ARM 사례와 원문 보존

헤더 분기·기본값 5사례와 실제 호출자 prefix 4사례가 RTOS·decoded 입력에서 동일하게 통과했다. 각 사례에서 출력 32 words의 쓰기 주소, 헤더 보존과 슬롯 2 표 보존을 검사했다. 함수 내부 호출을 대체하는 stub은 없으며 헤더·기본값·컨트롤러 입력은 모두 작성한 RAM이다. CPU 모델의 결과를 실제 장치 실행으로 해석하지 않는다. 9사례 결과

genuine C 출력 2개와 전체 ARM 607 words를 로컬에 저장했다. 호출자 전체의 C·ARM은 정적 근거이며 CPU 실행은 지정한 prefix에 한정한다. 전이 39개·핵심 명령 23개·진단 문자열 2개의 주소와 해시를 대조했다. 실제 매체 I/O·빌드·플래시는 수행하지 않았다.
