AF와 렌즈 제어 · Joint 쪽 하위 제어

Joint 모드 1이 쓰는 타이머·카운터 객체의 생성과 연결

Joint 모드 1의 하위 함수는 “서비스”를 거쳐 장치 객체를 부릅니다. 그 서비스에 어떤 객체가 어떤 순서로 연결되는지 원본 생성자부터 따라가 확인했습니다.

이 문서에서

  1. 배경: factory, 레지스트리, 서비스
  2. 두 채널은 서로 다른 장치 객체에 연결됩니다
  3. 키와 형이 맞을 때만 객체가 연결됩니다
  4. 한계와 남은 과제
  5. 재현 조건과 실행 범위
  6. 근거 파일과 참고 자료

핵심 요약

  • PafMotor의 리셋은 AF 서비스 객체의 두 칸을 씁니다. 채널 0은 ReloadTimer, 채널 1은 Udc 객체에 연결됐습니다. 객체 생성, 레지스트리 등록, 서비스 연결, 리셋 호출을 원본 코드로 이어 실행해 확인했습니다.
  • 서비스는 장치 레지스트리에서 정해진 키로 객체를 찾습니다. 키가 다르거나 형이 다른 객체를 넣으면 빈 포인터가 남았습니다. 같은 키를 두 번 등록하면 처음 객체가 유지됐습니다.
  • Udc 객체는 생성될 때 전역 카운터에서 채널 번호를 받습니다. 첫 레지스터 주소가 그 번호로 정해집니다.
  • 두 실행은 각각 첫 레지스터 읽기 직전에 멈췄습니다. 할당 주소와 일부 factory 상태, Udc 카운터 값은 합성 입력입니다. 실제 부팅 순서와 물리 의미는 확인하지 않았습니다.

확인 원본 코드 실행으로 확인

  • 두 객체의 생성자, 레지스트리 등록, 서비스 연결 (채널 0 4건, 채널 1 7건)
  • Joint 이벤트 처리기에서 채널 0 리셋까지 이어진 실행
  • RTTI 캐스트의 형 확인과 Udc 채널 번호 할당

정적 분석 코드를 읽어 판단

  • 정지 지점 뒤의 두 리셋 명령 (비트 조작, 되쓰기, 메모리 장벽)

모델 시험 조건으로 정한 것

  • 할당 주소, 단계별 스택·레지스터, 일부 플랫폼·factory 상태
  • Udc 전역 카운터 값 (0, 1, 5, 6)과 Joint 상태
  • 가드·할당·종료 콜백·진단·assertion·mutex 생성은 stub

미확인 확인하지 않은 것

  • 레지스터 읽기 이후의 동작과 하드웨어 응답
  • 실제 부팅에서의 객체 수명과 생성 순서
  • 물리 단위, SDM·바디 모터와의 대응

배경: factory, 레지스트리, 서비스

Joint 하위 제어 문서에서 모드 1은 서비스 어댑터의 가상 호출 직전에 멈췄습니다. 그 호출이 어느 객체로 가는지는 비어 있었습니다. 이 문서는 그 빈칸을 채웁니다.

이 부분의 펌웨어는 C++ 객체를 세 단계로 연결합니다. factory가 장치 객체를 만듭니다. 생성자는 그 객체를 장치 레지스트리에 키와 함께 등록합니다. 서비스 바인더는 레지스트리에서 키로 객체를 꺼내 서비스의 칸에 넣습니다. 형이 맞는지는 RTTI(실행 중 형 정보)로 확인하는 곳도 있습니다.

쉽게 말하면

장비 창고(레지스트리)에 번호표(키)를 붙여 장비를 넣어 두면 작업반(서비스)이 번호표로 장비를 꺼내 자기 선반 두 칸에 올려 두는 구조입니다. 이 문서는 선반 0번 칸에 ReloadTimer가, 1번 칸에 Udc가 올라가는 것을 확인했습니다. 장비를 실제로 켠 것은 아닙니다.

주의

ReloadTimer와 Udc는 펌웨어에 남은 클래스 이름입니다. 이름은 타이머와 카운터 계열 장치를 떠올리게 합니다. 그러나 이 연구는 레지스터를 읽기 직전에 멈췄으므로 실제 하드웨어 기능은 확인하지 않았습니다.

두 채널은 서로 다른 장치 객체에 연결됩니다

채널 0은 기본 키 0xd1로 찾은 ReloadTimer, 채널 1은 기본 키 0x123으로 찾아 형을 확인한 Udc를 씁니다.

채널 0 대조는 원본 이벤트 처리기 0x52f0853c부터 들어가 호출을 따라갑니다. 채널 1 대조는 리셋의 두 번째 호출 지점 0x52f0bb00에 따로 진입합니다. 두 실행 모두 AfDeviceFactory와 PafMotor 바인더가 같은 서비스 객체를 연결했습니다. 레지스터 읽기의 반환값은 합성하지 않았습니다.

  1. ReloadTimer 등록과 가상 호출 ReloadTimerFactory의 생성 블록이 생성자에 기본 키 0xd1과 IRQ 키 0x58을 넘깁니다. 생성자는 vtable 포인터와 레지스터 포인터 0x1e000020을 설정합니다. 바인더는 D1 조회 결과를 서비스 +0x38에 저장합니다. 리셋 어댑터는 그 포인터와 ROM vtable 슬롯을 읽어 분기합니다.
  2. Udc 등록과 형 확인 UdcFactory의 생성 함수가 만든 Udc를 생성자가 기본 키 0x123과 IRQ 키 0x67에 등록합니다. 바인더는 원본 C++ RTTI 캐스트로 Driver → Udc를 확인하고 결과를 +0x3c에 씁니다. 리셋 어댑터에서 분기한 함수가 Udc +0x38의 하위 1바이트를 읽습니다.

키와 형이 맞을 때만 객체가 연결됩니다

레지스트리에 무엇을 어떤 순서로 등록하느냐를 바꿔 가며 서비스 칸에 무엇이 들어가는지 확인했습니다.

채널 0 · ReloadTimer (4건)
등록 조건관찰한 결과
D1만 등록서비스가 D1 객체를 받아 0x5326d4f0에서 0x1e000020의 32비트 읽기 직전에 멈췄습니다.
D2만 등록D2는 같은 vtable 포인터와 별도 레지스터 주소 0x1e000030을 갖습니다. 서비스 +0x38은 0이었고 0x531784bc의 빈 포인터 역참조 직전에 멈췄습니다.
D2 뒤에 D1 등록D2를 먼저 등록해도 키 D1의 객체가 선택됐습니다.
D1 중복 등록factory 슬롯은 새 객체를 받았지만 기본 키 D1과 IRQ 키 0x58은 첫 객체를 유지했습니다. 서비스도 첫 객체를 받았습니다.
채널 1 · Udc (7건)
등록·카운터 조건관찰한 결과
키 0x123, 카운터 1 또는 5원본 할당 함수가 객체 +0x38에 32비트 채널 번호를 쓰고 전역 카운터를 1 올렸습니다. 첫 32비트 읽기 주소는 0x1e00200c + (channel << 5)에 따라 각각 0x1e00202c, 0x1e0020ac였습니다.
인접 키만 등록, Udc 미등록키 0x124에만 Udc를 등록한 경우와 등록 객체가 없는 경우 모두 서비스 +0x3c가 0이었습니다. 두 경우 모두 0x532726e8의 빈 포인터 역참조 직전에 멈췄습니다.
키 0x123에 ReloadTimer다른 형의 원본 생성 객체를 같은 키에 등록했습니다. RTTI 캐스트 결과가 0이었고 같은 역참조 직전에 멈췄습니다.
초기 카운터 0채널 1 리셋에 앞서 Udc 초기화 함수로 들어갔습니다. 0x5334a26c에서 0x1e002014에 0x8008을 32비트로 쓰기 직전에 멈췄습니다.
카운터 6할당 함수가 객체에 6, 전역에 7을 기록하고 거짓 조건을 assertion 서비스 0x530fdfc4로 넘기는 지점에서 멈췄습니다. 리셋 호출과 assertion 본문은 실행 범위 밖입니다.

정지 지점 뒤의 명령은 코드로만 읽었습니다. ReloadTimer 리셋은 첫 읽기 뒤 BIC #6, 되쓰기, DMB SY로 이어집니다. Udc 리셋은 ORR #0x1c, bit 7 지우기, 되쓰기, DSB SY로 이어집니다.

한계와 남은 과제

  • 하드웨어 레지스터 페이지를 매핑하지 않았습니다. 레지스터 응답, 리셋의 실제 효과, 타이머·카운터로서의 동작은 확인하지 않았습니다.
  • 부팅 순서 실제 부팅에서 객체가 언제 만들어지고 얼마나 사는지, Udc 카운터가 실제로 어떤 값에서 시작하는지는 모릅니다. 카운터 1·5는 합성 입력입니다.
  • 물리 의미 물리 단위, SDM·바디 모터와의 대응과 동작은 확인하지 않았습니다.
  • 이어지는 문서 리셋 뒤의 메서드와 모드 1 계산은 모드 1 문서에서 다룹니다.

재현 조건과 실행 범위

원본 생성·등록·연결 구간을 같은 RAM에서 단계별로 실행했습니다. 두 채널은 별도 스크립트로 검사합니다.

  • Unicorn 2.1.4에서 채널 0 네 건, 채널 1 일곱 건을 실행했습니다. Cortex-A7 기본 실행과 r1–r3/r12·NZCV를 덮은 Cortex-A7·A15 대조의 기록이 각각 일치했습니다.
  • RTOS 직접 입력과 decoded 입력에서 같은 JSON을 얻었습니다. 실행 전후 원본 매핑 전체의 해시도 확인했습니다.
  • stub으로 바꾼 함수 8개의 동작은 근거 JSON의 stub_contracts에 있습니다.
