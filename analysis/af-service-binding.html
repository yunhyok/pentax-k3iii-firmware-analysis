Joint 모드 1의 ReloadTimer·Udc 바인딩

K-3 III 펌웨어 2.20에서 PafMotor의 리셋 호출이 어떤 객체를 사용하는지 원본 생성자와 레지스트리부터 추적했습니다. 채널 0은 ReloadTimer, 채널 1은 Udc에 연결됐습니다. 두 재생은 각각 첫 MMIO 접근 직전에 멈췄습니다.

두 채널의 객체 연결

Joint 이벤트 재생에서 모드 1의 가상 호출 직전까지 확인했습니다. 이번 채널 0 대조는 원본 이벤트 처리기 0x52f0853c부터 들어가 호출을 따라갑니다. 채널 1 대조는 리셋의 두 번째 호출 지점 0x52f0bb00에 따로 진입합니다. 채널 0의 MMIO 반환은 합성하지 않았습니다.

  1. ReloadTimer 등록과 가상 호출ReloadTimerFactory의 ROM 슬롯은 생성 함수 0x5326e230을 가리킵니다. D1 생성 블록은 생성자 0x5326dd7c에 기본 키 0xd1과 IRQ 키 0x58을 넘깁니다. 생성자는 vptr 0x53ca9a00과 MMIO 포인터 0x1e000020을 설정합니다. 서비스 바인더는 0x53177be0에서 D1 조회 결과를 +0x38에 저장합니다. 0x531784b8부터 그 포인터와 ROM 슬롯 0x53ca9a40을 읽어 0x5326d4ec으로 분기합니다.
  2. Udc 등록과 타입 확인UdcFactory의 ROM 슬롯은 생성 함수 0x53272ec4를 가리킵니다. 생성자 0x53272540는 vptr 0x53ca9c08을 설정하고 기본 키 0x123과 IRQ 키 0x67에 등록합니다. 서비스 바인더는 0x53177c1c의 원본 C++ RTTI 캐스트에서 Driver → Udc를 확인하고 결과를 +0x3c에 씁니다. 0x531784b4에서 분기한 0x532726e8은 Udc +0x38의 하위 1바이트를 읽습니다.

두 재생에서 AfDeviceFactory와 PafMotor 바인더가 같은 서비스 객체를 연결했습니다. 레지스트리 기본 키와 IRQ 키는 각각 0x54784538, 0x54785994의 별도 테이블에서 사용합니다.

레지스트리와 채널 대조

채널 0 · ReloadTimer
등록 조건관찰한 결과
D1만 등록서비스가 D1 객체를 받아 0x5326d4f0에서 0x1e000020의 32비트 읽기 직전에 멈췄습니다.
D2만 등록D2는 같은 vptr과 별도 MMIO 주소 0x1e000030을 갖습니다. 서비스 +0x38은 0이었고 0x531784bc의 널 역참조 직전에 멈췄습니다.
D2 뒤에 D1 등록D2를 먼저 등록한 대조에서도 키 D1의 객체가 선택됐습니다.
D1 중복 등록공장 슬롯은 새 객체를 받았지만 기본 D1과 IRQ 0x58은 첫 객체를 유지했습니다. 서비스도 첫 객체를 받았습니다.
채널 1 · Udc
등록·카운터 조건관찰한 결과
키 0x123, 카운터 1 또는 5원본 할당 함수가 객체 +0x38에 32비트 채널 번호를 쓰고 전역 카운터를 1 높였습니다. 첫 32비트 읽기 주소는 0x1e00200c + (channel << 5)에 따라 각각 0x1e00202c, 0x1e0020ac이었습니다.
인접 키만 등록 또는 Udc 미등록키 0x124의 Udc만 등록한 경우와 등록 객체가 없는 경우 모두 서비스 +0x3c가 0이었습니다. 두 경우 모두 0x532726e8의 널 역참조 직전에 멈췄습니다.
키 0x123에 ReloadTimer대조용으로 다른 타입의 원본 생성 객체를 같은 키에 등록했습니다. 원본 RTTI 캐스트 결과가 0이었고 같은 널 역참조 직전에 멈췄습니다.
초기 카운터 0채널 1 리셋에 앞서 Udc 초기화 함수로 들어갔습니다. 0x5334a26c에서 0x1e002014에 0x8008을 32비트로 쓰기 직전에 멈췄습니다.
카운터 6할당 함수가 객체에 6, 전역에 7을 기록하고 거짓 조건을 assertion 서비스 0x530fdfc4로 넘기는 지점에서 멈췄습니다. 리셋 호출과 assertion 본문은 실행 범위 밖입니다.

정적 명령을 보면 ReloadTimer 리셋은 첫 읽기 뒤 BIC #6과 되쓰기, DMB SY로 이어집니다. Udc 리셋은 ORR #0x1c와 bit 7 지우기, 되쓰기, DSB SY로 이어집니다. 이 명령들은 두 재생의 정지 지점 뒤에 있습니다.

재현 조건과 실행 범위

원본 생성·등록·바인딩 구간을 같은 RAM에서 단계별로 실행했습니다. 할당 주소, 단계별 스택과 레지스터, 일부 플랫폼 및 공장 상태는 하네스가 공급했습니다. Udc의 warm 카운터 1·5와 Joint 상태도 합성 입력입니다. 가드, 할당, 종료 콜백 등록, 진단·assertion, mutex 생성은 대체 호출을 사용했습니다. MMIO 페이지는 매핑하지 않았습니다. 실제 부팅에서의 객체 수명, 물리 단위, SDM·바디 모터의 대응과 동작은 확인되지 않았습니다.

Unicorn 2.1.4에서 채널 0 네 건, 채널 1 일곱 건을 실행했습니다. Cortex-A7 기본 실행과 r1–r3/r12·NZCV를 덮은 Cortex-A7·A15 대조의 기록이 각각 일치했습니다. RTOS 직접 입력과 decoded 입력에서 같은 JSON을 얻었고, 실행 전후의 전체 원본 매핑 해시도 확인했습니다.

python verify_af_service_binding.py /path/to/original-rtos.bin --output new-reloadtimer-checks.json
python verify_af_udc_binding.py /path/to/original-decoded.bin --output new-udc-checks.json

두 재현기 모두 아래 SHA-256에 해당하는 RTOS 또는 decoded 파일을 읽습니다. decoded 내부 RTOS 시작 오프셋은 0x1c19c입니다. 새 출력 경로를 사용하고 Python 최적화 모드는 끕니다.
