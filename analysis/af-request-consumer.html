AF 요청 큐와 완료 통지

요청 생성부터 소비 task와 전달 gate를 거쳐 callback으로 돌아오는 경로를 연결했다. 완료 통지와 물리적 렌즈 이동 완료는 구분해야 한다.

연구 개요 · 제어 객체·capability · 상위 AF 요청

0x8900 descriptor의 복사부터 요청 큐, 실제 task entry, opcode 0x1b 실행 분기, 완료 callback까지 연결했다. 실행 분기는 0x52f15e2c → 0x52f15100의 직접 호출이다. 요청에 저장된 callback의 vtable slot +8은 그 호출이 돌아온 뒤 0x0409001a와 token을 받는다. 전달 gate가 transport 호출을 생략해도 이 통지는 발생하므로 렌즈의 물리적 이동 완료로 해석할 근거는 없다. [dispatcher 주소·해시, callback 주소·해시]

기준 RTOS는 base 0x52500000, SHA-256 342d2f35405e8daf1797dfe431d2e4aa70f4b52a2c242a29df48206672f1dfb4이다. 이하 offset은 모두 16진수다. L은 기존 AfLensControl 객체, A는 AccessoryArbitrate context, S는 원래 stack descriptor, D는 슬롯 안의 descriptor, Req는 큐에 넘기는 요청이다. task 이름은 원본 문자열 0x538f3d24와 초기화의 사용 지점으로 확인했다. [주소·hash·관계 metadata, 초기화]

Descriptor의 실제 변환

0x52efc7a0의 builder는 stack에 첫 8바이트 02 00 00 89 00 00 00 00, S+8=payload pointer, S+c=0을 만든다. 길이 2와 명령 0x8900을 포함한 descriptor이며 wire frame 자체로 명명하지 않는다. 0x52eff608은 request opcode 0x1b를 따로 지정한다. [builder 52efc830..84c, opcode wrapper]

범위별 원본 해시, 직접 호출과 핵심 명령은 공개 근거 JSON에 기록했다. genuine C 6개와 전체 ARM은 로컬에 보존했다. 디컴파일러가 추정한 타입과 조건은 원본 ARM에 대조했다. 주소·해시·조건 근거

Task 진입과 queue pop

52efe7b4..7f8은 singleton 52f16c10의 +4를 L+1d8에 저장한다. factory 52f16ae0..ae4가 이 객체를 52f14814로 생성했다. 이 constructor는 A+74의 queue와 A+88의 event를 초기화하고 A+4에 vptr 538f3c68을 설치한다. [alias, factory, constructor]

연결직접 증거
task 등록52f14130..134가 A+4를 530f4f60에 넘긴다. 530f5008 → 530f4e80은 task 설정에 객체와 callback 530f3c10을 넣고 530f4f08 → 525b6ae8로 등록한다.
실제 entry의 간접 호출530f3c40 BLX r2에서 [vptr+8]을 호출한다. A+4의 표 538f3c68에서 slot 주소 538f3c70의 값은 52f166ec. thunk가 r0에서 4를 빼고 52f16588로 분기한다. 단순히 main vtable의 이름만 보고 entry를 추정한 것이 아니다.

근거: 등록 wrapper, 등록 함수, generic entry, thunk, loop 전체, enqueue, generic push, generic pop. task 시작의 별도 경로도 factory start와 OS start 호출에 저장했다. OS 스케줄러 자체를 실행한 것은 아니다.

Opcode 1b, 8900, 완료 통지의 경계

52f15e84..e9c은 D에서 command u16+14, payload pointer+8, length byte+12, extra pointer+c를 꺼내 52f15100(A,0x8900,payload,2,extra)에 전달한다. A+5c는 factory+8 reader의 alias다. 52f15100 → 52f18490 → 52f182d4에서 실제 metadata lookup을 거치면 8900은 type3, index49, 추가 byte2, required mask0이다. type3 분기는 52f183fc → 52f18128로 이어진다. [reader alias, forwarder, wrapper·handler, metadata: 5315b08c, 5315b42c]

52f18128 내부에는 packet 0x63과 command의 하위·상위 byte 배치, 52f3a74c 송신 경계와 52f3a754 수신 경계가 보인다. 이번 수치 검사는 이 helper 진입에서 명시적으로 stub 처리했다. 전체 ARM은 로컬에 보존했고 공개 문서에는 범위·해시를 남겼다. 다만 실제 전송이나 모터 동작을 실행·검증하지 않았다.

forwarder가 돌아오면 dispatcher는 token의 하위16비트를 보존하고 D.command를 상위16비트로 다시 넣는다. 52f15ec0에서 Req+4의 vtable+8을 event 0409001a와 token으로 호출한다. L+1d4의 vptr538f0568에서 실제 slot538f0570은 52eff43c이며 이 thunk는 L로 되돌려 52eff330을 호출한다. callback은 token command와 slot에 저장한 command를 비교하고 일치하는 event1a에서 payload child 52efde0c와 cleanup child 52eff2c8을 호출한다. 이 두 child의 내부는 이번 검사의 범위 밖이다. [completion thunk, completion 본체, 조건부 vtable binding]

A.byte9b가 0이 아니면 forwarder가 바로 돌아온다. 52f14c9c(A,4,2)의 반환0도 즉시 return 경로이며 재시도 loop가 아니다. reader wrapper는 communication.byte52f3가 0이 아닐 때 8900 전달을 막는다. 이 조건들에서도 dispatcher의 완료 통지는 실행된다. 상태 byte의 생산자, 의미와 실제 렌즈별 정책은 이번 조사에서 확인하지 않았다.

검사 범위와 재현

원본 ARM 검사 18개를 독립 실행 스크립트로 재현했다. 1개는 constructor slot loop 구간, 6개는 전체 builder→descriptor 복사→request→enqueue wrapper, 1개는 null extra pointer 보존, 1개는 32개 slot 포화, 3개는 전체 queue pop의 합성 OS 반환, 5개는 실제 task entry부터 한 번의 queue drain과 callback까지, 1개는 completion command 불일치다. 이전 8900 builder 검사 횟수를 새 결과에 더하지 않았다.

메모리·queue·event·arbitration·transport·callback child의 stub은 결과 JSON에 개별 주소로 명시했다. OS queue push는 Req를 포착하고 OS receive는 합성 node를 제공한다. 실패 시 output 보존 검사는 receive stub이 output을 쓰지 않는 조건에 따른다. 실제 RTOS의 시간, 경쟁 상태나 failure 이후 loop 동작까지 입증하지 않는다. task loop는 두 번째 wait에서 중단하며 정상 종료 함수로 주장하지 않는다. Unicorn Cortex-A15 모델 사용은 카메라 실행과 동등하다는 뜻이 아니다.

python verify_af_request_consumer.py rtos.bin --output af-request-checks.json

RTOS와 전체 decoded 입력을 각각 SHA-256으로 확인하고 동일한 18개 결과를 재현했다. 비공개 원본 검증에서는 genuine C 6개, ARM 3,437 words, 직접 transfer 384개, 간접 연결 33개, 조건부 vtable binding 3개를 대조했다. 공개 JSON에는 주소와 해시를 남겼으며 원본 추출물은 포함하지 않았다. 원본 검증 요약

비동기 options.byte0=0 경로를 검사했다. 다른 request opcode, nonzero options의 대기·할당 분기, 모든 slot 재사용 과정, 상태 생산자, callback child, 실제 transport와 actuator는 미확정 범위다. 외부 장치 I/O, 펌웨어 수정·빌드·플래시는 수행하지 않았다.

CPU 합성 검사이며 카메라·렌즈·RTOS 스케줄러·실제 전송을 실행하지 않았다. 정적 문서·링크를 검사했으며 화면 렌더링 검사는 수행하지 않았다.
