AF PWM 요청과 정수 변환

K-3 III 펌웨어 2.20에서 PafMotor의 두 호출점은 스택 플래그에 따라 한 개 또는 두 개의 PWM 입력 레코드로 이어집니다. 원본 ARM을 구간별로 재생해 분기, 32비트 곱셈의 래핑, 16비트 합계 제한을 확인했습니다.

두 호출점과 서비스 경계

0x52f0bcf0에서 라우터에 전달하는 두 값은 3과 래퍼 진입 r2입니다. 이 두 번째 값은 0x52f0c060의 상수 20000 또는 0x52f0c4e4의 상수·적응형 반환에서 옵니다. 래퍼는 Motor +0x42 == 0을 라우터 r1로 보냅니다. 스택 첫 바이트가 1이므로 서비스가 앞서며, 후속 0x52f0bc7c는 두 레코드 패커로 분기합니다.

0x52f0bea8은 초기 리셋 이후의 상태에서 두 값을 고릅니다. Motor +0x2c가 비영이면 unsigned 반워드 +0x54가 1000 이하, 1001–2000, 2001 이상일 때 각각 (1000,500), (500,1000), (500,2000)을 선택합니다. +0x2c=0이면 래퍼 진입 상태 1에서 (1000,500)을 쓰고, 상태 2·3에서 0x52f0bd6c의 반환과 1000·2000을 조합합니다. 그 외 상태는 +0x64/+0x66에 값을 쓸 경로로 갑니다.

상태 2·3 사례는 각각 0x52f0beec, 0x52f0bf04의 BL 0x52f0bd6c 직전에 정지했습니다. 적응형 함수 본문은 정적으로 확인했습니다. 그 함수의 외부 반환 비교 문턱은 래퍼에 넘긴 상태값과 별개인 Motor +0x43에서 고릅니다. +0x43=2일 때 2배·4배의 초과 문턱은 2000·4000, +0x43=3일 때 4000·8000입니다.

라우터는 Motor +0x18=0이면 r1 == 1, 그 외에는 r1 != 1을 선택값으로 계산합니다. 두 스택 플래그는 바이트로 읽습니다. 첫 바이트가 0일 때 둘째 바이트가 비영이면 한 레코드 패커로 바로 가고, 0이면 앞선 서비스 뒤에 같은 패커가 옵니다. 드라이버 등록과 리셋의 원본 경계

두 반워드의 래핑과 제한

상태 선택 입력의 출처는 PafMotor 상태 바이트의 쓰기 경로에서 별도로 추적했습니다.

w(x) = s32(843 × x)
t(x) = u16(trunc0(w(x) / 1000) − 1)
a = t(r2)
b = min(t(r3), 65535 − a)
record[+0], record[+2] = a + b, b

s32는 곱의 하위 32비트를 부호 있는 값으로 해석합니다. 원본은 상수 0x10624dd3과 부호 보정으로 0 방향 절삭을 계산합니다. 각 결과에서 1을 뺀 뒤 u16으로 래핑하므로 입력 0도 첫 단계에서 65535가 됩니다. 두 반워드의 합이 65535를 넘을 때 둘째 반워드를 줄입니다.

입력 r2, r3레코드 +0, +2확인한 경계
3, 2000016860, 16859첫 호출점의 상수 조합
1000, 5001262, 420기본 입력과 절삭
0, 065535, 0감산 뒤 반워드 래핑
−3, −265535, 2부호와 0 방향 절삭

입력 2547430과 2547431 사이에서 843 × x의 하위 32비트 부호가 바뀝니다. 이 조합에서는 최종 합계 제한 때문에 출력만으로 무제한 곱셈과 구별할 수 없습니다. 위의 최대·최소 signed 32비트 조합은 두 방식의 결과를 구별합니다.

패커가 넘긴 12바이트 레코드

  • 한 레코드 패커는 선택값이 1이면 드라이버 +0x2c, 그 외에는 +0x30을 선택합니다. 계산한 반워드 두 개를 +0/+2에 쓰고 나머지 여덟 바이트는 0xff입니다. 0x53178154의 적용 호출 직전에 정지했습니다.
  • 두 레코드 패커는 첫 레코드에 반워드 0 두 개와 +0xa=3을, 둘째 레코드에는 계산한 반워드와 +0xa=1을 씁니다. 그 외 바이트는 0xff입니다. 선택값 1은 슬롯을 +0x30, +0x2c 순으로 넘기며, 그 외에는 순서가 반대입니다. 0x53179224의 적용 호출 직전에 정지했습니다.

이 레코드들은 기존 PWM 설정을 부분 갱신하는 12바이트 입력입니다. 후속 0x5326ca24에서는 반워드 0과 대부분의 바이트 0xff가 기존 필드를 유지합니다. 병합한 12바이트 입력을 바탕으로 별도의 16바이트 하위 스택 레코드를 만듭니다. 이번에는 이 후속 실행, PWM 레지스터 접근과 인터럽트 전달을 수행하지 않았습니다.

Motor +0x56/+0x68을 읽는 경로는 +0x5a의 문턱을 정하고, 이 문턱은 상수 20000을 사용하는 분기에 관여합니다. 두 필드에서 PWM 반워드로 직접 복사하는 경로와 0이 아닌 값의 생산자는 미확인입니다. Motor 필드의 입력 범위

원본 재현

Cortex-A7 기본, Cortex-A7과 A15의 레지스터·NZCV 변경 조건에서 드라이버와 슬롯의 RAM 주소를 달리했습니다. 패킹 15개, 라우터 6개, 상위 분기 10개씩 총 93개 실행이 같은 관측값을 냈습니다. 주소와 상태값은 시험용이며, 서비스의 성공이나 MMIO 응답은 공급하지 않았습니다. 숫자의 물리 단위나 실제 모터 역할은 미확인입니다.

저장소 루트에서 Python과 Unicorn 2.1.4를 사용합니다. 입력의 길이·SHA-256과 보조 코드 두 개의 SHA-256을 확인합니다. 원래 관측 전체의 타입을 구분하는 해시와 직렬화 해시를 검사한 뒤 공개 JSON을 만듭니다. 원래 연구 코드와 공개 검증기의 해시는 별도로 기록했습니다. 새 출력 경로를 지정하고 --compare에는 LF 또는 CRLF의 공개 JSON을 사용합니다.

python -B verify_af_pwm_parameters.py decoded.bin --output af-pwm-decoded.json --compare analysis/af-pwm-parameter-checks.json
python -B verify_af_pwm_parameters.py rtos.bin --output af-pwm-rtos.json --compare analysis/af-pwm-parameter-checks.json
python -B -m unittest discover -s tests -p test_af_pwm_parameters.py
