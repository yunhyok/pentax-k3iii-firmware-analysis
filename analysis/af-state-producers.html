PafMotor 상태 바이트의 쓰기 경로

K-3 III 펌웨어 2.20의 한 ARM 구간에서 PafMotor+0x43에 직접 쓰는 명령 22개를 찾았습니다. 피드백과 이전 상태를 비교하는 두 함수, Joint 요청의 분기에서 이 바이트에 0부터 5까지 쓰는 경로를 확인했습니다.

이 문서에서

  1. 객체와 입력
  2. 상태를 쓰는 분기
  3. 두 반환값과 상태 다시 읽기
  4. 정적 대조 재현

객체와 입력

AfMotorFactory는 0x52f08c80에서 PafMotor 생성자를 호출하고 0x52f08c94에서 그 포인터를 factory +0xc에 둡니다. 생성자에서 쓰는 vptr은 0x538f25c8이고 RTTI 이름은 8PafMotor입니다. Joint는 0x52f07bac/bbc에서 같은 포인터를 자기 +0xdc에 연결합니다. PafMotor +8은 AfMotorDriver를, +0x14는 PafPulse를 가리킵니다. 객체 결합 근거

상태를 쓰는 분기

v는 함수의 진입 r2이거나, r1=0 경로에서 피드백 함수가 반환한 값입니다. T는 PafMotor+0x5a의 unsigned 반워드입니다. 첫 함수 0x52f0bf5c는 Motor +0x34가 0과 5가 아닐 때만 문턱을 비교합니다.

선택 함수조건상태 바이트 저장
0x52f0bf5cMotor +0x34가 0/5이 분기에서 저장 없이 반환
v > T기존 4는 4, 그 외 0 · 0x52f0bfa0
19 < v ≤ T1 · 0x52f0c034
v ≤ T, v ≤ 194–19는 2 · 0x52f0c0b8
0–3은 3 · 0x52f0c0c0
0x52f0c3e4기존 0, 19 < v < T1 · 0x52f0c4d8
기존 1, u16(v−4) ≤ 152 · 0x52f0c4a4
기존 2, v ≤ 33 · 0x52f0c47c
기존 3, Motor +0x34가 0/5 이외이며 (s16(v) ≤ 1 또는 Motor +0x1a가 비영)5 · 0x52f0c45c
0x52f0d83cJoint +0x74의 요청 코드로 선택요청 1에서 PafPulse +0x15가 비영이면 선행 함수 호출 뒤 4 · 0x52f0dc80. 나머지 직접 저장은 0.

첫 함수의 크기 비교는 unsigned입니다. 두 번째 함수에서 기존 값 0/2의 비교는 unsigned 32비트입니다. 기존 값 1은 감산 후 16비트, 기존 값 3은 signed 16비트를 검사합니다. 두 번째 함수의 분기표는 0x52f0c40c에 있습니다. Joint 요청의 분기표 0x52f0d8bc는 10개 항목이며, 직접 0을 쓴 뒤에도 0x52f0da84에서 첫 상태 선택 함수를 호출할 수 있습니다.

생성자의 0 저장은 0x52f0b568입니다. 리셋 및 후속 정리에도 0 저장이 있습니다. 전체 22개 주소와 각 명령의 해시는 정적 대조 JSON에 있습니다. 상태의 원래 명칭과 물리적 역할은 확인하지 않았습니다.

두 반환값과 상태 다시 읽기

함수 진입 r1=0에서 상태 선택의 피드백 경로는 0x52f0b490 → 0x53178310입니다. AfMotorDriver +0x38에 키 0xd1의 ReloadTimer가 결합돼 있으면, ROM vtable +0x6c가 0x5326d5e4를 가리킵니다. 이 경우 0x5326d5e8의 LDR 주소는 0x1e000024로 계산됩니다. 드라이버는 반환의 하위 16비트를 사용합니다. 등록 성공과 레지스터의 실제 값은 관찰하지 않았습니다. ReloadTimer 결합 근거

래퍼 0x52f0be18은 앞서 읽은 상태값을 보관하고 0x52f0be38에서 드라이버 리셋 경로를 호출합니다. Motor +0x2c가 0이고 보관한 값이 2/3이면 적응형 함수로 향합니다. 적응형 함수는 0x52f0bd78에서 같은 상태 바이트를 다시 읽습니다. 이 값이 2일 때 2배·4배의 엄격 초과 문턱은 2000·4000, 3일 때는 4000·8000입니다. 문턱과 비교하는 수치는 별도 서비스 0x53106370의 unsigned 반환값입니다. 기존 PWM 재생은 적응형 함수 호출 앞에서 멈췄습니다. 기존 PWM 실행 범위

정적 대조 재현

검사기는 원본 RTOS 또는 decoded 입력의 해시를 확인한 뒤 Capstone으로 28개 구간, 직접 바이트 저장 22개, 명령 위치 35개와 분기표 2개를 대조합니다. 전체 기록이 동결된 AF83 결과의 타입과 직렬화 해시에 모두 맞아야 JSON을 씁니다. 객체 별칭과 분기 조건은 원본 명령을 사람이 추적해 해석했습니다.

저장 검색 범위는 [0x52f0b380, 0x52f0de00)의 명시적 STRB [receiver,#0x43]입니다. 다른 함수와 계산 주소, 간접·광역 저장은 목록에 포함되지 않을 수 있습니다. 원본 ARM 명령을 실행하지 않았습니다. 장치 레지스터를 읽거나 서비스 반환값을 공급한 실험도 없습니다.

Capstone 런타임 5.0.7을 사용합니다. 검증 환경의 Python 배포 패키지는 capstone 5.0.9였습니다. --compare는 LF와 CRLF를 허용하며, 출력은 새 파일 경로여야 합니다.

python -B verify_af_state_producers.py path/to/rtos.bin --output new-state-checks.json --compare analysis/af-state-producer-checks.json
python -B verify_af_state_producers.py path/to/decoded.bin --output new-decoded-checks.json --compare analysis/af-state-producer-checks.json
