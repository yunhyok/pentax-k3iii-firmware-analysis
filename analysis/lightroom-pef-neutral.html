K-3 III PEF에서 확인한 As Shot 중립값

Adobe DNG Converter 18.7은 PEF 복사본에서 RGB 중립값 (0.431703, 1, 0.625917)을 기록했습니다. 이 값으로 SDK 수식을 재현했을 때 프로파일에 따른 온도 변화는 −42.111 K였고, Lightroom의 원본 PEF 표시에서는 −50 K였습니다.

이 문서에서

  1. 두 DNG 변환에서 CFA 데이터가 일치했습니다
  2. 녹색 기준 역수 비율이 표준 중립값과 일치했습니다
  3. 같은 중립값에서 프로파일별 온도와 틴트를 계산했습니다
  4. 새 변환과 고정 입력 재현

두 DNG 변환에서 CFA 데이터가 일치했습니다

설치된 Windows CLI에서 원본 해시와 일치하는 복사본 두 개를 각각 변환했습니다. 두 출력은 6304×4224 한 채널 CFA, 16비트 저장, 기본 크롭 6192×4128이었습니다. 425개 타일에서 모두 무손실 JPEG SOF3를 확인했고, 전체 디코딩 픽셀의 SHA-256이 같았습니다. 이 두 차례 변환 검사에서는 원본 PEF 배열을 디코딩하여 대조하지 않았습니다. 변환 명령·태그·픽셀 해시

두 DNG는 각각 31,652,772바이트였습니다. 105바이트 차이는 IFD0 날짜, XMP 변환 시각과 생성 UUID, 미리보기 날짜에서만 발생했습니다. 두 실행 모두 종료 코드가 0이었고 GPU·WinML 초기화 진단은 로그에 남겼습니다. 원본과 복사본 PEF의 해시는 변환 전후 같았습니다. 두 컨테이너 해시와 비교 결과 · Adobe 명령줄 명세

녹색 기준 역수 비율이 표준 중립값과 일치했습니다

원본 PEF에는 표준 AsShotNeutral 태그가 없었습니다. Pentax MakerNote 0x0201의 WhitePoint는 18976, 8192, 8192, 13088이며 변환 DNG에도 보존됐습니다. LibRaw의 PEF 파서는 이를 RGGB 순서의 As Shot WB로 해석합니다. 이 표본에서 두 녹색이 같아 녹색을 기준으로 구한 역수의 RGB 비율을 직접 대조할 수 있었습니다. LibRaw 0.22.0 파서 · 채널 순서 · ExifTool 13.59 태그 정의

두 DNG의 AnalogBalance는 (1, 1, 1)이고 CameraCalibration1/2/3 및 CameraCalibrationSignature는 없습니다. com.adobe는 별도의 ProfileCalibrationSignature 값입니다. 관측한 역수 비율의 일치는 두 녹색 값이 같은 이 표본에 한정됩니다. ExifTool Windows 런처와 설치된 Pentax 파서 모듈의 해시를 각각 기록했습니다. 전체 Perl 실행 환경의 무결성은 확인 범위 밖입니다. 표준 태그와 도구 해시

같은 중립값에서 프로파일별 온도와 틴트를 계산했습니다

Converter가 기록한 같은 중립값을 세 프로파일에 적용해 공개 Adobe DNG SDK 1.7.1 Build 2768 수식을 Python으로 재현했습니다. Adobe Standard와 Camera Bright는 ColorMatrix 두 개와 조명 태그가 같아 모델 백색점과 온도·틴트가 같습니다. ForwardMatrix는 다르며 카메라→D50 PCS 행렬의 두 프로파일 간 최대 성분 차이는 0.619123입니다. 모델 CameraWhite는 매트릭스 기준과 최대 1.02×10⁻⁸ 차이였습니다. SDK 계산 경로 · 행렬·태그별 해시

모델 변화는 −42.111 K / +1.107, 관측 변화는 −50 K / +1입니다. 두 변화량의 차이는 +7.889 K / +0.107입니다. 매트릭스 4678과 두 Adobe 프로파일은 각각 8회와 4회에 수렴했습니다. SDK 저온 분기나 미수렴 대안은 사용하지 않았습니다. DNG에 내장된 두 ColorMatrix, 조명 태그 두 개, ForwardMatrix 두 개는 Adobe Standard의 해당 payload와 바이트 단위로 일치합니다. 변환기의 프로파일 선택 과정은 관측하지 않았습니다. 세 프로파일 전체 결과

계산 입력은 Converter 18.7의 DNG이고 비교한 표시값은 Lightroom 16.0의 원본 PEF에서 나왔습니다. 실제 Lightroom의 채널 이득, UI 반올림 규칙, PEF·DNG 렌더 동등성은 미확인입니다. 앞선 참조 프로파일 실험에서 As Shot 표시값이 바뀌어 엄격한 WB 동일 조건이 실패한 결과도 그대로입니다. 원본 PEF 현상 비교

후속 검사에서는 원본 PEF와 첫 변환 DNG의 디모자이크 전 센서 샘플 26,628,096개를 모두 대조했습니다. 세 디코딩 배열의 값은 같았으며, WhiteLevel 태그의 차이는 별도로 남았습니다. PEF·DNG CFA 샘플 비교

새 변환과 고정 입력 재현

새 변환을 확인하려면 원본 PEF의 SHA-256이 기록과 같은지 검증한 후 독립 복사본을 새 폴더에서 변환합니다. -c는 무손실 압축, -p0는 별도 JPEG 미리보기 없음입니다. 실제 결과에는 256×171 RGB 썸네일이 있습니다. 원본 내장·선형 DNG·손실 압축·크기 제한 옵션은 사용하지 않았습니다. Adobe CLI 옵션

& $converter -c -p0 -d $newFolder -o K3IIIhSLI0000100NR0.dng $pefCopy

아래 계산기는 연구 당시의 첫 번째 DNG 파일을 입력으로 사용합니다. 새로 변환한 파일은 CFA가 같더라도 날짜와 UUID가 달라져 전체 파일 해시가 바뀝니다. SDK ZIP과 DCP 세 개의 고정 크기·해시도 확인합니다. 온도 표는 지정한 SDK ZIP에서 읽습니다. Adobe DCP·SDK·사진 원본은 배포하지 않습니다. 매트릭스 4678 DCP는 스튜디오 기준 JSON의 profile_recipes.k3iii.spec와 profile_bridge.py로 재생성할 수 있습니다. 매트릭스 4678 레시피 · DCP 생성기 · Adobe SDK 라이선스

python -B tools/check_lightroom_pef_neutral.py --sdk dng-sdk.zip   --dng first-converted.dng --matrix pentax-k3iii-4678-matrix-test.dcp   --adobe-standard "PENTAX K-3 Mark III Adobe Standard.dcp"   --camera-bright "PENTAX K-3 Mark III Camera Bright.dcp" --output result.json

기준 결과와 전체 구조·자료형을 비교하고 유한 실수 항목에는 절대차 10⁻¹⁰을 적용합니다. 새 출력의 실제 SHA-256과 기준 SHA-256을 각각 표시합니다. 계산기는 Converter나 Lightroom을 실행하지 않습니다. 재현 코드 · 입력 핀과 결과 · Adobe DNG SDK
