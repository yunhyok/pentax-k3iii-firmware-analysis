Q13 행렬 곱 재컴파일과 RTOS 재패키징

독립 C로 작성한 3×3 Q13 행렬 곱을 ARM으로 다시 빌드하고, 원본 RTOS의 0x5312cd40에 넣어 로컬 후보 패키지를 만들었다. 후보를 재디코딩해 같은 주소의 함수와 원본 색 행렬 준비 경로를 실행했다. 합성 입력에서 원본과 같은 결과를 얻었고, 원본 ARM 헤더·체크섬 검사도 통과했다. C 소스 · 실험 코드 · 측정값과 해시

기계어 배치와 패키지 변경 범위

원본의 함수 구간은 0x5312cd40–0x5312cdb4이며 끝 주소는 포함하지 않는다. 앞 112바이트를 컴파일한 코드로 덮고 0x5312cdb0의 원본 명령 4바이트를 보존했다. 재컴파일본은 그 직전 명령에서 복귀했고, 검사 중 보존한 끝 명령을 실행하지 않았다. A32 명령 28개를 확인했고, 직접 분기 3개의 목적지는 함수 내부였다. 이 코드 구간에는 재배치, 외부 호출, PC 상대 데이터 참조가 없었다. 배치·디스어셈블 검사 · 원본 함수 주소와 해시

동일한 크기의 RTOS 레코드 하나를 바꿨다. 재디코딩한 78,683,892바이트를 원본과 비교했을 때 바뀐 바이트는 교체 구간 안의 79바이트와 디코딩 데이터 마지막의 체크섬 4바이트였다. 컨테이너 헤더 128바이트와 버전 레코드, 푸터 식별 필드는 일치했다. 편집 이미지의 스트림은 기존 도구가 전부 stored 블록으로 다시 인코딩했다. 재패키징 도구 · 바이트 차이와 레코드 해시

원본 주소와 실제 호출 위치에서의 검사

직접 호출. 원본과 재디코딩한 후보에서 각 106개 사례를 실행했다. 부호 있는 16비트 입력, 반올림·정수 범위 경계와 난수에서 출력이 기준식과 일치했다. 두 실행에서 함수 밖으로 나가지 않고 복귀했고, 보존 레지스터와 SP, 출력 쓰기 범위를 확인했다. 이 입력은 2바이트 정렬을 따르며 각 버퍼가 겹치지 않는다. 진입 SP 아래 가장 깊은 쓰기는 원본 28바이트, 후보 32바이트였다. 직접 호출 검증의 정의 · 원본 주소 실행 결과

색 행렬 준비. ColorSpace 조건이 켜진 합성 설정으로 원본 호출자 0x5312ce30 전체를 각 이미지에서 10회 실행했다. 수동 RGB 5회, 필터 5회에서 직접 분기 0x5312ced8, 0x5312cefc, 0x5312d0a0을 모두 거쳤다. 호출자와 이미지당 하위 호출 20개의 복귀 시점에 r4–r11, d8–d15, SP 보존을 확인했다. 각 행렬 호출에서 읽기는 두 입력과 자기 스택 프레임, 쓰기는 18바이트 출력과 자기 프레임으로 제한했다. 하위 호출의 프레임은 진입 SP 아래 원본 28바이트와 후보 32바이트였다. 호출자 기준 최대 스택 쓰기 깊이는 228바이트에서 232바이트로 늘었고 최종 출력과 쓰기 범위는 일치했다. 행렬 준비 경로 · 사례별 호출 위치·결과 해시

CPSR.Q. 별도 합성 행렬에서 출력 18바이트는 모두 0이었고, 복귀 시 Q는 원본 0, 후보 1이었다. 원본은 반올림 상수 4096을 누산 뒤에 더하고 C는 누산 전에 넣어 중간 부호 오버플로가 달라진다. 후속 시험은 원본의 상위 호출 지점 네 곳에서 시작해 하위 행렬 함수 복귀 시 Q만 0 또는 1로 설정했다. ColorSpace를 켠 80쌍(160회)에서 행렬 준비·패킹의 실행 경로, 쓰기 및 결과가 같았다. Q 차이는 다음 호출 직전까지 유지됐다. AAPCS32는 공개 인터페이스 복귀 시 Q를 정의하지 않으며, 이 시험으로 다른 분기나 간접 호출의 Q 사용 여부를 판단할 수는 없다. 원본·후보 차이 · 호출 위치와 후속 결과 · 재현 코드 · Arm AAPCS32

헤더·체크섬. Unicorn에서 원본 ARM의 헤더·외부 체크섬 검사와 내부 체크섬 검사를 전체 버퍼에 실행했다. 원본과 후보가 모두 통과했고, 프로젝트 값이나 매직 값을 바꾸면 양쪽 모두 거절했다. 거절 분기의 진단 출력만 생략했다. 별도의 호스트 검사에서는 외부 합이 틀린 후보, 외부 합만 다시 맞춘 내부 체크섬 오류, 체크섬을 다시 맞춘 뒤에도 원본 함수의 보존 영역을 바꾼 후보를 각각 거절했다. 원본 ARM 검사 코드 · 실행 및 실패 사례

후속 선택적 재패키징에서는 디코딩 결과를 그대로 유지하면서 원본 압축 블록 3,198개를 보존했다. 후보 크기는 35,136,788바이트로 줄었으며, 실제 카메라의 수용 여부는 여전히 확인되지 않았다.

재현과 남은 범위

검증된 원본 fwdc233b.bin 또는 바이트가 동일한 복사본을 사용한다. 이전 검증과 같은 Zig 0.15.2 Windows x86-64 배포본과 Python의 Unicorn 2.1.4, pyelftools 0.33, Capstone 5.0.7을 사용했다. 실행하면 빌드 결과와 후보를 .private/hq-integration/ 아래 새 작업 디렉터리에 남긴다. 후보의 처음 파일명은 matrix-offline.repacked.unverified.bin이다. 모든 검사와 결과 파일 기록이 끝나면 matrix-offline.repacked.bin으로 바꾼다. 공개 결과에는 SHA-256과 합성 시험 결과를 기록했다. 컴파일러 해시와 설치 경로 · 실행 명령과 후보 SHA-256
