RMW 8바이트의 최종값과 초기 64비트의 관계

원본 [0x525d8594, 0x525d85d0)의 15개 명령 의미를 수동 모형으로 옮겼습니다. signed count > 1로 이 구간에 진입해 순차 RAM 처리를 마치면, 두 워드의 최종값은 초기 64비트와 관계없이 (count << 2) | 1과 0입니다. 32비트를 넘는 부분은 버립니다. 공개 증명 실행 결과

실제 읽기와 중간 바이트 쓰기는 남아 있습니다. 이 증명은 물리 RAM 초기값의 생산자, 동시 접근, 전체 부팅을 입증하지 않습니다. 다른 48바이트는 이번 증명 범위 밖이며 기존 56바이트 RMW 허용 목록을 유지합니다.

1. decoded 이미지로 재현하는 범위

공개 도구는 decoded 이미지 전체와 RTOS, 대상 60바이트의 SHA-256을 확인합니다. Capstone으로 해당 구간이 4바이트 명령 15개로 해독되는지 검사한 뒤 분석자가 작성한 모형에 Z3를 적용합니다. 해시와 명령 수 검사는 수동 번역의 정확성을 자동으로 증명하지 않습니다. 모형의 코드와 전제는 함께 공개합니다. 주소·해시·전제 · 수동 모형 · 의사코드

모형은 초기 두 워드를 임의의 32비트 값으로 취급합니다. 첫 워드의 하위 2비트를 01로 정하고 상위 30비트를 count로 바꿉니다. 둘째 워드에서는 하위 2비트와 상위 30비트를 각각 지웁니다. 최종값이 이 식과 달라지는 반례에 대해 Z3는 unsat를 반환했습니다. 각 하위 비트 지우기를 모형에서 하나씩 생략한 두 대조군에는 sat 반례가 있습니다. 원본 firmware를 수정한 실험은 아닙니다.

2. 과거 실행 관찰과의 연결

이름 registry 할당과 조회 재현의 선택 실행에서는 0x56493278..0x5649327f를 남은 자유 블록의 길이 레코드로 처음 기록했습니다. 앞선 원본 기록 0xba51 >> 2 = 0x2e94에서 1페이지를 할당하면 count는 0x2e93, 최종 두 워드는 0xba4d, 0입니다. 이 관찰은 별도 출처 기록에 보존했으며 이번 공개 CLI는 과거 trace를 다시 검증하지 않습니다.

기록초기 00초기 A5
첫 바이트 쓰기01A5
둘째 바이트 쓰기00A4
완성된 두 워드0000BA4D, 000000000000BA4D, 00000000

기존 31번 재현은 마지막에 허용한 56바이트 모두를 guest가 기록했는지 검사합니다. 앞선 48바이트 역시 초기화 과정에서 읽고 씁니다. 그 값이 그대로 보존된다는 뜻으로 이번 증명을 해석하지 않습니다.

31번에서 실제로 관측한 prologue 중단점은 0x525b5a54입니다. 후속 정적 조사에서 찾은 MPIDR 후보 0x525d9f4c와 0x525d6f18은 그 관측 중단점과 구분합니다. 공개 도구는 어느 주소에서도 원본 CPU 명령을 실행하거나 값을 대신 넣지 않습니다.

3. 가벼운 검사와 실제 증명 검사

입력 없이 실행하는 기본 검사는 표준 라이브러리만 사용합니다. 패키지 해시·필드 타입·출력 충돌·별칭·변조 거부 등 18개 검사를 통과했습니다. 이 결과만으로 firmware에 연결된 증명이 실행됐다고 표시하지 않습니다. 기본 검사 기록

--decoded를 제공하면 원본 입력으로 실제 모형 증명을 두 번 재현합니다. 다른 경로로 옮긴 두 결과가 공개 결과와 같았고 입력도 보존됐습니다. 이 모드의 19개 검사가 통과했습니다. 실제 증명을 포함한 검사 기록

원본 분석 스크립트의 출처 해시와 현재 실행하는 공개 helper 해시는 별개입니다. helper와 source manifest는 캡처한 바이트의 해시를 확인한 뒤 사용합니다. 원본 명령 바이트·전체 disassembly·비공개 7MB trace는 패키지에 포함하지 않았습니다.

4. 실행 조건

Python 3.12.3 환경에서 확인했습니다. 설치 배포판은 capstone 5.0.9와 z3-solver 5.3.1.0이며, 런타임 모듈은 각각 5.0.7과 5.3.1을 보고합니다. 실제 증명용 의존성을 별도 환경에 설치할 수 있습니다. 기본 검사에는 이 패키지들이 필요하지 않습니다.

# 표준 라이브러리만 사용하는 기본 검사
python -S test_verify.py --work-dir /existing/temp-parent --output /path/to/new-guard-results.json

# decoded 이미지로 실제 모형 증명
python -m pip install -r requirements-proof.txt
python verify.py /path/to/decoded.bin --output /path/to/new-proof.json
python test_verify.py --work-dir /existing/temp-parent --decoded /path/to/decoded.bin --output /path/to/new-proof-tests.json

명령은 이 패키지 폴더에서 실행하는 예입니다. 스크립트의 절대 경로를 사용하면 다른 폴더에서도 실행할 수 있습니다. 입력은 업데이트 파일 자체가 아닌 정확한 decoded 이미지이며 크기와 해시는 source.json에 있습니다. 출력 파일은 새 경로여야 하고 --work-dir는 기존 폴더여야 합니다.

기본 검사는 독립된 임시 폴더 안에서 합성 fixture를 만들고 정리합니다. 저장소 CI와 릴리스 검사에 기본 검사를 연결했습니다. 실제 증명 검사는 사용자가 원본 입력을 제공한 환경에서 선택해 실행합니다.
