K-3 III DNG의 Adobe SDK Stage 2 실행

Adobe DNG SDK 1.7.1 Build 2768에서 읽은 Stage 2 값 25,891,840개가 고정 DNG에 대해 계산한 정수 모델과 모두 일치했습니다. 그중 8,530개가 uint16 최댓값 65,535에 도달했습니다.

호출 순서와 빌드 옵션

기본 dng_host에서 DNG를 파싱하고 원본 ReadStage1Image, ValidateRawImageDigest, SynchronizeMetadata, BuildStage2Image를 호출했습니다. DoBuildStage2가 ActiveArea 크기의 ttShort 배열을 할당한 뒤 원본 Linearize를 실행했습니다. 기본 블랙 보존은 꺼져 있었고 Stage 2 직후 Stage3BlackLevel()은 0이었습니다. SDK 근거는 dng_validate.cpp:172,207,239,248, dng_negative.cpp:5074,5314–5338,5586–5617, dng_linearization_info.cpp:494,765,803–824입니다. C++ 하네스 · Adobe DNG SDK

공식 Windows 예제는 이 환경에서 ClangCL 부재 오류(MSB8020)로 중단됐습니다. 실행에는 Zig 0.15.2로 빌드한 하네스를 사용했습니다. XMP·baseline libjpeg·SDK AVX를 끄고 번들 JXL과 Highway는 스칼라로 빌드했습니다. IFD0에 XMP 태그가 있지만 이 빌드에서는 XMP 처리를 사용하지 않습니다. RAW 타일 425개는 모두 JPEG SOF3이고 원본 SDK의 무손실 JPEG 디코더가 처리했습니다. IFD0와 CFA SubIFD에는 opcode 목록 태그가 없었습니다. JXL 소스 사본에 XMP 조건부 가드 두 개만 추가했으며, Stage 1·2의 원본 소스와 무손실 JPEG 디코더는 그대로 컴파일했습니다. 소스 해시와 전체 빌드 인자 · SDK 라이선스

Stage 3 호출 전에 실행을 마쳤습니다. 이 실험에서 확인한 범위는 변환 DNG 한 개의 디모자이크 전 처리입니다. Adobe Converter 18.7과 Lightroom이 네이티브 PEF에 사용하는 화이트 레벨, 디모자이크 또는 최종 렌더는 확인하지 않았습니다. 변환 DNG의 출처 · 원본 PEF와 DNG의 저장 CFA 대조

같은 입력으로 재현하기

Windows x64의 Python 3.12 및 NumPy 1.26.4 환경에서, 고정한 첫 변환 K3IIIhSLI0000100NR0.dng, Adobe SDK 1.7.1 Build 2768 ZIP, Zig 0.15.2 Windows x64 전체 배포판의 zig.exe를 직접 지정합니다. 새 변환의 DNG 해시가 다르면 이 고정 입력 검사는 중단됩니다. Zig 배포판의 인접 라이브러리가 필요합니다. 검사는 실행 파일의 해시를 확인하며 배포판 전체에 대한 인증을 수행하지 않습니다.

python -B tools/check_lightroom_sdk_stage2.py --sdk dng-sdk.zip --dng K3IIIhSLI0000100NR0.dng --zig C:\path\to\zig.exe --work sdk-stage2-run
python -B -m unittest discover -s tests -p test_lightroom_sdk_stage2.py

재현 도구는 기존 경로를 거부하고 입력의 크기·SHA-256을 확인한 뒤 새 작업 디렉터리에서만 SDK를 풀고 빌드합니다. 실행하는 동안 다른 프로세스에서 이 작업 디렉터리의 파일을 바꾸지 마십시오. 내부 DNG 사본과 배열 덤프, SDK 소스, 빌드 캐시가 이 디렉터리에 남습니다. 해시·통계·호출 로그와 정수 모델의 전수 대조를 모두 통과하면 result.json을 씁니다. 빌드·재현 도구 · 입력·출력 보호 검사

이 도구로 빈 작업 디렉터리에서 276개 오브젝트를 다시 빌드했습니다. 새 실행 파일의 SHA-256은 최초 실험과 달랐고, 두 배열과 실행 로그는 최초 실험과 일치했습니다. 최초 관측 JSON의 SHA-256은 9355f35257b9717d2e9ef4ce852f61bdde6bb36762e5fd876c0b88bca9637704입니다. 최초 관측 기록 · 새 빌드와 재실행 기록
