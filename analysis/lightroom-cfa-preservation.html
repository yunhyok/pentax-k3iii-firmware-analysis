원본 PEF와 변환 DNG의 CFA 샘플 비교

PEF를 DNG로 바꾸면 센서 값 자체가 달라지는지 확인했습니다. 이 결과가 있어야 뒤의 SDK 실험에서 변환 DNG를 원본 PEF 대신 써도 되는지 판단할 수 있습니다.

이 문서에서

  1. 배경: CFA 샘플과 변환 DNG
  2. 세 배열의 모든 위치가 같았습니다
  3. 같은 배열에 기록된 WhiteLevel은 달랐습니다
  4. 한계와 남은 과제
  5. 재현 방법
  6. 근거 파일과 참고 자료

핵심 요약

  • K-3 III PEF 한 장과, 이를 Adobe DNG Converter 18.7로 처음 변환한 DNG를 비교했습니다. 디모자이크 전 CFA 샘플 26,628,096개가 모두 같았습니다.
  • 디코더 두 종류로 배열 세 개를 만들어 서로 대조했습니다. 차이는 모든 위치에서 0이었고 배열 해시도 같았습니다.
  • 샘플은 같지만 WhiteLevel 기록은 다릅니다. PEF MakerNote에는 16,378, DNG에는 16,315가 적혀 있습니다.
  • 파일 한 쌍의 디코딩 배열만 비교했습니다. Lightroom에서 PEF와 DNG가 같은 사진으로 현상되는지는 확인하지 않았습니다.

확인 파일을 직접 읽어 대조

  • PEF와 DNG의 CFA 배열 전체(여백 포함)를 같은 좌표끼리 비교
  • RGGB 네 위치별 일치 개수와 배열 SHA-256
  • 두 파일에 기록된 WhiteLevel, BlackLevel, CFA 배치

모델 연구자가 정한 조건

  • 보존한 PEF 한 장과 그 첫 변환 DNG 한 개
  • 디코더는 rawpy 0.28.0(LibRaw 0.22.2)과 tifffile 2023.4.12로 고정

미확인 이 비교로 알 수 없는 것

  • Lightroom이 PEF와 DNG를 같은 결과로 현상하는지
  • Adobe가 PEF를 열 때 WhiteLevel로 어떤 값을 쓰는지
  • 다른 사진이나 다른 Converter 버전의 결과

배경: CFA 샘플과 변환 DNG

디지털카메라 센서의 각 화소는 빛의 세기만 잽니다. 색을 얻으려고 화소마다 빨강·초록·파랑 가운데 한 색의 필터를 얹습니다. 이 필터 배열을 CFA라고 합니다. K-3 III의 CFA는 2×2 칸에 R·G·G·B가 놓인 RGGB Bayer 배열입니다. 화소마다 한 색만 기록된 정수 값이 CFA 샘플입니다. 나머지 두 색을 채우는 계산을 디모자이크라고 합니다.

PENTAX의 RAW 파일은 PEF 형식입니다. Adobe DNG Converter는 이를 공개 규격인 DNG로 바꿉니다. 이 주제의 SDK 실험은 변환 DNG를 입력으로 쓰므로, 변환 과정에서 샘플이 바뀌지 않았는지 먼저 확인해야 합니다. 아래 그림은 이 문서가 RAW 처리 흐름의 어디를 다루는지 보여 줍니다.

나머지 세 문서는 같은 DNG로 이어집니다. CFA 범위와 기본 크롭, SDK Stage 2 실행, SDK Stage 3 실행입니다. 주제 전체의 지도는 Lightroom 색 프로파일 안내에 있습니다.

세 배열의 모든 위치가 같았습니다

PEF와 DNG에서 얻은 4224×6304 배열 세 개를 같은 좌표끼리 빼 보니 차이가 전부 0이었습니다.

rawpy는 LibRaw로 RAW를 푼 뒤 원본 크기의 raw_image 배열을 내줍니다. 스크립트는 디코더가 열려 있는 동안 이 배열을 복사합니다. 비교에는 디모자이크, 화이트밸런스, 크롭, 노출 보정, 블랙 레벨 차감이 들어가지 않습니다. 두 번째 스크립트로 디코더의 버퍼 열기와 unpack을 직접 호출해 같은 결과를 다시 얻었습니다.

같은 배열에 기록된 WhiteLevel은 달랐습니다

샘플은 같아도 현상에 쓰이는 숫자 가운데 WhiteLevel은 PEF와 DNG에서 서로 다르게 적혀 있습니다.

쉽게 말하면

BlackLevel은 빛이 전혀 없을 때 센서가 내는 값입니다. WhiteLevel은 센서가 포화했다고 보는 값입니다. 현상 프로그램은 이 두 값 사이를 0~1로 늘려 씁니다. 같은 샘플이라도 WhiteLevel이 다르면 밝은 부분이 잘리는 지점이 달라집니다.

파일 태그와 LibRaw 반환값
확인 위치WhiteLevel 또는 maximum
PEF Pentax MakerNote WhiteLevel16,378
PEF를 연 LibRaw maximum16,383
DNG RAW SubIFD WhiteLevel, LibRaw maximum16,315

저장된 CFA의 최댓값은 16,382입니다. DNG의 WhiteLevel 16,315를 넘는 샘플이 8,565개 있었습니다. 이 값도 잘라 내지 않고 그대로 비교했습니다. 두 파일 모두 채널별 블랙 레벨은 64입니다.

CFA 배치 표기는 두 도구가 다르지만 가리키는 위치는 같습니다. rawpy는 RGBG 인덱스 [[0,1],[3,2]]를, DNG의 CFA 태그는 RGB 인덱스 [[0,1],[1,2]]를 씁니다. 둘 다 RGGB입니다. WhiteLevel 초과 샘플이 기본 크롭 안 어디에 남는지는 CFA 범위와 기본 크롭에서 다룹니다.

한계와 남은 과제

  • 파일 한 쌍: 보존한 PEF 한 장과 그 첫 DNG 변환만 비교했습니다. 같은 PEF를 다시 변환하면 날짜나 UUID 때문에 파일 해시가 달라집니다.
  • 배열만 비교: WhiteLevel과 중립값처럼 현상에 쓰이는 메타데이터는 배열과 따로 해석됩니다. 같은 배열이 같은 렌더를 뜻하지는 않습니다.
  • Lightroom 미실행: Lightroom에서 PEF와 DNG가 같은 결과를 내는지, Adobe가 PEF의 16,378을 정규화에 쓰는지는 확인하지 않았습니다.

재현 방법

원본 PEF와 첫 변환 DNG가 필요합니다. 두 파일과 디코더 바이너리는 이 저장소에 없습니다. 검증기는 두 파일의 크기와 SHA-256을 먼저 확인합니다. 결과 전체가 기록된 SHA-256과 같을 때만 새 JSON을 씁니다. 변환 과정은 Converter 실행 기록에 있습니다.

실행 환경은 CPython 3.12.3(Windows x86-64)과 NumPy 1.26.4입니다. 디코더는 tifffile 2023.4.12, imagecodecs 2023.1.23, rawpy 0.28.0(LibRaw 0.22.2)입니다. rawpy는 공식 wheel을 받아 SHA-256을 JSON 값과 비교한 뒤 전용 폴더에 설치합니다. 스크립트는 설치를 하지 않습니다.

python -m pip install --no-deps --target .cfa-deps ./rawpy-0.28.0-cp312-cp312-win_amd64.whl
python -B tools/check_lightroom_cfa_preservation.py --pef K3IIIhSLI0000100NR0.PEF --dng first-converted.dng --output cfa-replay.json

두 번째 명령을 실행하기 전에 환경 변수 PYTHONPATH를 .cfa-deps 폴더로 지정합니다. 설치가 끝난 전용 환경이라면 두 번째 명령만 씁니다. wheel 해시는 설치한 일부 파일의 바이트가 공식 wheel과 같다는 확인입니다. 실행 중 불러온 DLL과 의존성 전체를 인증하지는 않습니다.
