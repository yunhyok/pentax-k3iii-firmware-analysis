Joint 모드 1의 요청과 피드백 계산

K-3 III 펌웨어 2.20의 PafMotor가 요청값과 렌즈 상태를 구동 인자로 바꾸는 과정을 확인했습니다. 리셋 후속 호출, 요청 분기, 피드백 숫자 계산을 각각 원본 ARM으로 재생했습니다.

세 재생의 진입점

이벤트와 모드 선택의 앞부분, ReloadTimer·Udc 객체의 실제 연결은 각각 앞선 원본 재생에서 확인했습니다. Joint 이벤트 처리 · 서비스 객체 연결

리셋 후속 호출

0x52f0bb0c에서 PafMotor +8의 서비스를 채널 인수 0으로 호출하면 0x531784c8이 기본 장치 키 0xd1의 ReloadTimer를 사용합니다. 실제 ROM vtable의 세 슬롯을 아래와 같이 확인했습니다. 두 번째와 세 번째 행은 원본 호출 프레임을 준비한 뒤 각각 진입한 대조입니다.

슬롯과 원본 대상확인한 인자와 정지 지점
+0x7c → 0x5326d6b0r1=0xffff, r2=1. 0x5326d6c8에서 0x1e000020의 첫 32비트 읽기 직전.
+0x54 → 0x5326d740원본 descriptor로 객체 +0x30을 0으로 쓰고 제어값 0xc80과 reload 후보 0xffff, 0을 준비. 0x5326d8b4에서 같은 읽기 직전.
+0x58 → 0x5326d570r1=0x1e000020, ip=0x1e000028, r2=0. 0x5326d57c에서 첫 읽기 직전.

첫 호출 앞에서 확인한 19바이트는 01000000 000001?? ffff0000 00000000 000003입니다. +7은 A5·5A 대조에서 각각 초기값을 유지했습니다. D1이 없는 경우는 0x5317850c에서 널 포인터 역참조 직전에 멈췄습니다.

별도 0x52f0bb18에서 채널 인수 1로 호출한 대조는 두 서비스 슬롯이 비어 있어도 스택 가드 확인 뒤 돌아왔습니다. 바깥 코드가 PafMotor +0x20/+0x21/+0x32를 0으로 썼습니다. 이 인수 1은 앞선 Udc 리셋에 사용된 객체의 채널 바이트와 별개입니다.

첫 ReloadTimer 메서드의 정적 반환 경로

원본 0x5326d6c8에서 읽을 레지스터의 bit 12가 켜진 분기는 이 인자에서 0x1e00002c에 값을 씁니다. bit 12가 꺼진 분기는 쓰기를 건너뛰고 거짓 조건을 assertion 서비스로 넘깁니다. 이 서비스가 반환하는 경우에만 이어지는 원본 코드가 0을 반환합니다. 호출자는 그 반환값을 검사하지 않고 다음 메서드로 넘어갑니다. 읽기 이후의 두 하드웨어 분기는 정적으로 확인했습니다.

5개 대조와 원본 범위 · 리셋 후속 재현기

요청 분기와 구동 인자

원본 0x52ef877c가 client 1에서 Joint 모드 1을 선택했습니다. 그 뒤 0x52f08474는 별도 Joint+0x74의 32비트 요청값을 읽습니다. 0x52f0d8b0은 이 값을 unsigned로 비교해 0–9의 점프 테이블을 사용합니다. Joint+0x5c의 32비트 값은 극성 계산 후보가 되며, Joint+0x68의 halfword는 Pulse +0x2e에 기록됩니다.

요청값첫 값과 후속 분기
0, 3, 범위 밖Pulse +0x2e. 요청 3은 뒤에서 D1의 피드백을 읽습니다. 4도 같은 점프 목표를 가리키며 독립 대조는 생략했습니다.
1, 2(Pulse[+0x2e] + Pulse[+0xec]) mod 65536. 요청 1에서 Pulse +0x15가 비영이면 합산 전에 별도 함수로 진입합니다.
5Pulse +0xec. 이전 Paf+0x48이 0이면 1, 그 외에는 0을 극성 계산에 넘기고 +0x48/+0x4c에 씁니다.
6, 76은 0xfffe, 7은 Pulse +0x2e. 두 요청 모두 이전 Paf+0x48을 극성 계산에 넘깁니다.
8Pulse +0x2e를 읽고 별도 함수 0x52f0d000 진입 직전에서 정지했습니다.
9Pulse +0x2e. 214 이하에서 밴드 기록을 건너뛰고 215–407, 408–540, 541 이상에서 Paf+0x41에 각각 0, 1, 2를 씁니다.

0x52f0bd1c은 렌즈 객체 +0x134의 바이트와 입력 word d를 읽습니다. 렌즈 바이트가 0이면 d가 1일 때, 렌즈 바이트가 비영이면 d가 0일 때만 결과가 0입니다. 그 외에는 1을 Paf+0x42에 쓰고 반환합니다.

보조 호출 0x52f06b24을 건너뛴 별도 진입에서 원본 구동 서비스 인자를 확인했습니다. 채널 0 대조는 준비한 값을 그대로 전달했습니다. 채널 1의 수치 인터페이스에 별도 값을 공급하면 Paf+0x42=1일 때 부호를 반전한 뒤 하위 16비트를 넘깁니다. 같은 0x12348001의 전달값은 상태에 따라 0x8001 또는 0x7fff였습니다.

19개 요청 경로와 4개 별도 채널 인자 대조 · 요청 분기 재현기

요청 3의 피드백 계산

요청 3의 원본 D1 메서드는 0x5326d5e8에서 0x1e000024를 32비트로 읽습니다. 재생은 읽기 직전에 멈췄습니다. 다음 단계는 0x52f0c7d8에서 수치 f를 r0에 공급해 시작했습니다. 원본 호출자 0x53178344가 읽기 결과의 하위 16비트를 취하므로 입력 폭을 그에 맞췄습니다.

A = u16(Paf[+0x52] + Paf[+0x58] − s16(f))
Paf[+0x52] = A
x = u16((A의 bit 15가 켜져 있으면 0, 아니면 A) + p)

0x52f0c7dc의 SXTH가 f를 부호 확장합니다. bit 15가 켜져도 메모리의 A는 그대로 유지되고 조회에 쓰는 임시값만 0이 됩니다. 이전 누적 99와 p=1에서 f=0xffff는 조회 입력 101을, f=1은 99를 만들었습니다.

Paf+0x43=0과 Paf+0x68=0이면 x=0은 버킷 0, 그 외에는 floor((x−1)/100)을 사용합니다. ROM 0x538f25e0부터의 halfword 표는 버킷 28까지 사용합니다. 입력 2900과 2901은 모두 300을 냈지만, 실제 주소 기록은 버킷 28 읽기와 기본값 읽기를 구분했습니다. +0x43이 비영이면 조회를 건너뛰고 2*p의 하위 16비트를 채널 1로 먼저 넘깁니다.

+0x68 비영 분기의 정정

앞선 요청 분기 기록에서 “범위 밖의 몫이나 Paf+0x68이 0이 아닌 분기는 기본값으로 간다”고 적었습니다. 당시 실행한 요청 대조는 +0x68=0이었고, 원본 명령을 다시 확인해 비영 분기의 설명을 아래와 같이 정정합니다.

  • 요청 9가 214 초과 경로로 들어가거나 요청 0xff를 처리할 때, 0x52f0c8cc가 읽은 비영 +0x68은 그대로 +0x5a에 저장됩니다. +0x5c는 ROM 기본값입니다. 원본 0x52f0c918부터 이 분기를 따라가면 0x52f0c8c0과 0x52f0c8c4의 두 저장을 확인할 수 있습니다.
  • 요청 3의 조회 경로는 +0x5a = u16(선택값 + Paf[+0x56])입니다. +0x68이 비영이면 그 값이 선택값이며, +0x5c는 ROM 기본값을 받습니다. 0x52f0c99c 경로의 대조에서 +0x68=1, +0x56=4일 때 결과는 5와 300이었습니다.

로컬 호출자의 양수 조건

별도 0x52f0c9f0 진입에서는 difference = u16(Pulse[+0xa88] − f)와 remainder = s16(Pulse[+0x2e] − difference)를 확인했습니다. 이 분기는 Paf+0x1a=0, Paf+0x43이 0 또는 4, remainder>0일 때 0x52f0ca44에서 요청 3을 호출합니다. 다른 호출 지점도 있으므로 이 조건은 이 로컬 분기에만 적용합니다.

14개 누적·조회와 9개 로컬 호출 대조 · 피드백 수치 재현기

재현과 범위

Unicorn 2.1.4에서 Cortex-A7 기본 실행과 Cortex-A7·A15의 호출자 저장 레지스터·NZCV 변경 대조가 일치했습니다. RTOS와 decoded 입력도 재현기마다 바이트 단위로 같은 JSON을 만들었습니다. 실행 후 RX 원본 매핑의 전체 SHA-256을 다시 확인했습니다.

세 도구 모두 같은 RTOS 또는 decoded 파일을 입력받습니다. Python 최적화 모드를 끄고, 출력 경로에는 새 파일명을 사용합니다.

python verify_af_reset_tail.py /path/to/rtos.bin --output reset-tail.json
python verify_af_mode1_parameters.py /path/to/decoded.bin --output mode1-parameters.json
python verify_af_request3_feedback.py /path/to/rtos.bin --output request3-feedback.json

원본 생성자와 레지스트리·바인더를 사용했습니다. 일부 공장 포인터와 할당 주소, Udc warm 카운터, 렌즈·Pulse 상태와 요청·피드백 수치는 하네스가 제공했습니다. 실제 장치 피드백, 부팅 중 객체 수명, 모터의 물리적 구분과 시간·거리·각도 단위는 확인되지 않았습니다. 남은 소프트웨어 질문은 Pulse +0xa88의 비영 기준값과 PafMotor 보정 필드의 생산자입니다.
