PENTAX K-3 MARK III · FIRMWARE 2.20 · 2026-11-08

업데이트 매체의 크기 필드와 완료 통지

C 경로의 SdDriver와 R 경로의 Emmc를 실제 생성자로 구분했다. SD의 sector 수 생산자를 연결하고 R의 별도 파티션 객체를 확인했다. 완료 통지는 FwUpdateModel의 상태 갱신과 UI 작업 등록까지 추적했다.

연구 개요 · 파일명·종료 처리 · 매체 객체 · SD 크기 계산 · R 파티션 · 완료 통지 · 검증 범위

문자에서 실제 매체 객체로

앞선 조사에서 C는 provider index 0, R은 index 2에 연결됐다. 이번에는 provider에 저장하는 실제 생산자를 따라 C의 클래스가 SdDriver, R의 클래스가 Emmc임을 확인했다. 근거는 생성자·vtable·RTTI와 provider 저장 위치다. 이 이름이 현재 카메라의 카드 장착 상태나 매체 초기화 성공을 뜻하지는 않는다. 객체 생산자·RTTI 근거

공통 생성자 0x5327f4e4는 인수 r1의 하위 byte를 +0x14에 쓰고 +0x18을 0으로 초기화한다. 따라서 뒤의 비제로 값은 별도 생산자가 필요하다. SD에서는 그 기록자를 찾았지만 Emmc의 +0x18을 나중에 비제로로 만드는 경로는 이번 범위에서 확인하지 못했다. 두 Emmc 초기화 함수에서 직접 쓰기가 보이지 않았다는 사실을 전체 펌웨어의 불변성으로 확대하지 않는다.

SD의 +0x18은 CSD에서 계산한 sector 수다

SD 활성화 함수 0x53281cf8는 선택한 gate·준비 상태·존재 조건과 acquisition 결과가 허용할 때 전역 0x54583af0의 16바이트를 this+0x28에 복사한다. 0x53282554가 계산한 값을 0x53281e04에서 this+0x18에 저장하고 +0x79를 1로 만든다. 검사한 gate 실패·이미 준비됨·존재 조건 실패·세 번의 acquisition 실패에서는 기존 +0x18이 보존됐다. 실제 데이터 수신은 합성 반환값으로 대체했다. 조건부 갱신 7사례

같은 전역 버퍼의 진단 경로는 이를 CSD Register로 표시한다. 성공 로그는 계산값을 total sectors라고 부르며 0x53281e20과 0x53281e4c가 해당 인수를 연결한다. 양쪽 매체 클래스의 vslot+0x4c getter는 512를 반환한다. 이 근거와 아래 계산식이 SD의 +0x18을 512바이트 sector 수로 해석하게 한다. 현재 매체 용량을 측정한 결과는 아니다. 진단·getter·계산 근거

CSD 필드와 ARM 계산식

16바이트 입력을 b, 구조값을 s=b[0]>>6으로 둔다. 0x532824fc가 크기 필드 C를 추출하고 0x53282554가 count를 계산한다. u32는 32비트로 잘리는 결과를 뜻한다.

s=1:
C = ((b[7] & 63) << 16) | (b[8] << 8) | b[9]
count = u32((C + 1) << 10)

s=0:
C = ((b[6] & 3) << 10) | (b[7] << 2) | (b[8] >> 6)
r = b[5] & 15
m = ((b[9] & 3) << 1) | (b[10] >> 7)
count = u32((C + 1) * (LSL32(2, u32(r-1)) >> 9) * LSL32(2, m+1))

s=2 또는 3: count = 0

LSL32의 register shift는 하위 8비트를 사용하며 shift가 32 이상이면 0이다. s=1의 최대 C에서 결과가 32비트 overflow로 0이 되는 합성 사례도 확인했다. 이 입력이 실제 지원 카드에서 허용되거나 도달한다는 뜻은 아니다.

공식 SD Association 문서의 CSD v2 용량식 (C_SIZE+1)×512KByte를 512바이트로 나누면 펌웨어의 (C+1)×1024와 일치한다. 공식 PDF의 검색 색인에서 C_SIZE·READ_BL_LEN 설명과 인쇄 쪽 172를 확인했다. PDF 직접 열기·다운로드는 지원 형식과 HTTP 403 제한으로 완료하지 못해 전체 문서를 검토했다고 주장하지 않는다. SD Physical Layer Simplified Specification v6.00

기존 backend selector는 descriptor byte+0x14가 4이면 Virtual, 그 밖에는 word+0x18이 0x0403ffff보다 클 때 ExFat을 선택한다. 이번 결과로 C 경로에서 읽는 크기 필드의 생산자를 연결했다. 전체 초기화와 mount의 실행 시점·성공 여부는 별도 확인이 필요하다.

R의 record 값은 별도 EmmcPartition에서 온다

0x53297fac의 대상은 vptr 0x53cb16e8, RTTI EmmcPartition인 별도 객체다. task lookup과 dynamic cast로 얻은 Emmc 포인터를 이 객체의 +4에 저장한다. 따라서 이 생성자의 +0x14/+0x18 쓰기를 Emmc descriptor의 갱신으로 세면 안 된다. 객체 정체성과 저장 관계

R 상수의 단위와 시작 위치·길이 의미는 하위 소비 경로까지 확인하지 않았으므로 여기서는 숫자로만 기록한다. 이 record와 FwPartition의 bank record는 서로 다른 구조다.

완료 통지는 모델 상태와 UI 작업으로 이어진다

완료 함수 0x52ff3960이 r1에 메시지 ID 0x2640820b, r2에 0을 선택한다. 공통 송신 함수 0x52ff382c는 전달받은 두 값을 envelope의 첫 두 word에 저장하고 나머지 다섯 word를 0으로 초기화한다. notifier+4의 pipe를 거쳐 0x53309c10에 전달하는 것은 이 공통 함수다. 공유 소유자 포인터가 null인 검사 조건에서는 하위 transport의 반환값을 그대로 반환했다. 상위 0x52ff3960은 그 반환값을 분기 조건으로 쓰지 않고 event 경계에 0x20을 넘긴 뒤 마지막 통지 호출로 이동한다. 송신 경로·반환값 근거

수신 router는 group 0x26을 선택한 뒤 두 predicate를 거쳐 0x52a64b3c로 이동한다. getter 0x528c6730의 초기화된 경로는 0x545acf48을 반환하고 생성자의 vptr·RTTI는 이 객체를 FwUpdateModel로 식별한다. 수신부는 +8을 3으로 쓴 뒤 작업 ID 0x128을 등록한다. 송신부와 수신부는 각각 원본 ARM으로 실행했지만 둘 사이의 실제 구독·전달·스케줄링을 이번 시험에서 연결하지 않았다. 상태 3을 물리 업데이트 성공이나 인증 통과로 해석하지 않는다.

UI queue가 가득 찬 경우

queue 등록 함수는 16비트 count와 capacity를 읽어 count < capacity−1일 때 12바이트 record에 작업 ID와 두 인수를 저장한다. count를 늘리고 write index를 (index+1)&mask로 갱신한 뒤 unlock과 wake를 호출한다. 합성 8-slot queue에서 count 6은 저장됐고 count 7은 assertion에 도달했다. lock의 반환값은 이 저장 경로의 분기 조건으로 쓰이지 않았다. wrap·반환값·full queue 검사

모델의 상태 쓰기는 queue 검사보다 먼저 일어난다. 기본 시험 fixture는 false assertion에서 멈춘다. 별도로 assertion이 반환한다고 가정한 사례에서는 record를 추가하지 않고 unlock·wake로 진행했다. 실제 assertion 함수의 본체와 카메라의 실패 처리 정책은 실행하지 않았으므로 두 시험을 실제 장치의 동작으로 단정하지 않는다. 이 경로의 모델과 queue 처리에서는 decoded 출력의 해제 호출을 확인하지 못했으며 작업 0x128의 소비와 최종 회수는 다음 조사 대상이다.

재현 범위

descriptor 57사례와 완료 통지 15사례, 합계 72사례가 RTOS 직접 입력과 통합 decoded 입력에서 동일하게 통과했다. C 출력 17개와 원본 ARM 1,878 words의 주소·해시를 로컬에 보존했다. 재분석한 함수도 포함한 출력 수이며 독창적인 원본 소스 17개를 확보했다는 뜻은 아니다. 공개 자료는 분석·합성 검사·메타데이터로 구성한다.

descriptor 시험의 base constructor·task lookup·dynamic cast·media acquisition과 설정·작은 memcpy는 대체 함수다. SD 활성화는 +0x24=0, +0x7a=0, +0x10=0x1b2와 기본 callback 조건의 선택된 분기를 실행했다. mutex 경로·다른 mode·재정의된 callback은 실행하지 않았다. 완료 통지는 초기화된 singleton guard와 작성한 queue를 사용하며 실제 transport·OS 이벤트·업데이트 executor는 대체했다.

자동 복원 C에는 tail call 누락과 구조체·index 추정 오류가 남을 수 있다. C 원문은 수정하지 않고 원본 ARM과 재현 결과를 결론의 기준으로 삼았다. 물리 매체·카메라·펌웨어 빌드·플래시는 수행하지 않았다.
