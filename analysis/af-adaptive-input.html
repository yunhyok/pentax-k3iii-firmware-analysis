AF 적응형 문턱의 입력

K-3 III 2.20의 적응형 함수는 ElapsedTimer가 두 카운터 표본의 차이를 27로 나눈 몫을 2000·4000·8000과 비교해 배율을 고릅니다. 원본 명령에서 저장 위치와 환산식을 확인했습니다. 카운터의 실제 주파수와 물리 단위는 미확인입니다.

이전 표본과 새 표본

  1. 이전 표본 — 0x531062d4의 반환을 PafMotor+0x80에 저장합니다.
  2. 새 표본 — 0x53106370이 ElapsedTimer+4에 연결된 객체의 가상 함수 슬롯 +0x6c를 호출합니다.
  3. 차이와 환산 — 0x53106304가 두 32비트 표본과 경계값을 받아 mode 0에서 27로 나눈 몫을 돌려줍니다.
  4. 배율 선택 — 0x52f0bdb4 뒤에서 Motor 상태에 따른 문턱과 unsigned로 비교합니다.

0x53102ce8이 반환하는 UtilityFactory의 +0x0c에는 RTTI 이름이 ElapsedTimer인 객체가 들어갑니다. 생성자 0x531062b8은 Timer +4와 +8을 0으로 씁니다. 할당 직후 호출하는 vslot +8의 0x5310623c는 1을 반환합니다. 별도 vslot +0x0c의 0x5310627c는 키 0xd9로 찾은 객체를 Timer +4에 두고, 그 객체의 vslot +0x30 호출 뒤 Timer +8에 0xffffffff를 씁니다. 실제 적응형 호출 전에 이 초기화가 언제 실행됐는지와 당시 필드 값은 확인하지 못했습니다.

Motor +0x80은 0x52f0b8fc, 0x52f0b974, 0x52f0ba10에서 이 카운터의 표본을 받습니다. 0x52f0bf48/bf54는 두 번 읽은 값을 +0x84/+0x88에 각각 저장합니다. +0x84는 별도 mode 1 호출의 이전 표본입니다. 상태 선택 경로의 D1은 Driver +0x38 결합을 전제로 0x1e000024에서 읽은 하위 16비트를 사용합니다. D1과 비교해 카운터를 다시 샘플링하는 곳도 있지만 두 반환 경로는 구분됩니다. D1 피드백과 상태 재읽기

차이 계산과 문턱

0x5310630c/10의 두 RSB는 모두 이전값에서 현재값을 뺍니다. 이전값이 현재값 이하이면 Timer +8을 더합니다. 최종 차이 D는 unsigned 32비트입니다. 같은 값끼리 빼도 분기 조건에 따라 경계값이 더해집니다.

D = u32(old − now + (bound if old ≤ now else 0))
mode 0: D // 27     mode 1: D // 108
mode 2: D // 216    mode 3: D // 27000

bound가 0xffffffff이면 old=1, now=0xffffffff에서 D는 1입니다. 같은 bound에서 old=now이면 D는 0xffffffff이고 mode 0 몫은 159,072,862입니다. 두 값은 원본 조건에서 계산한 산술 대조입니다.

0x53106328..0x5310636f의 UMULL과 시프트를 묶으면 처음 세 모드의 몫은 floor(D×(2³²+A)/(2³²×k))입니다. A=0x2f684bdb, k는 32·128·256입니다. 27×(2³²+A)−32×2³²=25여서 u32 입력 전체에서 오차는 각 나눗수의 역수보다 작습니다. mode 3의 두 번째 곱셈 상수 B=0x10624dd3는 1000×B−2³⁸=56을 만족합니다. mode 0 몫의 범위에서 내림 결과는 정확한 1000 나눗셈과 같으므로 원래 D의 27000 나눗셈에 해당합니다.

다시 읽은 Motor 상태2배 문턱4배 문턱차이 D의 최초 초과점
22000400054,027 · 108,027
340008000108,027 · 216,027

먼저 4배 문턱을 검사하고, 이어서 2배 문턱을 검사합니다. 둘 다 엄격한 초과이고, 배율을 적용한 값은 하위 16비트로 자릅니다. 래퍼가 리셋 전에 보관한 상태와 적응형 함수에서 다시 읽은 값의 동일성은 확인되지 않았습니다. PWM 정수 변환과 이전 정지점

남은 카운터 경계

키 0xd9의 객체를 읽는 실제 슬롯은 0x54784f6c입니다. 같은 키를 쓰는 공급자 등록 0x531fc9f0의 슬롯은 0x54785cf8입니다. 두 주소가 다르므로 공급자 등록만으로 결합 객체나 실제 getter를 지정할 수 없습니다. 객체 슬롯의 생산자와 +0x6c 구현, 카운터 클럭을 확인해야 물리 시간 단위를 판정할 수 있습니다.

후속 정적 조사에서는 별도 객체 등록에 성공한 조건에서 D9 ReloadTimer의 읽기 주소를 확인했습니다. IRQ 키와 객체 키, 등록 실패 가능성은 구분합니다. 후속 근거와 남은 시간 단위 검증

원본 정적 대조

추출한 원본 RTOS를 한 번 읽어 길이와 SHA-256을 확인합니다. Capstone 런타임 5.0.7로 30개 구간의 해시, 31개 명령 위치, 9개 워드와 이름을 대조하고 호스트 산술 조건 21개를 확인합니다. 원본 ARM, 서비스 및 MMIO는 실행하지 않았습니다. 아래 명령은 새 출력 경로를 사용합니다. 출력은 실행 중 다른 프로세스가 변경하지 않는 디렉터리에 둡니다.

python -B verify_af_adaptive_input.py path/to/rtos.bin --output new-adaptive-checks.json --compare analysis/af-adaptive-input-checks.json
